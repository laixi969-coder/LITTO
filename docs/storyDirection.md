# 剧情演绎与节奏改进

## 资料判断

参考用户提供的「【108】AI短剧创作SKILL/script-writing-studio」中的 SKILL.md、01b-rhythm-matrix.md、03-dialogue-expert.md 与 04-core-workflow.md。资料署名为 Revo AI 导演团队；本次吸收创作思路，以 LITTO 现有结构重新表述，没有复制安装整套技能或采用其中的命令、推广与强制流程。

有帮助的方法：停顿必须承担信息或关系变化；对白是人物达成目的的行动；先设计动作因果与空间调度，再安排摄影；生成片段的长度不等于成片剪辑长度。没有采用固定开场秒数、固定反转频率、镜数配额和“不追求人物深度”等模板，也不把复杂切镜或大量动作当作质量证明。

## 实现

- 导演接口默认启用模型润色，显式 useLlm:false 仍可取得规则草稿。不能从未完成的规则草稿直接自动生成正式素材；无模型或返回无效设计时明确反馈。
- 模型可以按 sourceIndexes 拆分单个源节拍或合并同场相邻节拍。校验完整覆盖、原顺序、场次边界及逐句原文和说话人；拆镜不把完整台词分裂为碎句。镜尾状态复用已有资产状态校验，不能提前沿用源节拍最终状态。
- 调度、表演、局部时长和 creativeBrief 一并写入真实镜头。对白计划进入现有视频编译器的声音与口型指令；没有匹配到真实角色的对白或旁白不猜说话人，保留草稿并要求先明确声音来源。
- 人物表演/武打镜头生成前检查具体表演、节拍、人物路径、镜头目的与剪辑依据；这些检查仅验证规格是否完整，不能判断演技好坏。
- 成片验收增加 narrative、performance、dialogueCoverage，并将 editing 变为通用必检。缺项默认为未验证，旧的通过记录缺少新检查时显示未验收，不删除旧记录。无人、无对白及非剧情作品按实际目标说明适用范围，不强加剧情或台词。
- 主提示词、故事/制作工作流、分镜团队与 Seedance 规则明确区分剧情事实和导演执行选择。对已有意图可设计未锁定的表演与走位；新增事件或改对白仍需遵守已有改编授权。

## 使用与边界

构建更新内置技能；已有安装的可编辑技能目录不会自动覆盖，需通过技能管理更新相应内容，保留自定义部分。主系统提示词与服务端校验随程序更新生效。既有素材不会被自动重生成或覆盖。

字段、类型检查及构建成功只说明流程可执行。真实节奏、表演、对白与口型仍须完整看听成片，记录时间点和观察；不以抽帧或像素变化证明演绎成功。

## 表演时序传递修复

2026-11-07 核对了两条现有入口：

1. 故事工作台采用版本 → `readSceneList` 即时关联逐场完整正文、目标、阻碍、变化、知情与因果 → 助手设计镜头 → `productionSpec(shot/updateShot)` 从采用版本写入场次来源快照 → `createShot/updateShot` 保存行动、表演、时间线和接戏关系。
2. 导演接口接收完整剧本 → `storyboardDirector` 建立源节拍 → `refineWithLlm` 接收完整剧本与草稿，核对源节拍顺序和逐句对白 → `createShotsFromDrafts` 保存分镜与来源映射。

两条入口均进入 `compileShot`，再由工作区媒体编译适配实际参考、模型格式与字符上限，生成任务保存并发送编译后的请求。场次来源用于追溯和审查，不把整场剧情直接复制进每个视频请求；本镜实际执行仍由行动、表演、时间线与起止状态承载。

确认并修复的丢失：

- 编译器原先只要存在普通或 MV 时间线就省略 `performance.timing`，没有证明触发与反应已经迁入时间线。现在保留该字段的已写原文；`camera.design.timing` 的同类省略同时移除。
- Seedance 2.5 的 MV 格式原先将表演、调度、相机时序及接续状态合并为 `Visual direction`，下游超长压缩无法按已有执行字段名单保护它们。现在保留独立字段，复用既有压缩保护；不新增压缩器或创作规则库。
- 现有自动成片叙事审查改为交叉核对时序字段与时间线，避免有时间线时忽略触发与反应。编译器不猜测哪份语义正确，不自行改写冲突；仍须在现有审查与预览中修正规格。

本轮内存数据库手动验证了无时间线、普通时间线、MV 时间线在通用、Q4 与 Seedance 2.5 三种格式下的九组编译：表演触发、相机时序、接戏要求保留，首帧不注入后续动态；另验证了规则分镜落库后的源节拍与表演时序。没有新增测试文件、调用付费生成或覆盖用户素材。没有实际调用语言模型压缩或验证成片质量；本轮压缩保护验证限于字段结构与保护名单的代码核对。

### 实际文本模型压缩复核

随后使用已配置的 AtlasCloud `openai/gpt-6-luna` 调用生产压缩函数，输入为内存数据库中的构造镜头经真实编译器输出的规格，并增加长视觉背景触发压缩。使用隔离配置和内存数据库，不改真实项目、全局模型选择或用户素材。

发现压缩函数直接使用配置中的 131072 token 最大输出额度，上游返回 HTTP 400 `invalid request params`。仅将隔离配置中的输出额度改为 4096 后同一模型成功。修复为压缩请求按字符预算分配输出额度、最多 4096 token，不修改全局模型能力；截断仍按现有失败检查拒绝，不接受不完整结果。直接导出现有压缩函数供本地调用，没有新增封装或测试文件。

修复后的三次真实压缩结果如下；输出长度含实际负面提示词附加文本：

| 编译格式 | 压缩前正文字符 | 压缩后含负向字符 | 本次上限 |
| --- | ---: | ---: | ---: |
| 通用 | 13187 | 2545 | 7000 |
| Q4 | 12776 | 2436 | 5000 |
| Seedance 2.5 MV | 13531 | 2895 | 7000 |

逐字检查表演、行动时间线、相机触发与停止、接戏要求及相应起止状态字段，全部保留。语义复核模型生成的视觉背景，未见新增冲突动作或反应顺序变化。样例明确要求听完呼唤才停步、停步后回头、镜尾等待，以及沿用前镜右手持行李和左脚已落地、不重置坐姿、不重复拿行李；这些原句均留在最终请求中。Q4 的相机时序位于既有 constraints，起止状态位于 staging，同样保留。

额外确认同进程相同请求复用压缩缓存，执行字段自身超过上限时在调用模型前拒绝。完整输入输出和逐字段结果保存在本机 `data/promptCompressionReview/report.json`，该目录不提交。Seedance 本次是显式设置上限的压力验证，不代表所有 Seedance 供应商默认启用自动压缩。没有生成任何视频；结论限于本次构造镜头的文本传递与压缩，不代表真实视频的表演质量。Cloud、server 类型检查及 server 构建通过。

### 真实项目片段复核

原片 49.25 秒处，剧本要求男方起身跟随，S06 分镜却要求继续坐着；57.29 秒进入 S06b 时男方已站在女方身后，缺少起身和靠近的动作。门口接触目标及跨门槛过程也不够清楚，现有素材不能完整补足。原片 67.33–87.42 秒将独自下楼放在楼道对峙之前，与采用稿相反；交换这两个各 241 帧的既有镜头，导出 75.33 秒局部修订片，保留 1808 帧总长及原音乐时段。原片、采用稿、分镜与候选状态均未覆盖，没有生成付费视频。
