# 广告、MV、剧情的制作质量链路

目标是可信的真人材质和表演、稳定的资产与空间、可读的受力过程、连贯的剪辑和声音。分辨率只是交付规格，不能证明这些目标达成。

## 三类作品共用的实现

- 正式出图和视频共用跨镜关系检查：`continuity:{mode,reason,visual,audio}` 区分 opening、continuous、coverage、parallel、ellipsis、montage；草稿可暂缺，生成前由助手补齐。连续动作和同场换机位明确指定 `continuityFromShotId`；平行事件线仅继承指定来源，时间跳跃/蒙太奇从本镜起态开始。旧记录保留原继承语义，不迁移或重生成已有媒体。
- continuous 生成使用前镜已采用且检查有效的视频实际剪出帧；接戏帧记录剪入剪出范围，修改前镜剪点会使其检查失效。coverage 的静帧可独立设计机位，正式视频须等实际承接状态。自动导演保存输出索引与真实镜头 ID 的映射，连续动作不再批量独立出图。
- 自动制片的叙事审阅包含承接关系及其版本；生成检查新增跨镜入口与落点观察。readEdit 和最终 cutReview 计划带回切镜动机、视觉及声音连接，必须连播审看；这些结构约束不保证模型实际演出正确，也不将自动拼接或草稿交付当作定稿。

- 正式镜头使用已采用的资产。角色、服装、场景、产品、车辆的参考图须真正送入对应模型输入；容量或参考能力不足会阻断，不降级为文字后继续宣称一致。视频可继承已经检查的本镜主帧。
- 沿用世界、影调、资产不变量、镜头摄影和五类真实感字段。真人妆造、皮肤纹理、材质高光、空间光源及表演须写成可观察条件；不把写实标准强加给明确选择的动画媒介。
- `shot.interactions` 可描述关键接触事件：`assetIds/start/contactAt/end/approach/contact/force/support/release/endState`。参与者须属于本镜出镜资产，事件在生成时长内。动作改变时同次复核该字段；编译进入视频指令，审片追加接触窗口采样。复杂动作仍须完整播放，有限抽帧不能证明每帧正确。
- 剧情/广告的 `camera.design.timeline` 与 MV 的 `musicVideo.timeline` 共用动作与接触检查，不再漏读剧情时间线。动作戏的 `combat.beats.timelineIndex` 绑定唯一执行节拍；缺少有效绑定、镜头模式、起止状态、空间保持项、机位或世界光源时，编译列出缺项，正式生成由现有准备门禁拦下。旧草稿保留，由助手补齐，不让用户填写技术表单。
- `qualityReviewPlan.motionPlan.checkpoints` 按时间线、接触和攻防生成当前检查项。工具、聊天代理审阅、面板与后端统一接收 `motionReview:[{id,verdict:pass|revise,note}]`；完整播放后记录实际时间点与证据，缺项、重复/无关项、动作未通过或素材实际时长不足不能正式采用。仅抽帧可记录问题和工作版，不能冒充完整动态通过。旧的概括检查不能替代新增动作检查；素材不重生成，补看并记录即可。
- 每个视频候选都须完整播放，记录 surface、imaging、world、motion、cinematic 检查。旧的仅抽帧检查不能用于正式交付。草稿可继续用于讨论。
- `agentReview` 在已有自主审阅授权下记录实际观察。完整检查通过并提供 `observedStateDelta` 后调用既有正式采用流程，实际末态传递给后镜；未提供时只进入工作版。无状态变化明确传 `{}`，不能照抄计划当观察。镜头规格、歌曲或继承状态改变会使相关检查过期。
- 显式 `continuityFromShotId` 的生成依赖在编译层核验：前镜须有已采用视频、实际末态及当前有效检查；缺失时仍可预览方案，不能正式生成后镜。意象蒙太奇及无此依赖的独立镜头仍可并行，不把所有镜头串行化。
- 所有类型的定稿均要求当前序列的正式镜头视频和有效检查，不允许用自由素材或未解决的严重连续性问题绕过。明确的静态落版可用本镜已检查的主帧作为 media 图片片段；须关联镜头，且不能承载对白、演唱或视频技法，不能将其冒充运动画面。

## 类型差异

| 类型 | 导演设计 | 成片核验 |
| --- | --- | --- |
| 商业广告 | 复用 adDirection、真实参考分析、产品权威参考和先行样镜定标；产品参与因果，精确品牌文字使用获批后期素材 | 保留 inspectAdFilm 的实际抽帧审片、产品识别、情绪表达与品牌记忆检查 |
| MV | musicVideo 将乐句、段落、动作峰值、演唱和视觉母题对应到实际原曲；不机械按拍切镜 | 增加 musicAlignment、musicProgression；核对原曲同步与主副歌视觉发展 |
| 剧情/短剧/中剧 | 复用故事采用版本、分集序列、角色知情与状态账本、逐句对白规划和跨集接续 | 核对事件因果、表演、完整对白、说话人、画内口型与跨镜连续性 |

## 原曲实际进入剪辑

先 `importAudio`，将真实媒体 ID 写入 `musicVideo.sourceMediaId`，并填写 `sourceStart`。没有媒体或实测时长、越过歌曲末尾会阻止正式生成或交付。草稿可以先规划而不绑定歌曲。

自动排轨把每段视频的生成歌曲静音，在 A2 音乐轨按 `sourceStart + 画面入点` 排入同一原曲。连续镜头沿用连续源时间，不在切点回到歌曲开头；也支持手工铺一条连续主音轨。已有手工剪辑保留，定稿会检查错位、漏段、重叠和变速。修改老时间线后使用现有重新排轨/剪辑入口，不能把旧音乐当作已经自动跟随。

源音频绑定不等于生成模型收到该音频。需要模型音频参考时仍使用真实 AUDIO 绑定并核对能力；画内演唱必须实际同步看听，`audioReview.referenceMediaId` 对应当前原曲。原曲排轨本身不能修复不匹配的嘴形。

## 最终文件的证据与局部返修

定稿导出后 `inspectFinal` 返回实际文件检测、`plan.fields` 和 `plan.cuts`。三类作品共用构图、色调、材质、动作、光线、连续性、声音、叙事、表演、对白和剪辑检查；按类型追加产品或音乐项目。

每个真实剪点记录 `cutReview:{id,seconds,verdict,note}`，观察动作阶段、视线/屏幕方向、空间与光色、声音交接。没看过就保持 unverified；失败写具体时间码、缺陷和需保留的部分，再用既有 trim/set_cut/soundBridge/set_gain 或局部重生成修复，避免重做整片。改变剪辑、素材或规格后原验收失效。

制作面板可填写实际验收；代理在用户已授权自主审阅且真实完整看听之后使用 `agentReviewFinal` 保存相同字段，记录授权和操作人。用户“满意”单独保存为喜好反馈，不自动勾选技术通过。检查表和有限抽帧不构成自动视觉质量保证。

## 参考来源与边界

用户指定的五条效果参考已转为按片型执行的要求。网页助手按当前版块自动加载 `cinema/references/referenceQuality.md`：动作剧情强调空间、完整行动链与多人反应；双人剧情强调位置、接触、视线和情绪；生活方式广告强调产品参与的行动链；感官广告强调材质、景深与意象衔接；MV 按实际原曲组织叙事与表演。既定高难动作必须保留，不能靠删成静站通过验收。

这些约束落实了设计、编译和验收责任，不构成已达到参考片画质的证明；当前没有新付费成片验证。

参考 [seedance-tvc-director](https://github.com/nutllwhy/seedance-tvc-director) 的[产品动作受力链](https://github.com/nutllwhy/seedance-tvc-director/blob/main/seedance-tvc-director/references/product-actions.md)、[镜头与声音交接](https://github.com/nutllwhy/seedance-tvc-director/blob/main/seedance-tvc-director/references/shot-handoffs-and-sound-bridges.md)、[实片质检](https://github.com/nutllwhy/seedance-tvc-director/blob/main/seedance-tvc-director/references/delivery-and-qc.md)方法，按 LITTO 现有领域模型实现，没有复制第三方技能或安装其工作流。

未采用固定镜数、强制快切或永久指定某个 Seedance 版本/时长的做法。实际模型能力取自已配置供应商。代码检查只能验证约束和流程，最终真人质感仍须用选定模型、真实参考和实际作品看听验证；本改动没有调用付费模型生成样片。

资料之间对时间精度、单镜动作量和强度配额有冲突：应先保证因果可见，再结合所选模型能力、用户节奏和代表性样镜结果调整，而不是将任一来源的数字当作通用上限。明确飞行的玄幻作品允许风格化重力；写实支撑要求适用于已有支撑和接触，不得取消飞行。出错时记录实际时间点，区分编排、画面覆盖和参考输入；切掉错误段只有在保留动作因果并核验相邻接点后才可能成立。

复核还发现两个容易直接造成错误的矛盾：短片规划表和多镜模板对跨画框出入边缘的示例并不一致，故先根据世界运动方向和两镜机位推导，不能固定填写同侧或异侧；Higgsfield 的不同资料一处将视频参考描述为可强锁，另一处又强调动作末帧不可精确继承，因此将其视为创作意图与待验证能力，不承诺 1:1 执行。第三方给出的固定帧率、参考数、预设与音画能力也不能替代当前供应商的实际模型声明及请求回读。

普通制作在会话开始时按已选 Seedance 2 系列模型加载 `seedanceDirector.md`；本轮中途切换则提示先读取。动作专项路由也识别武侠、仙侠、刀剑和剑斗。技能被加载、规格被编译都不证明生成器正确执行；用户不满意的旧视频、独立首帧和抽帧报告不能代替真实动态接戏验收。普通聊天流程仍缺少与自动成片同等的完整视频观察能力，需另行接入和实测。

### 逐份研究的关键判断

1. **ai-shortfilm-prompts：项目一致性方法有用，独立生成建议不能照搬到连续武打。** 主技能与 project-planner 把主体注册、全片影调、本镜摄影和行动拆开，适合映射到现有资产与 World/Look。其 multi-shot-narrative 与武器充能案例却强调独立分段、后期拼接；这只能保证每段提示完整，不能保证同一交锋的速度和相位连续。示例中的蓄力、慢动作终结、喘息和禁止飞天属于该案例，不能覆盖本次“全程打、允许飞”的要求。主技能强制手持、器材名与瑕疵数量，是作者的风格处方，不是视频质量的必要条件。
2. **awesome-seedance combat-choreography：最有价值的是关系约束，而非更多招式名。** 双方的攻击与回应要形成同一事件，握持点和器械连接保持一致，摄影机环绕不得被演成角色自转。材料中的案例数量与热度是检索信息，没有给出相同输入、多模型、重复生成的对照结果；不能据此宣称某模型武打成功率更高。其关于过滤与效果的因果解释同样是模板作者判断，本项目不把它当供应商保证。
3. **Seedance2.0-Prompt-Skill：参考用途和分段描述可用，网页能力不可直接套 API。** 已阅读 seedance2.md 的输入、写作框架、摄影、18 类场景、时长、输出与迭代章节。参考角色、动作、镜头和音频必须绑定真实素材；提示里写 @视频 或“延长”不会凭空开启接口能力。文中“强化词必加”、默认慢动作、固定远近循环，不能替代动作与机位设计；技术参数示例同时包含两种画幅，也不能原样转为单个生成请求。真实画幅、时长、参考数量与音频能力以当前供应商所选模式为准。
4. **fight-prompt-director：完整覆盖主技能和三个参考文件，核心是主动权与状态链。** 七种结构区分双人、多人、远程、人兽、演武等不同问题，不能把双人对练模板推广成所有动作戏。摄影视角围绕可见证据选择，诊断按动作、镜头、参考分开；同一部片中角色的优势距离和反制方式有区别，下一拍由前一拍造成的局面触发。其速度档位、三方案和微动作配额不直接采用；本项目已有相应动作设计技能，本次补的是遗漏与执行入口，不重复安装同一份。
5. **higgsfield-ai-prompt-skill：摄影、动作、首帧及失败诊断提供了更具体的失效解释，但“硬规则”也需要筛选。** camera 区分固定位置摇镜与摄影机平移；motion 区分动作参考与命名预设；FAILURE-MODES 明确描述独立生成的武打为何每段重新起势，还列出动作倒放填时长、手动而物体不动、镜头运动过载等症状。ENGINE-RULES 又要求每次切镜同时改变景别与摄影方式、出画后不可再入画，这些不作为本项目普遍约束。PRODUCTION-PATTERNS 中的视频强锁宣称与 camera 的能力边界不一致，因此只把参考视作有待实测的输入约束。Motion Control 专用任务不能等同于普通 Kling 文生或图生视频。

研究覆盖上述主技能和直接关联的动作、摄影、项目规划、输入与失败诊断文档；不包含逐一复现上游全部视频案例、阅读无关发布工具源码或验证所有供应商的当前能力。上游 README、模板、作者案例均是方法来源，不是本项目的效果证据；没有将整个第三方仓库复制或安装到运行环境。

### 连续性不是一个字段，而是六种关系

| 关系 | 缺失时的可见症状 | 本项目承载处与处理 |
| --- | --- | --- |
| 故事因果 | 下一镜无缘无故换地点、换目标 | 已采用剧本、continuity.mode/reason；先确定连续、换视点、平行还是省略 |
| 世界空间 | 换机位后人物瞬移、门窗和方向翻转 | blocking、camera.design、世界光源；世界方位与画面左右分开 |
| 动作相位 | 格挡后又起手，落地后下一镜仍在起跳 | combat.beats 与唯一 timeline；接续前镜实际剪出相位 |
| 动量与节奏 | 姿势接上了却停一拍，飞行忽快忽慢 | subjectPath、realism.motion、实际末态观察；尾帧只给位置，不能单独表达速度 |
| 接触与状态 | 剑穿过身体、武器换手、受击没有后果 | interactions、持有者与握持、observedStateDelta；不能以火花或震屏作为接触证据 |
| 摄影与听觉 | 人没动但镜头乱转，切点声音重启 | cameraPath、cutReview、声音交接；相机运动不代替人物动作 |

这些关系不是全都追加进 prompt 的六段说明。剧本与全片账本留在制作记录，模型请求只取本段可执行的起态、行动、摄影、参考与声音；同一事件只用一条执行时间线。新增更多相互重复的说明会增加冲突，不能解决上下文缺失。

### 应从哪里修：先编排，再分镜起态，再视频执行

分镜图不是故事连续性的唯一源头。若剧本只写“大战三百回合”，漂亮分镜仍然没有行动因果；若编排清楚而首帧已手剑融合、两人距离不可能接触，继续加负面词也不能可靠救回。顺序应是：明确争夺目标和主动权变化 → 规划完整交锋与换机位理由 → 检查起帧是否能执行下一动作 → 发送真实参考和唯一时间线 → 查看实际片段与接点。

必须区分三种输入：角色设定图确定外貌；分镜起帧确定本镜可见位置与姿态；前镜实际剪出帧确定已发生状态。计划图不是实际尾帧，外貌参考不是硬首帧。换机位时按同一实际状态设计新视点，不能直接沿用旧画幅又要求摄影机瞬间到另一侧。同机位尾帧接续也只能减少起态差异，无法证明速度连续。

原创纸面例：甲的进攻迫使乙向石阶方向退，乙利用偏转后的兵器空当改变高低差，甲的追击从这个位移继续。先在可读机位看见交锋，再因高低差出现而换到能展示追击路径的机位；下一镜从实际偏转与退向承接，不重新安排双方站定亮相。该例仅解释设计方法，没有生成视频，不作为效果证明，也不会替换用户已有剧情。

### 可复核的执行与失败归因

调用链为 `agent/runtime/resources.ts → loadProductionSkillContext → 制作规格 → domain/compiler.ts → 实际供应商请求 → 质量审阅与采用 → 最终剪点审阅`。技能正文会进入系统上下文，但模型是否遵守仍需查看规格与编译结果；列表里出现技能名不能证明正文被读取。

本次额外修复入口提前退出：原先仅凭当前一句话决定是否读取制作上下文，“再快一点”可能在读取已保存武打简报之前被过滤。现在先读取简报和待制作镜头，再判断专项；空白项目的一般问候不因此加载全部制作技能。禁用技能自动调用、关闭读取能力及工作区覆盖规则继续保留。

归因必须分层：规格本身断裂，修编排；规格正确但首帧违背起态，修起帧；参考绑定未发送，修请求；请求正确而身体与接触失败，才进入模型执行能力比较。相同提示失败一次不能证明模型能力上限；修改三类变量后成功一次，也不能证明是哪项修复有效。若供应商没有可复用随机种子，比较须明确存在随机差异，不称为严格控制实验。

实际复测应覆盖连续交锋、保持空间的换机位、既定飞行规则，并连续播放真实剪点。逐项记录输入、实际发送的模型模式/参考、观察时间码、缺陷、仅修改的变量与新输出结果。表单、类型检查、抽帧和提示文本合规只能证明流程的一部分。尚未完成实片动态核验时，结论必须停留在“规则与加载修复已验证”，不能写“武打效果已解决”。
