## 备份和恢复

独立 Bun 服务启动后每 24 小时执行一次备份，默认目录为数据目录同级的 `dataBackups`，可以通过 `MILIMILI_BACKUP_DIR` 指向独立磁盘。Compose 为该目录单独挂载持久卷。最多保留最近三份；只有新备份验证成功后才清理旧备份。失败写入备份目录的 `status.json` 并记录服务日志，不删除上一份成功备份。

数据库及文件在复制期间发生变化会放弃本次备份；频繁写入时应选空闲时段运行下列命令。空间不足以保存完整副本并保留 2 GiB 余量时拒绝执行，避免占满应用磁盘。

```sh
bun apps/server/scripts/dataBackup.ts create /绝对路径/data /绝对路径/dataBackups
bun apps/server/scripts/dataBackup.ts verify /绝对路径/dataBackups/backup...
bun apps/server/scripts/dataBackup.ts restore /绝对路径/dataBackups/backup... /不存在的新目录/restoredData
```

自定义数据库位置时，`create` 的第四个参数为其相对数据目录的路径。数据库必须位于数据目录内，否则拒绝备份，不能悄悄漏掉外置数据库。数据目录内的密钥、账号库、云媒体、租户项目及配置会一同复制；日志不复制。通过环境变量提供的密钥和其他外部配置仍应单独安全保管，否则无法解密恢复后的凭据。

正式恢复时先停止服务，验证新目录，修改 `TOONFLOW_DATA_DIR` 及必要的 `MILIMILI_DATA_DIR` / `MILIMILI_DB` 指向恢复目录后再启动。原目录保留，便于回退；不能让两个实例同时写同一目录。恢复旧备份后须重新执行备份之后已确认的注销请求。

本机副本不能代替异地灾备。当前磁盘空间不足以长期容纳三份现有完整数据，应将 `MILIMILI_BACKUP_DIR` 配置到容量充足的独立磁盘或由运维同步已验证副本到备份存储。此次恢复演练使用隔离样本，不声称已完成真实全量灾难恢复。

## 保留与待核对边界

- 注销保留匿名化账号标识、不可修改的积分账本和去掉 detail 的审计记录，用于账目追溯；不是“所有历史、备份和供应商副本即时删除”的承诺。备份按上述保留规则淘汰，外部供应商及法规保留期限需另行制定。
- 已提交但无法取得供应商回执的任务需要人工核对，不能通过退款或清掉任务号来绕开重复扣费保护。
- 本轮零依赖告警仅代表扫描时所用漏洞数据库结果，不等于所有依赖或产品不存在未知漏洞。
- 147 项原始清单中“不适用”“无法确认”及产品规划项不属于本轮十项修复范围；SSO 实际接入、外部监控、异地副本、合规认证与参考级成片能力均未因此被验证。
