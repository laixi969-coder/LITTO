## 验证范围

使用隔离数据库、临时目录、模拟供应商与本机临时 HTTP 服务验证支付、并发/恢复、上传、CSRF、注销及备份恢复。没有调用真实付费模型、真实支付或删除真实账号。没有新增测试文件。真实数据通过修复前后的只读摘要比对。

Stripe 付款判定依据：[Checkout Session 字段](https://docs.stripe.com/api/checkout/sessions/object)、[支付履约流程](https://docs.stripe.com/checkout/fulfillment)。

## 备份和恢复

独立 Bun 服务启动后每 24 小时执行一次备份，默认目录为数据目录同级的 `dataBackups`，可以通过 `MILIMILI_BACKUP_DIR` 指向独立磁盘。Compose 为该目录单独挂载持久卷。最多保留最近三份；只有新备份验证成功后才清理旧备份。失败写入备份目录的 `status.json` 并记录服务日志，不删除上一份成功备份。

数据库及文件在复制期间发生变化会放弃本次备份；频繁写入时应选空闲时段运行下列命令。空间不足以保存完整副本并保留 2 GiB 余量时拒绝执行，避免占满应用磁盘。

```sh
bun apps/server/scripts/dataBackup.ts create /绝对路径/data /绝对路径/dataBackups
bun apps/server/scripts/dataBackup.ts verify /绝对路径/dataBackups/backup...
bun apps/server/scripts/dataBackup.ts restore /绝对路径/dataBackups/backup... /不存在的新目录/restoredData
```

自定义数据库位置时，`create` 的第四个参数为其相对数据目录的路径。数据库必须位于数据目录内，否则拒绝备份，不能悄悄漏掉外置数据库。数据目录内的密钥、账号库、云媒体、租户项目及配置会一同复制；日志不复制。通过环境变量提供的密钥和其他外部配置仍应单独安全保管，否则无法解密恢复后的凭据。

正式恢复时先停止服务，验证新目录，修改 `TOONFLOW_DATA_DIR` 及必要的 `MILIMILI_DATA_DIR` / `MILIMILI_DB` 指向恢复目录后再启动。原目录保留，便于回退；不能让两个实例同时写同一目录。恢复旧备份后须重新执行备份之后已确认的注销请求。

本机副本不能代替异地灾备。当前磁盘空间不足以长期容纳三份现有完整数据，应将 `MILIMILI_BACKUP_DIR` 配置到容量充足的独立磁盘或由运维同步已验证副本到备份存储。此次恢复演练使用隔离样本，不声称已完成真实全量灾难恢复。

## 保留与待核对边界

- 注销保留匿名化账号标识、不可修改的积分账本和去掉 detail 的审计记录，用于账目追溯；不是“所有历史、备份和供应商副本即时删除”的承诺。备份按上述保留规则淘汰，外部供应商及法规保留期限需另行制定。
- 已提交但无法取得供应商回执的任务需要人工核对，不能通过退款或清掉任务号来绕开重复扣费保护。
- 本轮零依赖告警仅代表扫描时所用漏洞数据库结果，不等于所有依赖或产品不存在未知漏洞。
- 147 项原始清单中“不适用”“无法确认”及产品规划项不属于本轮十项修复范围；SSO 实际接入、外部监控、异地副本、合规认证与参考级成片能力均未因此被验证。

## 2026-11-14 复审修复

- authToken 等凭据字段参与统一加密及脱敏。已泄露令牌仍须在供应商侧核查和轮换，代码不能撤销历史副本。
- 工作台图片/视频队列复用管理员 pricing（providerId/modelId 的 perImage、perSecond、perCall，单位 USD）和积分预占。必须启用 billingEnabled、配置有效正单价和足够积分；未定价拒绝提交。结算使用提交时冻结的报价，供应商实际成本仍保留未知，不冒充真实账单。真实配置未自动修改。
- 查询 HTTP 错误保留远端任务号；已提交/受理不明的任务禁止直接取消并释放额度。
- API 身份检查前置；cloud JSON 读取限额，登录 16 KiB、普通 body 2 MiB；Express API 同时缓冲最多两个请求体。
- 工作区写入复用云端配额预占，统计租户文件和未清理媒体；当前采用同步扫描，较大目录需升级空间账本。
- 画布版本冲突保留未保存编辑，不自动获取新版本后覆盖。
- 镜像初始化备份目录权限；启动按最后成功时间补跑备份，失败通常 15 分钟后重试。已有 Docker 卷若属主不正确，仍需部署时修复卷权限。
- cloud 媒体 Range 使用文件流，不再为小范围读取整部视频。
- POST /billing/checkout 必须携带稳定 Idempotency-Key（16–128 位字母、数字、下划线或短横线）；同一次购买重试保持相同键，不同购买更换键。归档 legacy 客户端不属于当前工作台，旧调用方需适配该安全要求。

本轮无新增测试文件；隔离数据验证覆盖脱敏/加密、购买去重及冲突、请求字节限额、存储配额、媒体 206/416、备份创建与恢复。没有操作真实支付、真实供应商账单或生产备份卷。

### 提交前复查

复查补齐按次计价、恢复任务沿用已存报价、超配额时允许不增长的文件保存，以及损坏备份状态记录不会永久阻断备份。

使用隔离数据和真实本机 HTTP 验证加号邮箱密码登录、Cookie 会话、创建项目、首次/更新保存、旧版本冲突拒绝、只读成员拒绝写入，以及关闭账号模式后的项目创建/保存/读取。模拟供应商验证生成请求去重、503 后提交一次查询两次、已受理取消保留冻结额、按次报价预占与成功扣费（仅结算一次）；媒体 Range 的 206/416、支付去重、凭据保护与备份恢复均通过，损坏状态记录下启动备份补跑通过。

主服务、cloud、前端类型检查和前后端构建通过；未进行真实付费模型、真实支付、Docker 卷或双页面浏览器交互验收。共享媒体生成仍要求明确单价和可用积分；这属于本轮费用保护的预期限制。
