# 故事工作台

项目内点击「故事工作台」。故事短片、连载短剧、效果广告、品牌片和 MV 共用资料、版本与反馈管理，创作判断按作品类型区分。

## 短剧、中剧与跨集一致性

- 在「目标与资料」选择「连载短剧 / 中剧」，设置剧集形态、计划集数和单集目标时长；剧本逐场保存所属集号，跨集保留唯一场次 ID、人物知情、事实与伏笔。旧项目的分集字段可留空，已有版本不自动改写。单个候选仍最多 100 场，计划集数不代表已写完或已生成的集数。
- 「镜头制作」可切换当前集 / 序列并新建下一集；新镜头建立在当前集。助手创建序列时保存 `kind:serial`、`episodeNumber`、`storyRevisionId`，镜头通过 `source:{sceneId}` 关联采用正文，集号不符会拒绝保存。每集沿用已有剪辑与导出能力，不把整集时长当作模型单次生成时长。
- 各集共用项目资产、定妆、世界、影调与配音方案。「接戏来源」可以选本项目更早集的镜头，继承服装、伤势、持物等末态；没有显式来源的首镜仍从资产基线开始。倒叙、平行线按实际承接关系选择来源，不按场景名字猜测。
- 前集镜头或已采用视频的实际状态变化会向后集传播，使受影响的镜头检查与成片指纹过期；旧素材保留。跨项目、向后和循环引用不允许；删除或重排导致接戏失效时整个操作回滚。复制项目会重映射接戏引用。
- 剧集正式生成要求采用资产，并实际发送角色、服装、场景参考；视频复用已检查的主关键帧。缺少参考或模型容量不足不能靠文字绕过。定稿导出要求本集已采用且检查仍有效的视频，无未解决的高严重度连续性问题；工作片可继续导出草稿。

这些约束用于减少漂移和阻止无依据的验收，不保证模型像素级身份锁定。真实角色、表演、声音与跨集接点仍需看片。动态分镜预演保留每次最多 10 分钟的限制；中剧正式成片按镜头生成后在制作序列中剪辑导出。

本次分集扩展通过 cloud、server、web 和相关工具包类型检查，以及前端、服务端、工具构建。临时目录与内存数据库验证了分集 HTTP、非法输入、跨集状态传播、检查指纹失效、引用冲突回滚、复制引用、参考输入门禁和剧本原子保存。未调用付费模型，也未以这些验证证明真实中剧视频的生成质量。

## 从资料到采用版本

1. 保存作品目标：受众、观看渠道、想让观众感受或做什么、时长、语气、结尾及限制。
2. 上传 TXT / MD / PDF / DOCX、图片或参考视频。文档保留原件与提取正文；PDF 正文带页码。首页故事、广告和已有素材入口上传的附件也进入资料列表。
3. 指定用途：事实依据、风格参考或结构 / 剧情参考。分析结果包含精确引句、位置、读取范围及未知项，可人工校正。作为事实的资料需要确认；文件变动后须重新分析。
4. 用已配置的创作模型生成 2–3 个方向，选择后发展剧本；也可手动录入或从已有场次表与根目录正文整理候选。已有定稿无需重写。
5. 剧本保存稳定场次 ID、正文、对白 / 旁白、目标、阻碍、变化、人物知情、因果引用，以及人物事实和伏笔。每次修改创建版本，旧版保留。
6. AI 审稿必须引用该版原文并声明审阅场次。明确矛盾须修改或记录保留理由；理解风险、审美建议供用户判断。也可逐场人工审阅后记录结论。审阅覆盖全片后，由用户采用。

聊天创作时，助手调用 `requestStoryApproval` 展示故事标题、版本、场次数和大纲，用户直接点击「采用此版本」或「暂不采用」。采用成功后助手继续已授权的后续工作，无需切换到故事工作台；工作台原有采用入口保留。等待确认期间项目发生修改时，旧卡片不能覆盖新状态，须重新核对后确认。已采用的有效版本不重复询问。

资料理解、创意方向选择和审稿问题保留决定也通过 `requestStoryDecision` 聊天卡片完成，内容从已保存记录读取。资料卡展示读取范围、引句和未知项；方向卡同时列出全部候选；审稿卡展示问题依据及拟保留理由。只有明确点击对应选项才保存，暂不决定或跳过不会授权后续步骤。发布反馈仍由用户填写实际观测数据。

聊天输入区上方显示待确认数量，点击即可定位卡片；滚动查看历史不会卸载待回答表单。卡片加载失败可原地重试，提交失败会保留输入并显示错误，无需停止整个任务。停止后的确认显示「已停止」，不会误显示为仍在保存。

资料、目标和方向变更使旧版依据待复核；单场改写仅替换指定场，显示直接改动及因果依赖。不会把候选剧情自动变成正式记忆。所有写入校验版本，冲突时不覆盖；「重新载入」明确放弃未保存编辑。

## 动态分镜与正式制作

- 动态分镜逐场设置时长，可上传图片 / 音轨，或用已配置模型生成单张草图、临时配音。没有图时使用明确标注的文字分镜卡。
- 有台词须有音轨；音轨比场次长时停止导出并提示调整，避免截断对白。FFmpeg 合成 1280×720、24 fps、H.264 / AAC MP4，当前每次最多 10 分钟。长篇拆为单集或段落。卡中文字可能为摘要，不能把它当作完整逐字字幕。
- 新剧本版本复用未变场次的预演方案；修改场次清空图与音轨。旧方案、旧预演始终保留。
- 「交给助手整理制作场次表」仅整理已采用版本的场次与拆解，沿用现有助手模型，不自动生成付费媒体。场次表记录 storyRevisionId；剧本采用版本变化后，旧场次表会提示待更新，拆解保存会阻止版本错配。
- 「配音与口型」中可同步采用剧本台词：按行导入后核对对白 / 旁白、分配说话人、选择固定音色及每句情绪和语气。未变场次复用配音；改变的场次重新核对和生成。同步前将完整旧方案独占保存为 assets/speech/voiceHistory*.json，保留原音频和口型视频。
- 正式语音 / 口型继续使用已有服务适配；开源部署见 [语音与口型](./voiceProduction.md)。

## 发布反馈

反馈绑定实际故事版本及发布链接或预演，记录渠道、受众、自然 / 付费分发、花费、观察窗口、指标口径、数据来源或观众原话。未知数字留空，真实零值保留为 0。修正观测时新增记录，保留历史。

表格按记录比较，不把不同渠道和投放条件直接合并。反馈可导出 JSON；每次导入一条，核对后再保存。模型复盘引用已存反馈，分别写观察、限制、待验证解释和下一次实验；不会自动改定稿、生成爆款概率或伪造观众数据。

## 当前能力边界

- 文本分析最多读取提取正文的前 400000 字节；扫描 PDF 仍需 OCR。参考片分析只查看 6 个等间隔采样时刻的实际帧，列出时间，不包含声音、其他时间画面或完整剧情理解。
- AI 创作、视觉分析、草图和 TTS 需要对应已配置服务，质量取决于模型；没有服务时仍能手动编辑、人工审稿和用上传素材预演。自部署开源服务需要自行准备运行资源。
- 预演是节奏与理解检查，不代表正式成片。正式镜头、演员表演、口型质量和传播效果仍需逐项验收及真实发布反馈。
- 故事数据保存在工作区 storyProject.json，通过专用接口原子保存；通用文件接口不能覆盖、改名或删除它。项目目录整体备份仍可正常进行。
- 新安装使用更新的 story / adfilm 技能。已有安装的可编辑技能目录不会被应用启动覆盖；如保留了旧技能，请通过技能管理导入新版并核对自定义内容。故事工作台自身使用本次内置规则，不依赖旧技能文本。

## 本次验证范围

执行了全工作区类型检查、工具 / 前端 / 服务端构建，以及临时数据目录的 HTTP 和浏览器手动验证。检查了资料引句、并发版本、人工采用、审稿覆盖、循环因果、局部版本、资料变更及反馈零值；实际通过浏览器导出两场预演并用 ffprobe 核对视频与音轨。

未使用付费模型或真实观众数据证明作品质量；开源模型实际推理和内容效果不属于上述构建与流程验证的结论。
