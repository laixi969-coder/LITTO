## 实际修复

1. **恢复自动仍被拒绝。** 空工坊对象仍为真值，轨迹或口型模型会要求用户再次恢复自动。保存时清除无效修饰；服务端先校验并编译有效内容，兼容旧画布的空对象，再判断模型能力。有效文字修饰仍会被不支持的模型拒绝。
2. **视觉参考显示新用途，实际发送旧快照。** 重新打开工坊时，将仍在项目收藏中的选用项更新到独立草稿，统一更新用途、说明及对应摄影方法；关闭不改节点，保存才生效。已从收藏移除的项目继续保留明确的历史快照，允许手动移除。
3. **断连引用被静默删除或错绑到另一素材。** 保留标签及来源身份，明确显示已断开，重连原素材后恢复。生成时也读取持久化的标签身份，不依赖选中节点或输入框挂载；无法解析时拦截。图片、视频、文本节点和 3D 导演台共用此解析，纯文本序号继续兼容。
4. **创建副本和粘贴没有完整迁移参考。** 两个入口复用同一迁移函数，处理首尾帧、3D 图片来源、分镜参考、参考排序及提示词标签。复制范围内指向新素材，范围外保留原身份。保留失效标签也避免了粘贴先挂节点、后接边期间引用被删除。
5. **空请求被默认肤质指令放行。** 实际 HTTP 验证发现单机请求会先补 SKIN，再绕过空内容校验。现在在自动指令注入前校验真实正文、分镜、有效工坊内容或机位参考，空工坊不能单独触发生成；正式镜头继续由既有编译链路提供正文。

- 实测整组创建副本及剪贴板复制粘贴。读取实际保存的画布，确认三套视频链的首尾帧、提示词标签来源与各自入边一致，参考排序完成迁移，没有因初始化丢失标签。
- 通过真实故事接口修改收藏用途，再打开工坊，预览采用新的 lighting 方法和说明；关闭后磁盘仍为原 composition 快照，保存后磁盘更新为 lighting。恢复自动并保存后 visualModifiers 字段清除；刷新重开，正文、分镜及引用保留，工坊不含残留修饰。
