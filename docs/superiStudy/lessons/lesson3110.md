# 3110｜场景剖面参考：补空间信息，不把示意图当三维真值

来源：[别只给AI一张图：让视频场景更稳定](https://www.super-i.cn/info-3110.html)。作者 Loki，页面显示“4天前”。2026-10-26 完整阅读正文各节与示例提示词（页面章节由六跳九，不推断缺失章节）；实际观察两张关键图。模型名称与参数只记录为案例条件，未验证当前供应商支持情况。

## 作者方法摘要

单视角缺少画外信息，多视角也可能互相矛盾；用移除屋顶及部分墙体的斜俯视图集中交代门窗、家具、通路，同时带入场景光色。视频生成时标明其空间用途，人物参考与当前动作另写。作者明确承认这仍是二维图，不是可测量模型。

## 关键图实际核对

空间图：`https://superi.mfdemo.cn/chaoji/2026/10/22/6ad9bb7b8768f.webp`。可见多卧室住宅剖面，蓝色窗外光与室内暖灯并存，门洞与家具可辨。图中“餐厅”标签靠近客厅沙发区域，而餐桌在画面左边；奶奶卧室文字在外墙下方。说明标注并不自动等于准确语义，必须逐房检查文字对应和动线，不能直接以生成标签建立机位事实。

生成界面：`https://superi.mfdemo.cn/chaoji/2026/10/22/6ad9bcc9960b3.png`。可见四张人物图、第五张豪宅场景图及一条视频参考；文本把图5指定为空间参考，另有胶片/器材/色彩描述，UI 显示 Seedance 2.5、480P、30秒。它不是只用上述住宅剖面加一张人物图的受控实验。截图仅有成片缩略画面，不足以证明全程布局稳定、真人质感或动作质量。

## 需要先确定的空间真值

已有真实室内照片时，原图可见部分是依据，未见部分只是待确定补全；不要把生成补全反过来当成真实建筑。新虚构空间则先由剧本需要确定入口、行动路径、遮挡、出口和关键家具，再允许其余区域简化。没有人进入的次要房间不必逐间精细建模。

拓扑比“45°”更关键：哪些空间相通、门开在哪面墙、角色经过哪条路、摄影机能否到达和看见接触点。斜俯视只是展示选择；开顶视图不能让模型把正式镜头也拍成玩具屋，切掉的墙在正片中仍应存在。

## 与前几篇方法的冲突如何处理

3033 强调一图一个主要职责，本篇允许空间与气氛合用，两者不必机械统一。若场景光色与本次拍摄条件相同，可明确兼作氛围；若同一房间有日夜两场，应保持结构，使用当前场次的光源设定覆盖，不能为了布局保留旧夜景。将角色、场景、构图职责写清，比规定绝对“一图一用途”更可执行。

住宅案例是风格化三维动画，不能把这一材质风格迁移为真人视频默认；提取的是布局表达方法。教程的器材与分辨率词也不能保证最终呈现，尤其 UI 实际输出分辨率与文字“4K”不相同。

## 原创执行改写

“此参考仅定义门窗、固定家具和通路；切除墙体用于展示，正式镜头保留完整房间。当前镜头机位在入口内侧，角色沿桌子靠窗一侧通过，桌后通道保持可通行；场景光源按本镜已定夜景，忽略参考的日光。”实际使用要以真实引用编号替换“此参考”，并确认模型接到了该图。

## Milimili 接入与完成判断

`continuity` 已保存场景固定项与按用途引用；`referenceQuality.md` 已要求场景资产记录门窗、障碍、出口和固定光源，镜头保存 blocking、camera.position、路径与保持项；`schema.ts` 的 lighting.directionSpace 已区分 world/screen，compiler 也明确输出坐标语义。优先落实这些现有字段，不另造地图真源。

当前没有证据证明模型能从剖面图精确还原全部几何。应逐镜核对共同地标、反打方向、通路和遮挡；至少检查一次跨角度切换和完整移动，不能只凭一张场景图或首帧给空间连续性通过。本轮未运行生成，也未完整播放示例。
