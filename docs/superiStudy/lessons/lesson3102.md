# 3102｜多人站位：预演简化、真实编号与逐段状态

来源：[用导演台固定多人站位：从剧本到 AI 短片的完整流程](https://www.super-i.cn/info-3102.html)。作者西瓜，页面显示“2周前”。2026-10-26 完整阅读八节正文；下载并只读检查两个附件：提示词汇总 DOCX 全部三段、Skill 主文/三份 references/agents 元数据。未安装附件，未调用 LibTV 或生成模型，示例视频未完整播放。

## 作者方法摘要

先以剧本和资产形成站位提案，用简化三维人物还原并手动修正；导演台导出的单帧负责空间构图，正式人物、场景和道具另有参考；按实际图序编写共用规则及各段内容，低规格筛选后再超分剪辑。正文与附件都说明站位参考不保证完全执行。

## 这一步额外解决了什么

从带服饰与环境的合成图转为简化代理模型，主要减少外观干扰，让颜色、位置、朝向、坐站和遮挡更可辨。代价是代理形体、比例与正式角色可能不同；手握关系和面部表演也不能由简单模型保证。若现有构图草图已足够清楚，不必为了复刻教程额外绕一次工具。

代理颜色只作当前截图里的身份标签，不能污染服装或肤色。身份映射应从实际标签、图像与项目素材核对，不凭“红色看起来像管家”猜。机位变化后重新派生屏幕左右，原世界空间位置不变。

## 附件逐条核对发现的冲突

这些是文字版本之间的矛盾，不是已确认的成片错误：

1. 网页的站位图提示词把旧照片放在管家托盘；原剧本及 DOCX 动作将照片安排在布莱克腿上。DOCX 三段共用说明仍保留“从托盘递出”，与本段实际交接不同。必须先选定同一持有链，删除旧版本描述，不能靠增加“不许穿帮”解决。
2. DOCX 第一段开头写老人握笔悬停，随后布莱克放下钢笔，之后老人再次拿起。单支笔的来源与先后冲突；应让开头的实际持有状态与后续动作一致。
3. 第二段交照片时布莱克站起，第三段开场又“仍坐着”，中间没有坐回动作。可以在受控切点建立坐回的依据，也可以保持站立；不能把“仍”当成已发生的过渡。
4. 网页概括每段前一秒全景，而第三段 DOCX 用短中景接照片特写。说明最终稿并未机械执行统一开场，制作时应依据当前采用版本与叙事需要，而不是拼接所有范文。
5. DOCX 要求左右不随切镜翻转，实际只能理解为沿原参考坐标保持布局；如果照字面把屏幕左右永远锁定，就会限制反打或造成矛盾。应明确“世界位置保持，屏幕位置按机位变化”。

这些问题说明长共用块最容易携带过期动作。应该只共用身份、环境与摄影原则，一次性事件和持物状态放在当前段，不靠全片全局否定词压制状态更新。

## 原创的最小状态交接

假设一件信物由甲交给乙：本段起点甲持有；先乙手接触并稳定托住，再甲松开；本段结果乙持有、甲空手。下一段从乙持有开始，不能再次执行交接。镜头若只拍脸，也需承接画外持有状态，但无需反复把全部细节塞回动作指令。

若真实成片与计划不同，应以观察结果决定修复或接续，不能把计划结果记成已观察。多人同时行动应保留剧情必要的并行反应；不能为减难把其他角色都冻结成等待者。

## Milimili 实现映射

- `schema.ts` 已有 blocking 的前/中/后景、camera.position/side/axisCrossing/screenDirection、camera.design 的起止/主体路径/机位路径及唯一时间线。使用这些位置存当前镜头，不新增导演台专用平行规格。
- `compiler.ts` 已按参考 role/weight 与供应商能力筛选输入；有权重排序、权威参考、额外首帧等处理。实际发送顺序不能按资产表原始顺序猜测，必须检查最终 sent 输入与目标节点实际编号。
- `COMPOSITION`、`IDENTITY`、`ENVIRONMENT`、`GEOMETRY` 分别对应构图、人物、环境和道具用途；角色图、站位图和首帧不能视为等价输入。九张参考若超出模型或适配器上限，应显式报告，不能在文字中假装全部已接入。
- `state.ts` 与 `continuityFromShotId` 可保存实际起点、变化和结果；`interactions` 可表达接近、接触、受力、承托与释放。表演和对白仍走既有字段，不再建另一条秒数表。
- 声音固定不能只写几句形容词。多人对白仍应按 Milimili 现有实测配音/专用口型链处理，不因为教程用原生生成便跳过。

30秒、480P、三段是该案例设置，不是通用模型上限或成功方案；所谓某团队重试二三十次没有本次独立证据，不写成成功率或预算依据。预览片需先检查结构和表演，再决定是否值得超分；超分不会修正错脸、持物或接触。每段开头是否裁除由其是否正式画面与剪辑需要决定，声音时轴也随切点更新。
