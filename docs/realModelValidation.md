# 真实模型创作链路验证

验证时间：2026-10-11（纽约时间；响应记录为 UTC 2026-10-12）。使用当前已选的智谱 `GLM / glm-5.3-flash`，没有改选模型，也没有使用模拟模型响应。凭据只用于独立本地验证服务，未写入本报告或 Git；原用户模型配置未修改。

## 实际经过的链路

文字请求通过前端共用的 `useNodeAi` → `/api/ai/generate` SSE → Pi SDK → 已配置的智谱官方接口。模型必须调用结构化保存工具；普通文字回复不算保存成功。校验错误实际返回模型，由模型修正再提交。

短剧最后一版含助手的最小人工校正，解决清单可读性与楼层转场歧义；只在独立验证样本中采用，不冒充用户作品定稿。两类分镜最终稿也记录人工校准：写实跨镜绕行起点、玄幻局部秒数、退步坐标及方向。模型原稿和修订稿均保留，未把人工修改说成模型原始输出。

六个最终镜头的实际编译告警均为空，`requireCompiledInputs` 通过，镜头指纹有效；逐个核对下一镜 `start.characters` 与上一镜 `result.characters` 一致。这是计划状态和文字规格验证，不是实际视频连续性证明。

## 已修复的问题

1. 故事面板首次打开未恢复当前已选模型，仍要求用户重新选择。现在复用唯一有效选择，浏览器刷新后已核对。
2. GLM 5.3 不允许关闭思考，缺省推理强度为 max。共享适配明确发送 enabled 与合法强度；普通请求用 low，显式高档选择仍保留，工作台与 Agent 共用，原请求预算 hook 保留。依据：[智谱接口文档](https://docs.z.ai/api-reference/llm/chat-completion)。实际修复后请求成功，但不同提示的耗时不能当作严格性能对照。
3. 真实创作曾漏掉 brief 的公开行动，speech 也曾包含角色名前缀。共享字段说明与创作／审稿提示补齐正文、朗读内容、知情证据和 brief 核对；仍需实际审稿，不用关键词启发式假称语义正确。
4. `intendedStateDelta` 原先接受角色名／ID 直接放在根层，结束位置没有进入角色状态组。现在限制标准分组，创建与更新共同校验人物／服装／道具的项目归属及类型；null 仍可清理已删除资产的旧状态。旧非法记录不静默改写，制作检查返回明确的 409 修正提示。
5. 项目复制只映射 `assetIds`，状态与攻防、配音、服装归属仍指向源项目。复制时同步映射精确资产 ID 的键和值，并重算状态；实际复制三镜后的指纹与继承验证通过。
6. 模型交接曾从旧候选复活已经删除的清单状态和手电。场次／拆解工具说明明确只沿用已采用版；真实模型重新保存 v2，最终道具及服装描述未保留这些旧设定。
7. 动作资料与摄影字段补充单镜局部时间、跨镜末态接续和编译告警处理规则，防止把累计秒数直接发给单镜生成请求。

本次提交同时纳入工作区此前已有、经真实调用验证的智谱官方域名 Fake-IP 兼容改动。范围仍限两个指定官方域名，保留公网地址检查、TLS 证书与 SNI 校验、禁止重定向和不重试生成请求。

## 验证与保留成果

- web、server、cloud、sceneList、mediaGeneration 类型检查通过；web/server 及两个工具包构建通过。web 构建仍有原有的大块体积及配置加载提示。
- 在独立临时数据库调用真实创建／更新入口，根层误写、假资产 ID、跨项目 ID、类型误组共 8 次拒绝；失败后镜头记录不变。已删除资产的 null 清理接受；旧非法状态指纹返回 409。相关验证事务回滚。
- 项目复制使用真实领域函数，在事务内核对资产 ID、攻防引用、镜头指纹和邻镜继承；另实际核对服装归属、初始版本快照、wardrobeId 和 heldBy 重映射，然后回滚验证副本。
- 共享模型参数在内存核对 off/low/medium/high/xhigh 的合法档位映射、正文与既有 thinking 参数保留，以及无关域名／模型不变。
- 两路只读对抗审查已完成：逻辑审查发现的跨项目状态与复制引用缺口均已修复，最终逻辑与仓库规范审查均无阻断问题。
- 未新增测试文件、测试框架或自动检查入口。
- 成果保存在 Git 忽略的 `data/creativeValidation20261011/`：短剧各版、审稿、最终可读稿、场次历史、资产拆解、视觉排名与用途；动作初稿／修订／人工校准最终稿、编译文本和计划状态；模型响应使用量记录。
