# 悬疑短剧实跑：两套编剧方法比较

本题结论：**山音稿A的悬疑张力与场面推进更好；两稿核心时间与录音因果均不成立，都不能直接采用。** 若只按可读性选继续开发的底稿，本轮偏向A；若按悬疑逻辑验收，两稿均不通过。生活题材中B领先的结果不能推广到本题。

## 运行条件

2026年11月8日本地时间执行。重新读取 MILIMILI 当前配置，仍为 AtlasCloud 的 `openai/gpt-6-luna`，OpenAI Chat Completions 协议。使用应用同款 ModelRuntime、modelFetch 和 prepareModelPayload 发起真实调用；密钥只在内存解密，未改变模型设置。

两组收到相同题目：暴雨封闭办公楼，夜班保安收到自己的求救录音，显示发送时间比当前时间晚十分钟。固定三人：保安、物业经理、女租户；主要空间为保安室及相连走廊。现实解释，禁用穿越、鬼怪、梦境、精神病、失忆、万能黑客。录音来源、时间异常、动机须解明；至少一次有前置证据的认知反转，并有改变局面的后续行动；单集局部结局完整，正文1200—1600个非空白字符。

同样采用 temperature=0.8、maxTokens=8192、关闭思考，Luna适配为reasoning_effort=none。本轮先B后A，与生活题材轮次相反；每组独立上下文，不输入旧故事、对方故事或此前评价。

每组都执行“方案→初稿→一次作者修订”，共6次正常stop。修订时给予程序测得的初稿正文字符数，要求同等核对录音、时钟、知情、权限、道具、反转行动与收束。本轮不因一稿较差追加重抽，不人工补写。

A使用山音原包主入口、核心方法、短片、短剧、对白、叙事六份资料；B使用当前运行目录的storyCreation.md。各自方法体量不同，没有将A人为缩成B的长度。两组共用中性阶段提示，没有把writeStoryDraft中固定的现有方法提示施加到A上；因此这是同模型的方法比较，不是完整聊天Agent或工作台的端到端比较。

## 两稿均未解开的硬问题

### A：时间解释方向错误，旧录音没有来源

1. 开头发送时间02:27、墙钟02:17；后文电脑系统时间02:07、实际时间02:17。若“发送时间取的是电脑时间”，慢十分钟应显示更早，不能解释开头更晚十分钟。文本没有建立另一层偏移或不同时间字段的规则。
2. 录音已经在开头收到，后文却说明“排队任务则会在门禁复位后发送”，而复位发生在接收之后。除非存在此前另一次复位，但正文没有写，不能替作者补。
3. 最终称经理“把旧录音排进队列”，却没有交代保安何时、为什么说过“别让她碰门禁，老邵已经倒了”。登录记录只能证明账号操作，不能证明这段具体内容的来源。钥匙落地声与后来事件相似，也不足以补齐录音产生过程。
4. 女租户为何挡住保安接近伤者、断卡与经理倒地具体有什么关系，没有交代。经理为了拿回照片而制造预告和自己倒地，手段如何促成目标并不清楚。
5. 钥匙先放桌上，熄灯时听到落地，后来又写“钥匙仍压在桌沿”，缺少取回或多串钥匙的依据。

这些不是单纯的“技术术语没写准”，而是核心悬念的原因与发生顺序不成立。作者修订几乎没改变正文，字数只增加1，未修复承重问题。

### B：定时发送不解释提前收到，录音中的预知被放过

1. 23:08已经收到、播放的录音，结尾23:18又写“那条录音准时送达”。普通定时发送不能解释接收者提前十分钟收到它；如果开头是草稿预览、结尾是另一收件人收到，必须提前写明，原稿没有这样建立。
2. 保安说十分钟前录了“报修语音”，实际播放内容却是“她把我锁在走廊了”“许澄，柜门后面——”。正文没交代这些事情在录音前何时发生，也没有兑现“柜门后面”到底是什么。
3. 保安自己设定过发送给经理的消息，却收到来自自己号码的消息，并对自己说过的“锁我”表现出首次获知。发送对象、接收方式和人物知情没有接通；正文不能依靠遗忘补洞。
4. 半小时前签收报修单只能证明经理知道问题，不能直接证明她准备关闭报警器掩盖失职。正文用叙述句替这一推断下结论，然后让经理承认，证据到结论之间少了一步。
5. 危险处置依赖临时的木尺、纸箱塑封等手段，不能凭这些物件的出现就证明现场操作安全或合理。本报告不把这段当作应急操作指导。

修订虽被告知初稿偏短，最终仍从1122缩至1040字；说明这一轮作者自检未有效落实篇幅和逻辑要求。

## 两轮合看

上一轮生活题材B的行动链更清楚；本轮悬疑A的场面张力更强，不能据生活题材认定现有方法普遍优于山音。另一方面，A多用约10倍上报token，也没有解圆最关键的时钟和录音问题，因此也不能据本轮戏剧性就替换现有编剧入口。

目前更准确的结论是：**两套方法各有表达倾向；当前模型在这两个样本中的自检都不可靠，悬疑承重逻辑尤其需要逐项核对。** 本轮选择A作为可继续开发的悬疑底稿，不将任一稿标为完成验收。现有技能与产品代码未因这次比较改动。

评价由本助手阅读实际输出完成，非独立读者盲评；同模型单题单次、不同上下文体量，且两轮题材和阶段数不同，不计算总体胜率。这里的文本证据比主观精确打分更有用。
