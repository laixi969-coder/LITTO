# 故事到分镜能力与生效链路核对

日期：2026-11-07。范围：现有真实MV项目、当前运行时技能、编剧/分镜入口、用户提供的GitHub技能索引。未生成媒体，未改旧项目采用稿或素材。

## 判断

这段真实片段首先暴露的是转译与执行链路问题：采用稿s03已经写出起身追两步，分镜却写留坐；不能把这个例子归因为编剧没有写出动作。已有编剧能力仍可能写出弱故事，但当前证据不足以证明换一套技能就能解决，也不能把审稿通过当观众体验达标。

## 已有能力和实际生效

- story：独立writeStoryDraft先做节拍规划，再写正文。MV还具有原曲顺序、可见证据、人物回应、动作时间预算与作者修订能力，返回skillApplied等真实状态。
- cinema / continuity：已有目标与策略、触发与反应、人物调度、起止状态、相机动机、接戏与声音覆盖方法。
- 导演接口：源节拍sourceIndexes、对白保真及前后镜关系校验；规则草稿不能直接作为正式生成方案。
- 正式提示词：ShotSpec经编译器与实际模型适配，已有时序保留及压缩保护。独立文本提示词与正式ShotSpec是不同入口，不能把其中一个入口的能力宣称覆盖全部。
- 实际检查data/skills中6套技能的83个文件，全部与packages/skills对应文件一致；没有发现缺文件、旧副本覆盖或自动调用禁用。实际加载入口也无缺项警告。

## 发现与修复

### 1. 阶段资料过量

用真实项目运行loadProductionSkillContext，“把剧本拆成分镜”原先自动加载22份资料、132034字符，包括已完成的故事创作方法、资产与生成协议。它们确实进入上下文，但如此大的方法量存在稀释具体剧情的风险；没有用这个数量推断模型必然遗忘。

现在对已有采用稿且明确仅拆分镜的请求，复用7份现有镜头、运镜、表演、覆盖和连续性资料，38967字符，约减少70.5%。不切掉所需的表演与接戏方法；其他资料仍能按需读取。不明确的“继续”、完整视频制作、显式点名技能、重写故事不套这个窄路由。此优化尚未做付费视频A/B，不宣称画面质量已提升。

### 2. 普通制作入口没有落实来源

真实旧会话通过productionSpec逐镜创建，没有调用writeStoryDraft或分镜团队，也没有为这些镜头传source；序列同样没传storyRevisionId。工具调用缺席不能证明当时自动注入的技能正文缺席，更不能据此声称技能未安装。

修复普通productionSpec入口：已有采用稿时，新建shot必须明确source.sceneId，复用既有场次快照写入；新建sequence未指定版本时默认关联当前采用稿。不凭标题猜场次，不覆盖旧镜头，也不将完整剧本复制进每个视频提示词。已有更新入口的来源解析继续复用。

通过真实createAgentToolContext.media.production入口，在临时工作区和内存数据库复制真实采用稿验证：缺source被拒绝，s99无效场次被拒绝，s03完整原文和版本成功落库；序列正确关联采用稿；生成任务数为0。没有新增测试文件。

## 仍需区分的边界

- 独立编剧工具可用，不等于每条主Agent路线都已实际调用；历史稿件也不会自动获得新写作能力。
- 场次来源是可追溯证据，不保证镜头语义正确；上一轮的叙事审查与完整看听仍需要发挥作用。
- 普通制作的独立审查可调用，与自动成片的前置检查不是相同的覆盖范围；本轮没有宣称所有旁路都已强制语义审查。
- 本项目旧OTIO与正式剪辑数据库仍需区分，不能用分镜顺序冒充真实播放顺序。
- 整片是否让观众愿意看，需要新输出的剧作和成片实测；本次完成的是已证实的加载/来源链路修复。

本轮不修改旧视频、不提交视频供应商任务。复用 `reviewNarrative`、`requireReviewed`、`assertSpeechExport` 与最终审片规则：

- 公共生成 worker 在首次提交与失败重提之前核对采用剧本、分镜及实际 compiledPrompt；拒绝缺服务、缺来源、检查未通过或检查后版本变化。已有供应商任务的恢复查询不重新提交。
- 审查通过仅按完整输入快照缓存在当前进程（最近 100 项）；不接受调用方传入“已通过”标志。普通制作、云端直接生成与自动制作共用这道检查。
- 叙事视频不能以 standalone 或直接供应商执行绕过镜头绑定。独立非叙事素材、资产图和分镜总览不强加故事流程。
- 正式渲染前检查叙事与剪辑，完成前复核版本；最终验收写入 pass 前再次核对。草稿仍可用于检查问题，不视作验收通过。

# 事实、接戏与实际事件证据（本轮优化）

- 分镜来源不只核对 revisionId：场次正文、对白、人物知情必须与采用稿一致；顺序证据只能引用对应场次的镜头，不能借另一场相似动作充数。
- 复用已有状态继承、前镜采用检查和实际剪点取帧机制。叙事快照增加明确前镜的计划/实际末态、候选及媒体哈希，先审前镜是否符合剧情，再审后镜是否接续，不能顺着错误改剧情。
- 完整视频观察按已有原句→镜头映射返回 eventReviews，验证覆盖、唯一引用、实际时间窗口和同场关键事件顺序；按现有 finalReviewPlan 返回逐剪点 cutReviews，验证当前剪点 ID、时间码及结论。
- 修复 assertStoryObservation 原先视觉阶段不检查叙事、表演、接戏的问题。实际观察 revise/unverified 会阻止采用和定稿，不能仅靠总体评价通过。
- 自动制作将观察员事件证据与切点结论传给现有采用/验收入口；普通制作新增 observeNarrative 操作，复用同一完整视频观察器。普通制作的 creativeReview.events 同样核对原句、时间、先后和结论，无关键事件的过场允许明确 []。
- 观察证据随任务保存；复用时核对当前叙事快照、媒体和观察模型，旧版仅有摄影检查的记录不能替代新检查。

本轮内联验证覆盖有效证据、触发反应倒序、错镜时间、空时间、事件漏项/重复、旧剪点、未确认接点、同版本原稿篡改、过场豁免，以及视觉/最终阶段的失败拦截。未新增测试文件，未调用模型或视频供应商。规则验证不等于实际审片模型的识别率验证；关键事件提取与声画识别仍可能漏判，不能宣称绝对连贯。
