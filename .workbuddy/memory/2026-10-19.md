## 发现一个坑：data/skills 运行时版本落后且不会自动升级

- 运行时技能根目录 = `dirname(conf.path)/skills` = `data/skills`（`apps/server/src/utils/skills/files.ts:12`）。
- `data/skills`：workflow **2.9.1**、story **1.2.0**，无 characterCasting.md，characterStyling.md 仅 41 行。
- `build/skills` 与 `packages/skills`：workflow **2.17.0**、story **1.4.0**，characterStyling.md 124 行，多出 characterCasting.md。
- 原因：`apps/server/src/utils/plugins/syncBuiltins.ts` 按 sha256 三重比对（新源码 / 上次记录 hashes / legacy baseline），任一不符即判 conflict 并**跳过整个技能目录的升级**，只写 `builtinVersions.json`。当前 conflicts = continuity、musicfilm、cinema、adfilm、canvas、workflow、story 共 7 个。
- data 里 workflow SKILL.md 的 hash（07781d…）在 git 全历史里都找不到对应版本（`git log -S 'version: "2.9.1"'` 无结果），来源不明，**不是任何一次源码构建的产物**。
- 已执行（全量同步 A 方案）：备份在原目录 `~/LITTO-skill-backup-20261019/skills`（896K），然后 `rsync -a --delete packages/skills/<name>/ data/skills/<name>/` 覆盖 9 个内置技能。`diff -rq packages/skills data/skills` 仅剩 `builtinVersions.json` 与 `initialized` 两个运行时标记文件，内容完全一致。

- `builtinVersions.json` 的 conflicts 未手改：下次服务启动时 `syncBuiltins` 会因 current === 新源码而判定不冲突，自动重写 hashes 并清空 conflicts。手改 hash 反而会制造真冲突，不要动。

## 成片自检（同日，老板要求逐条分析问题）

逐镜抽帧 + 段边界亮度 + 音量统计后，确认 7 类硬伤，报告在 `data/deliverables/记忆税_自检报告.md`：

- **段间黑闪 51 次**：渲染时给每段加 `fade=in:0:6`（0.25s），拼接后每镜都从黑浮出。实测 26.50s 亮度 0.0、26.80s 回到 45.5。**教训：fade 是单段预览习惯，拼片时必须去掉。**
- **跨镜换脸**：陈砚至少 6 张脸、沈望 4 张、老妇人 3 张、祁 2–3 张且左脸疤从未出现。根因是 text 模式无 `imageReference`/`startFrame`，提示词锁不住骨相。
- **服装漂移**：陈砚 101 灰蓝红领 → 404 灰毛衣 → 501 深色外套 → 510 又变蓝。
- **乱码文字**：曲面屏/招牌全是无意义字符，提示词写「不要文字」无效。**应反向规避场景元素（不给「招牌/广告牌」词），而非靠负面指令。**
- **音频 max −0.3dB**（0dB 处 1309 采样），合成时只 `concat -c copy`，没做 loudnorm。
- **关键动作退化成静态摆拍**（103 没推门、106 没白光、207 没松肩、309 变成两手交叠、414 没有倒地）：提示词写的是「状态描述」而非「单一可执行动作」，5 秒模型只会定格最上镜的一瞬。
- **跑题镜**：407 侧门炸开 → 金色隧道孔；409 交火 → 保安举枪摆拍；502 手掌是别人的手。
- 根因链：跳过 breakdown/角色资产 → 图像模型只有 edit 版（无参考图直接报错）堵死资产生成 → 没有 ShotSpec 直接写视频 prompt → 每镜 4.5s 装不下动作 → 无 QC 核对。
- **LITTO 正确链路应是** `story → breakdown(Character.invariants) → 角色三视图 → startFrame/i2v`；绕过这一步，换脸换装是必然结果，不是偶然。
