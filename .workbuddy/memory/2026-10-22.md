「变黄」是场景暖光污染肤色：厨房定场图本身是木色台面 + 暖窗光，人物合成进去后模型把环境色带到脸上。基底只写了「色彩自然准确、不加青橙滤镜」，不够。已加：「白平衡以面部为准——室内暖光或窗外冷光不把皮肤染黄、染红，画面里的白墙、白衬衫与白瓷保持中性白，不整体偏暖。」改后 v1/v2 对比：上版脸偏黄偏红、下版肤色中性、白衬衫是白的。

**bug 3：四视图判定形同虚设。**
`assetImport` 只要求 references 非空，一张定妆照就算「角色卡可用」；flow 与门禁都只看卡在不在，不看四视图做没做。所以换模特后只出了全身图就直接进视频。修法：cast 写 `fourView` 字段（assetSheet 写 true，import 按 references≥3 判断），flow 的 cast 阶段与 `assertAssetsReady` 都要求 fourView，缺则报「只有单张参考，还没有四视图」。

### 流程重构：判据收敛成一份（19:10）

老板追问「为何流程会出现问题，务必修正避免再犯」。根因不是某个 if 写错，是结构问题：

1. **判据有两份**：`flow.ts`（报告）与 `generate.ts`（门禁）各写一套，判据还不一样。改一处另一处不动，必然出现「报告通过、实际不达标」。
2. **判据太弱**：两边都只看 `references` 非空，把「有卡」当成「可用」，四视图做没做完全没检查。
3. **只有项目级检查，没有镜头级要求**：不管这镜是特写还是蹲下走远，都用同一套门槛。
4. **执行者能绕过裁判**：直接调 `generate` + `assetImport` 就能拼出一条片，完全不经 flow。

**重构**
- 新增 `utils/media/assetContract.ts`：`inspectAssets(cwd, {needsLowerBody})` 唯一真相源，返回结构化 `problems[{code,subject,message,hint}]` 与 `ready`。`sameSubject` 的模糊名字匹配也搬进来。
- `flow.ts` 重写：资产阶段全部读 `inspectAssets`，额外返回 `problems` 与 `ready`；清单两步（script/asset）改为非硬门（清单是组织工具，不是资产）。
- `generate.ts` 门禁改调同一函数，并按 `lowerBodyAction` 决定要不要四视图。
- cast 增加 `fourView` 字段；历史 14 份角色卡已迁移（≥2 张记 true，单张记 false）。

**实测**（gateTest 项目，单图卡「试镜」）：蹲下动作 → 400 拦截并给出补四视图的具体做法；近景 → 200 放行。bfPovVlog 与 xiaoQingXin 回归 `ready: true`。
