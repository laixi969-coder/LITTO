# 故事与剧本

目标：用一个好讲、好记、好传播的故事，写出一个不好说破的人性问题，并留下一个让人忘不掉的瞬间。交付的不只是文字，而是**能拍出来、能拆解的剧本**：正文与场次表同时产出，供 [breakdown](../breakdown/SKILL.md) 提取资产，供 [cinema](../cinema/SKILL.md) 规划镜头。

## 分工与边界

- 用户已有定稿剧本：不重写，保存原稿并按 [workflow](../workflow/SKILL.md) 的「已定稿剧本直接进入制作」处理，只做场次表整理；用户明确要诊断时才给改法。
- 产品、品牌、带货：用 [adfilm](../adfilm/SKILL.md)。音乐视频以歌曲与歌词为起点，不套本技能的剧情结构。
- 本技能不规划镜头、不写提示词。镜头规格由导演 Agent 在拆解和资产确认之后生成。

## 流程：每一级先给用户看，确认后再往下

| 阶段 | 交付 | 确认问题 |
|---|---|---|
| 1 故事核 | 情感锚点、一句话故事核、主角表层欲望与深层需求、核心困境、名场面方向、传播钩子 | 这个方向对不对？ |
| 2 大纲 | 按体量的结构（见下表与 [结构模板](references/structureTemplates.md)），含情绪曲线与关键场次 | 按大纲写剧本，还是调整？ |
| 3 剧本 + 场次表 | 可视听的剧本正文，以及同源生成的 SceneList | 采用，还是改某一场？ |

确认用可用的 `askUser`（`title`、`question` 必填，选项为「按当前方案继续 / 调整」）；没有该工具时文字提问并等待。用户跳过或未回答，保留成果并暂停，不自动推进。已知信息不重复追问；开始前只补问影响方向且未知的缺项，最多 4 项，一次问完。

用户修改上游产物（故事核、大纲）后，明确列出下游哪些场次受影响，标为「待更新」，不静默覆盖已确认版本；局部改写只动用户指定的场次，保留版本。

## 创作硬标准

性质要求对任何体量一律不打折，任一不达标就重写。

1. **情感锚点**：故事必须落在一种真实感受上（亏欠、不公、阶层落差、亲密困境、代际冲突、无力感；科幻奇幻则是技术恐惧、归属、失去）。能回答：戳中观众哪种感受、为什么普遍、为什么平时说不出口。
2. **类型是压力容器**：悬疑是真相压力，爱情是亲密压力，职场是尊严压力，科幻是技术与人性压力，不是包装。
3. **传播级故事核**：反常识、强冲突、高代价、容易转述。公式：一个什么样的人，因为什么事件，被迫做出什么选择，付出什么代价。
4. **开场不可逆事件**：人物回不到原来的生活，且不能假装没发生。
5. **欲望分两层**：表层想要（赢、逃走）与深层需要（被爱、被理解）。
6. **真正的两难**：进也痛，退也痛。外部冲突必须对应内部冲突。
7. **人物有缺陷和弧光**：开头和结尾必须变化；没有纯好人或纯坏人。细则见 [人物设计](references/characterDesign.md)。
8. **信息差与代价递进**：观众知道而主角不知道、主角知道而他人不知道、所有人都误解；每一步都让主角失去点什么。
9. **因果紧密**：靠人物选择推动，不靠巧合、突然的救命信息或人物智商下线。反转必须有铺垫。
10. **情绪必须拍得出来**：不用「他很愤怒」交代情绪，把情绪词删掉后导演仍能拍出来。用动作、物件、反话、沉默、环境细节。
11. **前三句出现异常**：开头不写背景介绍，先出现一个具体的异常。
12. **结尾有回响**：不给答案，留一个与现实伤口有关、难判断的问题。
13. **台词有潜台词**：不直接喊主题，不用台词解释剧情。
14. **转发被设计**：能写出一条自然的转发语（替我说话、身份认领、送给某个人、站队表态至少一种），写不出来说明没有传播基因。

名场面、情绪曲线、结构模板见 [名场面](references/iconicScenes.md)、[情绪曲线](references/emotionCurves.md)、[结构模板](references/structureTemplates.md)。

## 面向拍摄的约束

先估体量，再用下表定数量；同时为当前可用的画面模型留余地。

| 体量 | 人物立场 | 代价递进 | 悬念 | 反转 |
|---|---|---|---|---|
| 微型（1 分钟以内） | 主角 + 阻力，可合并 | 2 级 | 1 个 | 结尾一击 |
| 短篇（3–5 分钟） | 2–3 个核心 | 3 级 | 2–3 个 | 小 1 + 大 1 |
| 中篇（单集） | 3–4 个核心 | 4 级 | 4 个 | 小 2 + 中 1 + 大 1 |
| 长篇及以上 | 完整五类立场 | 5 级 | 章节末留钩 | 分层递进；先总纲、分卷、按章写，不一次写完 |

- 人物与场景数量服从体量：1 分钟不超过 3 个角色、2 个场景；3 分钟不超过 5 个角色、4 个场景。再多必须有叙事理由。
- 一个角色要贯穿全片时，设定要能被一套稳定的外形描述固定（年龄、体型、发型、标志性服装/物件），避免依赖难以复现的细节。
- 不写依赖模型难以稳定生成的内容：大场面群像、需要精确文字或口型的特写、长段连续复杂动作。必须有时，在场次表里标注「高风险」并说明原因。
- 时长估算写出依据（对白量、动作长度），不拿模型支持的时长当作剧情容得下的证明。

## 交付格式

剧本正文按场次书写：场号、空间与时段、出场人物；其后是可见的行动、对白、必要的声音与画内文字。每场必须有目标、阻碍、交锋、变化；一场戏结束后若人物关系、信息、情绪都没变，删除或重写。

正文之后，**同一次生成**附上场次表 SceneList，用 JSON，字段固定：

```json
{
  "schemaVersion": 1,
  "title": "",
  "volume": "micro|short|medium|long",
  "scenes": [
    {
      "sceneId": "s01",
      "order": 1,
      "location": "",
      "timeOfDay": "",
      "characters": [],
      "props": [],
      "wardrobe": [],
      "emotionBeat": "",
      "narrativeFunction": "",
      "durationHint": "",
      "risk": ""
    }
  ]
}
```

规则：`characters`、`props`、`wardrobe` 只列该场实际出现并影响画面的内容；`narrativeFunction` 写这场让观众获得什么（建立、揭示、反应、对比、过渡）；场次表必须与正文逐场对应，不在事后从正文反推。

保存：账号模式下按 [workflow](../workflow/SKILL.md) 的画布执行规则，把故事核、大纲、剧本、场次表分别放入文本节点；仅文字阶段、用户只要对话文字时直接回复，不操作画布。没有对应工具时说明实际只能交付文本，不假称已保存。

## 自检（内部执行，不向用户展示分数）

交付前逐项过一遍，任一为否就重写：

- 一句话能否复述这个故事？结尾后读者会不会愣一秒？
- 主角想要什么、得不到失去什么，是否在前三分之一内看得清？
- 有没有真正的两难，而不是表面困难？
- 删掉所有情绪词后，场面还能拍出情绪吗？
- 转发语能预演出来吗？
- 场次表与正文逐场对应吗？人物与场景数量在体量内吗？

出现三项以上硬伤（欲望不清、无两难、靠巧合、台词解释剧情、主题被喊出来、无名场面、结尾无余味、反转无铺垫）不得输出。
