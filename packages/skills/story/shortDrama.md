# 短剧故事创作

从创作想法、已读原作或已采用的上一集接续。先读取项目简报、框架和版本。短剧简报保存 `brief.kind=serial` 与 `brief.serialFormat=short`。将用户明确的计划集数记入 `brief.episodeCount`，单集目标秒数记入 `brief.duration`。总集数可以留空，只展开这次约定的范围。用户给出的集长优先于工作台的初始值。

## 先定观众要追的那件事

用一句话写清谁想争取什么、谁或什么拦住了他，以及观众希望亲眼看到什么结果。开篇尽早让人物遇上必须回应的具体事件。把背景放在观众需要用它理解选择的地方。

从题材、受众要求和人物目标选择主要看点。女频、男频是可选的创作方向，人物性别不决定写法。

- 关系与自主选择可以推动情感、家庭或事业线。给双方各自要守住的东西。让一次可见的决定改变信任、边界或主动权，把这个改变带进下一集。
- 能力与局势变化可以推动成长、职场或冒险线。交代主角手里有什么筹码、用它要付出什么。让对手有机会察觉和应对，让胜负实际改变主角的权限、责任或处境。

## 把主线写成一集接一集的戏

框架先写全剧要解决的问题、关键人物、主要转折与结局。分集大纲按集交代开场承接、眼前目标、对方的应对、人物做出的选择和由此改变的局面。只在用户要求分季时组织季线。

每集给观众一次看得见的兑现。如果集尾留悬念，让悬念从刚发生的结果长出来。例如主角拿回被冒领的署名后，客户当面请她解释方案里的一个漏洞。下一集从她如何回应写起，保留署名已经归还的事实。收官集可以把问题答完。

写反转时，回看揭晓前已经出现的证据，分清当时谁知道它、谁误解它。写完一集再核对，若删掉这一集，下一集开头的人物关系、知情和选择是否仍然完全相同？若相同，就给本集一个真正影响后续的结果，或合并重复的戏。按对白和行动估算单集容量，优先保住关键选择和反应。

## 从故事交给制作

新故事先保存 `framework`，用 `requestStoryDecision(confirmFramework)` 让用户选择代表场次、分集大纲或完整正文。前两项保存为 `expansion`，完整剧本保存为 `draft`。续写和局改沿用已确认的范围与事实。

剧本采用与剧情片相同的[改编与对白要求](references/script.md)和[分场要求](references/scenes.md)。每场保留稳定的 `sceneId` 和所属 `episodeNumber`，用 `canon` 与 `threads` 记住人物知情、关系、持物和线索的埋设与兑现。

交稿和审稿时，只读各集的场次正文，逐个核对已确认框架里的关键揭示。观众在哪个动作或哪句对白里第一次得知答案？能指到这处证据，才在 `threads` 标记已兑现。涉及相似物件时，要能看出人物指的是哪一件；沿动作检查它从谁手里到哪里，尤其核对集尾和下集开场。

采用后由 `saveSceneList` 按 `kind=story` 整理同一版正文，`saveBreakdown` 提取角色、场景、服装和道具。按集建立 `kind=serial` 的制作序列，分镜引用该集的来源场次，跨集复用已采用的资产、影调和声音。画幅与画面风格依项目设定，摄影、表演和连续性沿用剧情片的制作标准。
