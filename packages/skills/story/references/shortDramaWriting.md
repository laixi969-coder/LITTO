# 短剧与连载编剧

本资料是 story 的按需专项，适用于短剧分集、连载节奏或用户明确要求借用的方法。由主 Agent 主动读取并组织工作，不要求用户执行 /start、/plan 或 /episode。方法依据和许可见[来源说明](shortDramaLicense.md)。

## 先定作品，再定方法

沿用当前故事项目、已采用方向与创作范围。只补足会改变当前写作的未知项：面向谁、单集时长、计划集数、观看渠道、语气、结尾与制作限制。题材可以组合，不限制为固定题材表，也不根据性别推断观众喜好。已给信息不重复询问；用户只要一集、局部修改或方案时，只完成该范围。

电影方法可帮助人物动机与高潮积累，剧集方法可帮助多线和整季结构，短剧方法可帮助紧凑推进。选择一个主要组织方式，其他方法用于明确的问题；宁静开场、留白、无反派、单元故事、平弧人物、开放或封闭结尾都可以成立。英文输出不自动等于好莱坞结构，海外创作还应按用户指定文化背景调整关系与表达。

## 从全剧到单集

1. 全剧方向：说明核心人物追求什么、什么持续阻碍他、观众期待什么，以及最终如何回应这个期待。已有原稿与定稿直接沿用，不重建故事。
2. 人物与关系：把欲望、手段、认知与关系变化关联到可见行为。对手可以是人物、环境、制度或内心矛盾；仅故事需要时区分不同层级对手，不默认四层反派或临终再添隐藏反派。
3. 分集规划：用简洁条目记录集次、本集目标、关键行动、局面或关系变化、未决问题和下一集如何承接。区分本集能完成的目标与整季尚未解决的问题；支线服务当前作品，不为凑多线强加角色。
4. 单集正文：沿用 story 的逐场格式，写人物行动、台词、必要的声音及信息变化。时长由对白、动作和情绪停留估算，不按最低字数、固定场数、固定景别数量填充。
5. 接续下一集前：读取已采用前集末态、人物知情、物件去向与未兑现线索。本集先对前集承诺作有意义的回应，再展开新的变化；不重复上一集高潮、复位关系或假装悬念从未发生。

若总集数未定，可以先提出适合当前时长与故事规模的方案；不默认写成 50–100 集。用户已授权的阶段主动完成，真正改变方向的选择沿用 story 的决定卡片，不额外逐级确认。

## 入戏、节奏与集尾

开场先让观众有进入作品的理由：有目的的行动、关系张力、信息疑问、氛围或情感都可以。快节奏短剧可以压缩无关背景；慢节奏作品保留有作用的观察和停留，不把“前 5 秒必须异常”当硬门槛。

节奏看实际变化和理解负担：同一争执重复多场却不改变关系、信息或代价时，考虑合并或改写；持续高强度导致人物反应缺失时，应留出接收与选择的时间。全剧按其因果组织，不套固定百分比或反转次数。

集尾可按问题选择以下方法，不强制每集使用，也不叠满：

| 方法 | 使用目的 | 核对依据 |
| --- | --- | --- |
| 悬念 | 让尚未回答的问题继续推动观看 | 问题与人物目标相关，后续有回应路径 |
| 反转 | 新证据改变对已有事件的理解 | 前文有依据，不靠改写已知事实或突然降智 |
| 情绪 | 关系选择留下后果与期待 | 下一集接住情绪，不用反复误会拖延 |
| 信息 | 新线索改变人物能采取的行动 | 交代谁知道什么，以及信息从何而来 |
| 危机 | 新障碍迫使人物行动或取舍 | 起因、代价与应对接得上，不凭空加险 |

一集可以完成局部收束而保留长线期待，也可以完整结束。优先兑现已建立的期待；不以突然掐断台词或反复不揭晓同一个答案代替推进。不宣称某种钩子保证留存、爆款或转化。

付费卡点仅在用户明确采用付费分集发行时设计，服从真实平台方案与故事承诺；免费、品牌、电影、MV 不自动加入。未取得渠道要求时不编造固定卡点比例或审核结论。

## 在现有故事工作台保存

先 readStoryProject，再依照本轮工具 schema 更新；没有工具时交付可读文本并说明未保存。复用当前项目和版本，不创建第二套 .drama-state.json 或另一个故事状态系统。

- 连载可使用已有 brief.kind=serial；集数、单集范围、主方法与约束写入 brief.constraints，当前制作范围的时长使用 brief.duration，不虚构 totalEpisodes 等顶层字段。
- 方向阶段使用已有 directions；有实际逐场正文后才保存 draft。分集规划写在 draft.outline，场次 title 标明所属集次；正文仍使用稳定且在当前版本中唯一的 sceneId，跨集不重新从 s01 编号。
- draft.canon 保存已确立事实及来源场次；draft.threads 保存线索的埋设、兑现和状态。causes、setupSceneId、payoffSceneId 只能引用当前版本有效场次，不能用“第几集”冒充场次 ID。
- 当前故事版本最多 100 场，outline 最多 12000 字符。大体量连载先明确当前可制作范围，保留完整计划于通过现有文件工具保存的文档，并作为来源读取；已采用前集的事实要注明真实文档与版本出处。不能把跨文档来源伪装为当前 sceneId，也不能静默截断、创建占位场次或声称全集已结构化入库。
- 局部改写生成新版本，列明受影响的前后集与伏笔；不改未授权场次。用户采用后沿用 saveSceneList 与 breakdown / cinema 制作，已生成素材按依赖复用。

## 审读和交付

审稿覆盖实际读过的集与场，区分明确矛盾、理解风险和审美建议，给出原文、依据和最小改法。检查人物行动动机、跨集时间与知识、线索承诺与兑现、对白可表演性、估时和制作条件；不因为没有反转、没有反派或未按模板分幕就判不合格。

用户要求面向某地或某平台发布时，另核对当时适用的官方要求；上游合规清单只提供检查思路，不作为现行规则或审批通过证明。未做实测时，不把自评得分称为观众反馈。

给用户展示可读大纲或正文、当前版本、实际完成范围与待决定项。内部保存由 Agent 调用现有工具完成；保持 story 的既有采用与版本规则，不要求用户理解技能名或命令。
