# 音乐影像

默认创作有故事演绎的 MV：让观众从第一个有意义的画面就关心“发生了什么、接下来会怎样”，通过人物行动推进，而不是把漂亮镜头串成配乐相册。音乐决定情绪与节奏，故事提供持续观看的理由。用户明确要求纯演唱、歌词视频、情绪拼贴或抽象实验时，沿用该范围，不强塞剧情。

完整制作按音乐理解 → [story](../story/SKILL.md) 故事开发与审读 → 音乐与事件编排 → 场次表 → [breakdown](../breakdown/SKILL.md) 资产 → [cinema](../cinema/SKILL.md) 镜头与执行推进。开始或继续时先 `readStoryProject`，沿用已选方向、采用版本和资料，不另开一套 MV 故事记忆。故事工作台的资料确认、选方向与采用沿用现有人工操作，其他必要选择用可用的 `askUser`；已有决定不重复询问。

只要完整提示词或单段方案时，在本轮直接完成可复制交付，不强制走资产生成与成片审批。参考图可以作为创作起点；先实际查看，再提取人物、关系和可发生的故事，身份与前史的推断标为提案。用户没有歌曲且明确委托原创音乐时，可以设计音乐与歌词；这只是待生成方案，不能称为已分析音频。

## 先说清能做到什么

MV 入口可提供 `musicAnalysis.txt`（`kind: littoMusicAnalysis`）和 `musicLyrics.txt`。先核对报告的歌曲名称、SHA-256 与本次歌曲是否一致，读取分析、歌词和卡点计划：

- `analysis` 来自本地 Basic Pitch 音符识别和 Beatroot 节拍检测。旋律是混音中最强音符候选，不等于分离主唱，也不等于识别曲名；BPM 与节拍是算法估计。
- `cutPlan` 含帧率、偏移、剪点秒数与帧号。`reviewed: true` 表示用户声明已试听校准，否则标注“自动识别待复核”。帧对齐不意味着识别误差为零，不自行以匀速网格替代逐点结果。
- 歌词报告保留原歌词、转写 `segments` / `words` 与可编辑 `cues`。逐句内容优先使用用户时间码或校正后的 cues；逐词时间戳属于原始转写，不能冒充校正文本的强制对齐结果。
- 场次与镜头的音乐区间使用真实秒数，并引用选定剪点的帧号。缺少节拍时可按歌词时间码设计，不编造节拍。音乐情绪仍属于创作解读。

没有报告时，仅能依据用户给的歌词文本、用户自述的结构与情绪、`ffprobe` 读到的时长及 `ffmpeg` 基础处理。因此：

- 结构（主歌、副歌、桥段）、BPM 与能量走向，来自用户提供的信息或歌词的重复与分段推断，一律标「推断」，不声称已分析音频。
- 歌词没有时间码时，只按段落给出大致比例，不编造逐句时间；用户提供 LRC 或 SRT 时才使用其时间。
- 听不到音频的事实要明说，并请用户补一句：歌曲整体的情绪与最想要的画面感觉。

## 1. 理解音乐

只补问缺失且影响方向的信息，一次问完，最多 4 项：歌曲或歌词、时长、希望的感觉、是否有必须出现的人物或产品。已有信息不重复问。

交付一份简短的音乐理解：

- 段落表：段落名、大致时长占比、情绪与能量（标注来源：用户给定 / 推断）。
- 歌词解读：字面意思、潜台词、隐喻与反复出现的意象、叙述视角、情绪如何推进。禁止机械的「唱到月亮就画月亮」。
- 值得留白的位置：间奏、静默、副歌前的蓄力。

## 2. 故事与开场：先让人想看下去

剧情与混合型在构思方向前读取 [story](../story/SKILL.md) 和[故事开发](../workflow/references/methods/storyDevelopment.md)，用其中的人物目标、惯用策略、行动后果与关键选择发展故事。人物动机薄弱时再读[人物设计](../story/references/characterDesign.md)。这些能力在本 MV 内完成，不要求用户另开故事项目。已有定稿只核对与整理；只做人物资产时直接进入资产制作，纯唱跳或抽象段落不强行补人物冲突。

在构思第一套方向时就核对视觉设定的来源。MP3 的音色、曲风、歌词中的怀念或失落，只支持情绪解读，不能据此认定人物中年、驼背、须茬、疲惫，也不能自动安排老剧场、旧巷、磨损木地板、旧椅或磨白吉他。没有用户原稿、明确要求或已采用参考依据时，场景、服装与道具默认符合时代用途、正常维护、整洁完好；用表演、人物关系、空间构图和光色承载情绪。未指定的年龄、造型、场地属于可修改提案，不能伪装成歌词或音频提供的事实；各候选不能共享一套无依据的做旧设定。明确要求年代感、旧物或年长角色时按其依据保留。

每套剧情方向先回答五件事：观众跟随谁、此人此刻想完成什么、什么阻碍了他、他做了什么选择、选择造成什么变化。短 MV 可只有一次有分量的选择，不用塞满人物与反转。歌词提供情感或主题，不默认每句都是必须照拍的事件。

- **第一幕就建立观看理由**：呈现已经发生的异常、正在进行且结果未明的行动、重要关系中的矛盾，或先给出一个值得追问的结果。默认在最初几秒让问题可辨，不用片名、慢推、风景和人物摆拍拖延进入故事。若空镜本身携带异常或线索，也可成为开场。
- **悬念可读**：观众可以暂时不知道原因，但应知道在关注谁或什么。纯粹随机闪切和信息缺失不等于吸引人，不要求每秒反转。
- **中段有因果**：人物尝试改变处境，尝试带来新信息、代价或关系变化。删除一场后若人物处境和观众理解都不变，优先合并；有意留白和音乐呼吸可保留。
- **音乐推动戏**：蓄力段形成预期，副歌释放行动或揭示，桥段可改变理解；具体落点服从真实歌曲，不机械套四幕等分。反复副歌可以让同一动作或意象获得新含义。
- **高潮回应开头**：完成开头那件事、揭示开头画面的另一层意义，或让人物做出不同选择。开放结尾也要让本轮情绪或行动有所抵达，不用无关奇观替代回收。
- **演唱与剧情有关系**：明确歌者是故事人物、旁观叙述者还是独立表演者；切到演唱段应强化选择、情绪或视角，避免每次副歌都暂停故事。

给用户看的方向至少包含：第一幕具体画面与追问、人物目标与阻碍、中段行动、音乐高潮对应的选择、结尾如何回应开头。用户只给图片时这些是创作提案；用户已有完整故事时保持其事实与结局。

## 3. 从方向写成可演绎的故事，再对应音乐

只做人物资产或三视图时，直接按当前设计需求进入[资产制作](../workflow/references/assets.md)，不要求先选完整 MV 方向或补场次表。现代真人 MV 未指定其他人物质感时，以[精致写真人像](../workflow/references/methods/characterStyling.md#精致写真人像皮肤妆发与搭配)的细腻肤面、完整妆发与当代搭配作为初始提案，在人物出图前落实；用户参考和已选画风优先，不按摇滚等曲风直接套唯一服装。保持既定年龄、肤色与身份，不默认复制参考人物。实际生成和验收沿用资产与画布流程。

通常提供 2 到 3 套故事方向，先讲出第二节的完整行动链，在人物关系、开场问题、视角或结局上拉开，不只换色调。通过 `updateStoryProject(directions)` 保存；用户已选方向、已有定稿或要求直接出完整提示词时，不为凑选项重新提案。视觉仅辅助说明方向，每套简要写清：

- 一句话概念与视觉命题
- 世界与影调、人物或场景策略；含日景与夜景的方案写明各时段的基底、色温与光源，候选方向之间保持昼夜光色有差异，不只给单一暗调选项
- 贯穿的视觉母题与镜头语言
- 与歌词、音乐的关系（贴合、对位、反差）
- 副歌处理：剧情段落推进人物行动、关系或对母题的理解；独立表演段按舞步、造型与尺度发展，不机械重复
- 2 到 3 个关键时刻的画面示例

用户选定或合并后，该方向成为全片的约束。随后完成连贯梗概与逐场可视听正文，再进入制作；不能把概念介绍、情绪曲线或关键画面清单当作完整故事。

用 `updateStoryProject(draft)` 保存同一份底稿：

- `outline` 写清行动如何导致后果、后果怎样迫使下一次选择，以及结尾如何回应开头。短 MV 可以只展开一次互动，不按固定幕数添事件。
- 每场 `text` 写触发、可见动作、反应与结果；`goal/obstacle/change` 写具体目标、阻碍、前后变化，`knowledge` 写人物与观众知情，`causes` 引用真正导致本场的场次。因果依赖不等于成片相邻；混合型切回剧情时接上一相关剧情场，不能把表演场当作虚假原因。纯表演场可不填剧情目标、冲突与因果。
- `canon/threads` 沿用故事工作台的人物事实与线索；未授权的前史仍是提案。优先用行动、物件、空间和反应讲述，不靠歌词、解释字幕或大量新增对白补齐关键因果。`speech` 只放另需朗读的对白或旁白，原曲歌词不重复填入以免另生成配音。
- 在同一场保存 `musicRange/syncMode/lyricLines`，正文说明哪个音乐变化推动哪次行动、揭示或情绪停留。真实时间码已知才写秒数，否则写段落与大致占比并标待对齐；歌词只引用原文。歌曲的重复不意味着剧情复位，不为套主歌、副歌、桥段模板打断已成立的事件链。

给用户看简洁的音乐与事件对应表：歌曲段落｜可见行动｜承接的原因｜结束变化｜音乐如何参与。表格是故事底稿的阅读视图，不另存一套剧情；必要的空镜、停留与独立表演写真实功能，不为填列编造冲突。

用 `updateStoryProject(review)` 审读指定版本：遮住解释文案后能否看懂人物在做什么；调换关键场次是否破坏因果；结尾是否回应起点；重复副歌是否有发展；音乐区间能否容纳行动与反应。每个问题引用该版正文并给最小改法，先修理解与推进问题，再谈画面美感。审读覆盖与用户采用复用工作台，不新设评分或额外审批。只要提示词或本轮没有工作台工具时，在交付中完成同样的故事与音乐编排，明确尚未保存，不强制完整制作流程。

## 4. 段落场次表

故事采用后，按 [story](../story/SKILL.md) 的场次表规则用 `saveSceneList` 保存，**不在回复里写 JSON**。`storyRevisionId` 引用已采用版本，`kind` 填 `musicFilm`，保留该版的 `sceneId` 和顺序。逐场沿用底稿的 `musicRange/syncMode/lyricLines`；旧稿没有这些字段时据真实资料补充，不编时间码。不能从影像概念直接跳到场次表，不能只用“孤独、回忆、释怀”代替剧情。

- 镜头长度服从音乐与表演，不默认固定 5 秒切镜；可故意不同步，不把卡点率当唯一标准。
- 人物与场景数量要克制，复用同一批资产；长歌曲按段落拆成多个场次，不依赖单个模型一次生成整片。
- 高风险内容（需要口型对齐的近景演唱、精确文字）标注在 `risk`。

## 5. 镜头编排与完整提示词

先 `readSceneList`，核对 `needsUpdate`；过期时先从当前采用故事重整场次。读取返回的 `storyContext`（梗概、人物事实与伏笔）和每场 `story`（正文、目标、阻碍、变化、知情与因果），再结合音乐字段拆镜；这些是只读关联内容，不传回 `saveSceneList`。未返回时用 `readStoryProject` 读取对应采用版；没有故事正文不能把制作摘要冒充故事。把本场起点、触发、行动和结束变化落实到 `action/performance/musicVideo.timeline`，在编译预览核对，不能只填情绪或摄影词。

人物妆发、服装和造型变化按[妆造设计](../workflow/references/methods/characterStyling.md)区分类型：剧情段落服务人物行动与选择；唱跳、舞台或时尚表演段落可主动设计多套妆发服饰，随歌曲段落、舞步和剪点切换，不要求换装剧情或穿衣过程。身份保持稳定，造型只在其指定段落内保持一致。混合型 MV 的叙事线与表演线分别绑定正确状态，回到剧情时接回该时空的妆造；表演保持[目标、触发与反应](../cinema/references/performanceDirection.md)，唱跳也可用舞蹈和音乐任务表达，不强加虚构人物冲突。

进入短 MV、剧情演唱、多图编排、音画切点或生成反馈修订时，读取 [MV 导演编排](references/musicVideoDirection.md)。它负责把故事、表演与音乐写成同一个可执行时间轴；摄影与资产继续复用 cinema 和 continuity，不重复建立另一套制作系统。

选择 Seedance 2.5 时，将完整内容编入 workflow 的 A9.2 字段，交付本段全部参考、时间块、视听方向与约束，不只交付零散建议。实际制作须先保存 `musicVideo` 规格并检查编译预览；自由 prompt 会被服务端编译结果替换，不能只在聊天中保存音画方案。其他模型保留同一创作意图，按真实能力编译。

## 6. 交接

场次表确认后交给 [breakdown](../breakdown/SKILL.md)：它提取角色、场景、道具与世界、影调草案，用户确认后进入 [cinema](../cinema/SKILL.md) 的镜头规划。音乐卡点计划可以从分析报告读取，整曲视频组装仍须使用实际可用的剪辑与渲染工具；未执行或未验收时，不声称已生成或已精准同步成片。

场次表由 `saveSceneList` 写入工作区；音乐理解、影像方向按 [workflow](../workflow/SKILL.md) 的画布执行规则放入文本节点。用户只要对话文字或本轮没有对应工具时，直接回复并说明未保存，不改为手写 JSON。

## 镜头方法接入

涉及镜头选择、产品展示、音乐运镜、预演或运镜验收时，按需读取 [镜头方法卡](../cinema/references/masterShots.md)。将方法落到 ShotSpec.camera.design 与现有摄影、表演字段；不以大师姓名替代规格。
