# 生成段划分与节点规划

剪辑镜头是一项观看设计，生成段是一次真实模型请求，两者不必一一对应。先保留已确认的镜号、动作、对白与结局，再按现场能力决定合并或拆分。

## 1. 合段依据

同一场景与连续状态、参考可同时容纳、动作及对白可执行，且模型实际支持所需内部切镜时，默认优先把完整剧情段落合成一段。只因分镜表有多行不必多次生成；只因总秒数低于上限也不能强制一个节点。不能沿用4秒、6秒短档作为默认生成单元；短段须有换场、独立修复风险、输入限制或完整段落本来很短等实际依据。

例如10秒五镜可以是一段，也可能因多角色参考、对白或动作负担需要分段；依据是实际请求能力与当前设计。用户明确要求一次生成或一镜到底时，分别核对其含义与能力，不静默换成另一种交付。

## 2. 拆分依据

总时长超限、参考容量不足、声音窗口不足、动作/调度难以完整执行、模型不支持所需内部切镜或用户明确指定时，选择完整因果、可接续的边界。先去重复文字与无关装饰，不删除关键动作来迁就模板。

场景切换、回忆、年龄/衣装变化或重要物件状态变化可作为候选边界；并非每次变化都必须独立请求。普通动作允许连续，多人反应允许并行，不按每秒一个动作或固定镜数拆分。

## 3. 模型与时间

沿用用户已选模型；未指定时用 listMediaModels/getConfig 或 productionSpec(planGeneration) 的实际可用模型、支持时长、参考模式与声音能力决定，不硬编码版本秒数或静默选最高规格。

区分计划时长、实际请求时长、媒体实测时长、剪入区间。后配音先按实测声音规划；MV保留 sourceStart 与原曲区间。每段唯一执行时间线从0开始并覆盖实际请求时长，保留源镜号；余量应有用途，不用定格、变速、重复画面伪造完成。

正式写入制作规格前用 productionSpec(planGeneration) 输入 requests:[{kind:"video",count:1,quality,mode,referenceCount,shots:[{editId,paragraphId,sceneId,duration,description,transition,canSplitAfter,splitBefore?,isolateReason?}]}]。count 是每段候选数量，默认方案用1；需要比较候选才增加。内部切镜状态只读服务端 multiShotCapabilities，按供应商、精确模型版本和模式匹配，含资料来源与核验日期。不能提交 multiShotEvidence 或自填 supported。unknown 保留合段草案，按 nextAction=research 用 webFetch/webSearch 先读 research.urls 或 query 对应的供应商官方资料，核对实际模式、版本和适配器实现；资料须经代码审阅进入正式能力表才放行。查不到时保持未知，不拆短、不付费探测；unsupported 才按必要切镜拆分。每个 canSplitAfter 只能在完整动作和原句结束处为true，跨镜对白中间为false。规划器按顺序优先合并同段落镜头，超限退回安全边界；ready=false时先解决缺项，不提交不完整方案。

每个返回的 segment 对应一个制作 shot 和一次生成请求，timeline 保存各剪辑镜头的 editId，不再为内部每镜重复创建生成任务。将其时间线写入 camera.design.timeline（MV用musicVideo.timeline），多镜模式为multiShot；设置 duration 与 generationDuration，并为 handles 补写有用的可剪余量使时间线覆盖生成时长。既有已采用规格和素材不自动合并重做。

提示词共同身份、场景、光线和参考只写一次；各时间窗保留源镜号、景别、动作、原句说话人、连续运镜或切镜，明确整段起终状态。不能简单拼接数条互相矛盾的单镜提示词。生成后根据真实切点选择素材入出点，计划时间码仅作检查依据。

## 4. 接续与参考

每段只绑定本次有效资产，回读当前引用顺序、用途与发送状态，不沿用全片图号。首尾帧只有实际支持且传入时才成立；普通参考不等于首帧，前镜不自动传给后镜。

连续段从已采用视频的真实末态或明确接戏帧开始，保存身份、当前衣装、持物、位置、未完动作与声音依据。共同端点仅约束部分外观，不保证中间动作、接点速度或口型；首尾帧接续如实称分段连续效果。

已有关键帧不足以表达必要动作部位时优先用有效裁切/补充参考或调整镜头方案，不为每次近景强制全身首帧。服装与鞋履保持见 [服装连续性](wardrobeContinuity.md)。

## 5. 输出与核验

生成前给出“生成段｜源镜号｜生成时长/拟用区间｜实际资产｜起终状态与依赖｜拆分依据”，分别汇报剪辑镜头数、生成段数与包含候选数的调用次数。无依赖段可按授权批次生成，有前镜实际状态依赖的等待对应采用结果。

独立段使用完整五板块；正式镜头仍由 productionSpec 的现有规格编译，不另建竞争时间线。改变分段后检查原句覆盖、动作完整性、图号与接点；结构通过不代表动态或声画通过。

## 原创例与反例的使用

适用与输入：模型容量不足或需要接续；输入实际能力、完整事件、声音时长和前镜采用末态。

写法示例：前段结束时乙持杯，后段从乙持杯开始；需要转为甲持杯时先设计交还事件。

反例：为了凑固定秒数把接稳与松手截断，或直接恢复初始持杯者。

约束与例外：本例只说明组织方法，人物、时长、数量与媒介须换成当前项目；不自动加入案例剧情。已有有效方案直接复用。

验收与修复：检查完整动作与接点；调整分段或实际剪点，不用循环/定格延长冒充新动作。 本例未实际生成，不作为效果证据。
