# 制作流程（固定顺序）

资产先行不是建议，是硬顺序。跳过资产直接出片，代价是每一镜重新选角、重新搭景——实测会走到第五段时裤子消失、鞋子不见。

## 七步与门口的判据

| 步 | 做什么 | 产物 | 门口的判据 |
|---|---|---|---|
| 1 剧本 | 故事 → 定稿剧本或场次表 | 故事项目 / `assets/assetPlan.json` 的来源 | 有可拆的正文 |
| 2 资产清单 | `POST /api/ai/media/assets` | `assets/assetPlan.json`（角色/场景/道具） | 清单非空 |
| 3 角色卡 | `POST /api/ai/media/assetSheet`（kind=character） | `assets/cast/<角色>.json`，`references[]` 非空 | 清单里每个角色都有可用卡 |
| 4 场景与道具 | `POST /api/ai/media/assetSheet`（kind=scene/prop） | `assets/scenes/`、`assets/props/` | 清单里每个场景都有一张定场图 |
| 5 分镜与提示词 | 按五板块写，调用 preflight 检查 prompt 与 duration | `assets/shotList.json` 或 `分镜.md` + 段提示词 | 五板块齐、时间码连续 |
| 6 分段生成 | 按生成段提交，段间优先末帧续接 | `assets/generated/*.mp4` | 每段都有文件 |
| 7 成片 | concat 不重编码 + 统一 loudnorm/影调 | 项目根目录 `.mp4` | 时长与分镜总和一致 |

进度随时可查：`GET /api/ai/media/flow?directory=<绝对路径>`，返回七步的 `done`、`detail`、`next` 与 `missing`。**动手前先看一次，做完一步再看一次**，不要凭印象说"资产已经齐了"。

## 肤质两条路径

统一成一条会两头不讨好：定妆图油了不能当长期基准，vlog 里全哑光又像塑料。所以按用途分：

| 路径 | 适用 | 表现 |
|---|---|---|
| `clean`（默认） | 四视图、定妆、广告、商业镜头、剧情正戏 | 干净半哑光，受光处只有极淡高光，不出现成片油亮与反光斑 |
| `natural` | vlog、自拍、纪实、日常跟拍 | 允许极少量自然皮脂反光：鼻头与额头很薄一层、颧骨细小高光，是活人质感不是油亮 |

**怎么切**：项目根写 `assets/visual.json`：

```json
{ "skinFinish": "natural" }
```

规则：
- `purpose: "asset"`（四视图、定妆、道具图）**永远 clean**，不受项目配置影响——资产是长期参考，必须干净。
- 请求里可临时覆盖（`skinFinish: "natural"`），用于单镜试拍。
- 什么都不写就是 clean。

普通请求补缺省肤质；完整五板块在【画面质感与光影】中明确肤面与光线，不再追加通用基底。按 cleanPortrait.md 写细微纹理、克制高光与轻薄妆面，不自动添加黑眼圈、干皮或粗大毛孔。HTTP 的 skinFinish 是普通请求的缺省选项，其他工具在正文写清肤面处理。

## 三类作品共用一套流程

广告、MV、剧情的七步完全相同，差别只在资产与验收：

| 类型 | 多出来的一关 | 判据 |
|---|---|---|
| 剧情/短剧 | 无（沿用角色与场景） | 角色卡 + 场景定场 |
| 商业广告 | `product`：产品与品牌资产 | `assets/products/` 有真实产品参考，不靠文字描述 |
| MV | `music`：原曲与演唱规划 | `assets/` 下有原曲音频，乐句与演唱对齐实际音频 |

`GET /api/ai/media/flow?directory=...&kind=ad|music|drama` 会按类型返回对应阶段；不传 `kind` 时读 `assets/brief.json` 的 `kind`，再退到剧情。

## 已有角色直接导入，不要再生成一遍

用户手上有角色图时，走 `POST /api/ai/media/assetImport`：不调模型、不消耗额度，只登记。

```json
{
  "directory": "项目绝对路径",
  "kind": "character",
  "name": "林夏",
  "description": "26 岁女性，齐肩黑发",
  "wardrobe": "米白衬衫、浅蓝直筒牛仔裤、草编帽",
  "images": ["assets/ref-fullbody.png", "assets/ref-face.png"]
}
```

登记后与生成的角色卡完全同构，**后续分镜图与视频用 `cast: ["林夏"]` 就能引用**，不需要重新出图。

三条注意：

- **只给一张图也能用**，但全身动作（蹲下、起身、走远）会缺下半身依据，接口会明确提示补一张完整全身（含鞋）。
- 要补侧面/背面，用 `assetSheet` 并把 `reference` 指向这张已有图——只补缺的角度，不重做整张。
- 场景与道具同样可导入（`kind=scene|prop`），会复制进 `assets/scenes`、`assets/props` 让 flow 数得到。

## 两个接口的实际行为

- `assetSheet` 同步等待模型返回，一张图通常 1–4 分钟。调用方超时要设长（≥5 分钟），不要因为超时就重发——会重复扣费。
- 只有图生图模型（如 `gpt-image-2/edit`）时必须给 `reference`，否则接口直接报错让你补参考图，不会硬生成。有文生图模型时 `reference` 可省。

## 默认四视图与有效信息

接口与 workflow 的资产模板共用以下默认意图；用户指定版式优先，实际身份、视角和结构仍须看输出：

```text
左侧：独立正脸妆造特写
右侧：正面0° / 右侧90° / 背面180°完整全身，等高且头脚完整
画幅与精度：实际请求支持的参数，不以提示词保证4K
背景与用光：简洁背景，中性展示光，服从已确认画风
一致性：四张同一个人的同一天；脸型、发型、体型、服装、鞋履完全一致
负面：不要拼贴边框、不要图注文字、不要第五个人、不要把某张改成半身或坐姿
```

## 资产门禁

拆过 `assetPlan.json` 且清单里有角色，但角色卡没建齐，提交视频会被拒绝：

```
资产清单里有 N 个角色，还缺 X、Y 的角色卡……
```

确实要先试拍，在提示词里写 `ASSETGATE: 理由` 可跳过。没拆清单的项目不受此限——快速试片仍然允许。

## 常见跳步与后果

| 跳步 | 后果 |
|---|---|
| 不拆清单直接写分镜 | 每镜自己发明角色与空间，同一场戏出现两个人 |
| 有清单不建角色卡 | 视频里脸每段都变；服装靠猜 |
| 不建场景定场图 | 每镜重新描述空间，光向和地形不一致 |
| 角色卡只有一张定妆照 | 全身动作时模型自己补下半身，裤子与鞋会消失 |
| 先生成再补资产 | 已生成的片段全部作废，重做成本最高 |
