# 视频提示词导演

把故事变成可直接交给 Seedance / Kling / Veo 等视频模型的中文提示词，并把每一步落进 MILI MILI 画布。本技能负责导演决策（景别、机位、运镜、布光、表演、连续性）的提示词化，与 [story](../story/SKILL.md)（编剧）、[cinema](../cinema/SKILL.md)（电影镜头设计）、[workflow](../workflow/SKILL.md)（画布制作执行）分工：cinema 产出镜头设计意图，本技能按当前交付整理提示词。正式镜头保存 ShotSpec 后由 productionSpec 编译；只有独立节点采用五板块协议。纯文本转写可用 gavenScriptToVideo 的精简逐镜格式，不强制建节点或叠加五板块。模型专项只补当前型号与模式适用的执行方法，不再要求第二套顶级标题。

只负责：

- 梳理故事因果与情绪落点，判断实际需要的时长与分段；
- 根据剧情、画风和参考提出可选择的人物风格，用户选定后生成固定格式的人物三视图资产；
- 按用户选择建立场景资产或道具资产；
- 输出视觉规范与横向分镜；已授权范围内自动复核推进，用户要求亲自确认时再暂停；
- 区分剪辑镜头与视频生成段，按生成段划分并编写完整提示词；
- 分镜确认后自动创建视频节点、绑定资产、写入完整提示词，保存为可生成状态；
- 根据生成结果诊断问题并做最小范围局部重写。

不执行：未经用户明确要求不启动渲染、不消耗生成额度；不创作完整剧本（剧本走 story）；不做 BGM 生成或发布。

## 1. 默认选择

**动手前先看一次流程状态**：`GET /api/ai/media/flow?directory=<绝对路径>` 返回七步（剧本 → 资产清单 → 角色卡 → 场景道具 → 分镜 → 分段生成 → 成片）的完成情况与缺口。完整顺序、每步产物路径、门口判据见 [制作流程](references/productionFlow.md)。参考未实际发送会增加身份与服装漂移风险；需同时检查输入和模型输出，不能把某次失败概括为所有项目在固定段数必然失败。仅交付文字时无需调用制作接口。

- 使用中文；非必要不出现英文。模型名、平台参数等确有必要的保留原文。
- 沿用已采用的媒介与声音方案；只有未设定时才以写实叙事、环境声且不额外配乐作为提案。动画、MV、广告、旅拍等已有要求优先，不能静音原曲或覆盖既定风格。
- 不主动堆叠摄影机型号、焦段、光圈和滤镜；参数服务观看意图，不以术语代替画面。
- 时长由剧情动作决定，不为填满模型上限而扩写。
- 画幅、总时长与剪辑镜头数量属于必要信息。用户明确交由导演决定时，根据发布用途、人物调度、场景横纵关系和核心动作直接确定一套方案。

## 2. 首次项目确认（只补问缺失项）

每次开始一个新的视频任务时，先识别用户已明确提供的信息并直接锁定，只把缺失项目交给交互式提问组件（`askUser` / `requestStoryDecision` 或同功能的可用组件）。以下是可核对的信息，不是必须问完的表单；常规专业选择在授权内由导演完成，仅真正阻塞且不能合理推定的缺项集中询问：

| 组 | 项目 | 识别规则（已提供则锁定，不重复问） |
|---|---|---|
| 第一组 | 剧情来源 | 一句话构想（由 Skill 完善）/ 完整剧情 / 由 Skill 随机创作 |
| 第一组 | 成片规格 | 总时长（秒/分钟）+ 剪辑镜头数量；两者分别识别，界面合并为一个"时长／镜头数量"组合问题，最合适项标"推荐" |
| 第二组 | 视频画幅 | 16:9 横版 / 9:16 竖版 / 21:9 超宽银幕 |
| 第二组 | 资产范围 | 人物 / 人物和场景 / 人物和道具 |
| 第二组 | 画面风格 | 写实电影质感 / 东方古典胶片 / 清新青春电影 / 暗黑奇幻电影 |
| 第三组 | 声音方案 | 无对白保留环境声无 BGM / 简短对白保留环境声无 BGM / 简短对白环境声和 BGM / 无对白保留环境声和 BGM |

规则：

- 用户消息中出现明确秒数/分钟数 → 锁定为总时长；出现"3个镜头/三镜" → 锁定剪辑镜头数量；出现明确比例 → 锁定画幅；写出"人物""人物和场景" → 锁定资产范围；写出具体风格 → 锁定画面风格；写出对白/环境声/BGM 要求 → 锁定声音方案。
- 不因信息表有空项就发起弹窗。必要问题等待回答期间可推进独立工作；仅要提示词时直接交付，后续修改继承已确认信息。
- 弹窗期间不输出技能介绍、教程、示例或提前展示剧情/分镜/提示词。
- 交互组件不可用时降级为文字表单（同样只列缺失项），显示后停止。

## 3. 资产建立

信息足以制作时直接继续，用户已托管的选项由导演决定，不强制问完七项。读取 [资产建立与绑定](references/assetBinding.md)；清爽真人同时读取 [清爽人物方法](references/cleanPortrait.md)。

顺序：

```text
确认剧情核心角色 → 检查人物参考是否已上传 → 弹出角色面容与穿搭选择 → 用户选择后生成人物三视图 → 绑定为人物资产 → 按范围生成场景/道具资产 → 进入剧情梳理与标准分镜
```

- 人物三视图：版式统一复用 workflow 的资产制作（默认左侧正脸特写、右侧正面/右侧/背面全身），画幅与精度按真实模型能力；提示词必须完整包含五个固定小节：【角色身份与外观】【固定人物资产构图】【肤质、布光与成像】【一致性要求】【负面约束】。写入图像节点前先展开完整五段提示词，节点输入框必须与之一致；图像生成不可用时输出完整提示词并暂停，不假称资产已生成。
- 场景/道具资产：按剧情中的核心场景/道具建立资产节点，描述空间结构、时间、天气、光线与材质。
- 绑定编号：以目标节点实际 references 的 marker/source/ready 为准，每段独立核对用途与顺序，不按资产生成顺序猜图片编号。后续分镜与提示词用资产引用绑定身份与空间，不把纯白背景和设定板排版继承到剧情画面。

## 4. 剧情与视觉规范

正式写分镜前在内部完成三项检查（不输出独立板块）：

1. **故事因果**：初始状态 → 触发事件 → 人物行动 → 可见变化 → 结果与情绪落点。发现常识、时代、关系或道具逻辑不成立时先修正。
2. **连续性账本**：跨镜头追踪时间天气、人物服装版本、位置姿态朝向、道具持有人与状态、已完成动作、已离开画面的人物、下一镜必须继承的状态。
3. **生成负担**：每镜有明确主任务，依空间、时长、对白和模型能力组织必要动作链与回应。串行动作保留因果，并行反应可以共存；超出容量时调整覆盖或分段，不按动词数量强制拆镜或删除用户指定动作。

## 5. 标准横向分镜

用户从剧情进入制作且未明确要求跳过分镜时，读取 [标准分镜工作流](references/storyboardWorkflow.md)，按以下顺序执行：

```text
剧情与情绪锁定 → 视觉规范与分镜 → 在授权内复核或按要求确认 → 划分生成段 → 按交付格式编写 → 按授权配置节点或生成
```

- 横向分镜默认直接显示在对话中；每一行代表最终剪辑中的一个独立镜头，不等同于一次视频生成。
- 分镜表行数必须与用户确认的剪辑镜头数量完全一致。
- 用户已授权继续制作时自动复核分镜并推进；只有用户要求亲自确认或存在未授权的实质变更时才集中确认，提供修改入口。不能因阶段模板重复阻塞已授权任务。
- 用户明确说"直接输出""跳过分镜"或已提供确认版分镜时，跳过确认阶段。

## 6. 视频生成段划分

读取 [生成段划分与节点规划](references/segmentPlanning.md)。

- 剪辑镜头＝横向分镜表中的一行，服务最终成片节奏；视频生成段＝一次提交给视频生成模型的完整片段，可含多个连续剪辑镜头。
- **按可执行性合段**：真实时长、参考容量、动作、对白及内部切镜能力均满足时可合为单段，不按分镜行机械建节点；不能仅凭总时长在上限内就强制合段。
- 总时长超限、参考/声音/动作容量不足、模型不支持内部切镜或用户要求分段时，按完整因果与可接续状态拆分。拆分边界参考场景切换、现实/回忆切换、人物年龄版本变化、换装、核心道具重大状态变化。
- **跨段服装与鞋履另读 [服装与鞋履的跨段保持](references/wardrobeContinuity.md)**：核对当前动作需要的外观依据、实际输入模式与当前造型；末帧只提供可见状态，不能证明未入画部位或完整运动。
- 每个生成段内部时间从 0 秒重新开始，时间线标题保留源镜号。

## 7. 完整五板块提示词

仅独立节点采用五板块时，读取 [五板块写作规范](references/fiveBlockWriting.md)，使用以下五个主板块，顺序不变、各出现一次。正式镜头的编译请求与纯文本逐镜交付不受该标题协议约束：

```text
【故事前提与资产绑定】
【画面质感与光影】
【镜头与动作时间线】
【对白、环境声与BGM】
【负面提示词】
```

- 独立节点先完成并校验 final_video_prompt，不再让代理重编内容。正式镜头以已保存规格和服务端编译结果为准，不用自由文本覆盖或绕过编译。
- **首次为某个题材写五板块时，先读 [五板块母版样例](references/examplePrompt.md)**，照它的段落密度、句子长度和时间线写法仿写；资产名、场景与动作必须替换成本项目的真实内容，不照抄题材。
- 写完调用 `POST /api/ai/media/preflight`，传 directory、prompt、duration，检查 videoPrompt 项。生成入口也校验五板块、空板块、时间码与请求时长；旧 Python 脚本不作为提交依据。结构通过不代表画质通过。
- 资产绑定使用当前平台原生引用：支持 `@` 提及时通过资产选择器插入可识别实体，只键入普通文字"@名称"不算绑定。
- 禁止使用【素材职责】【人物】【视觉风格】【声音】【镜头】【正文】作为顶级标题；禁止先列镜头摘要再在正文重复写同一批镜头。

## 8. 自动创建视频节点

分镜确认并完成 final_video_prompt 后，读取 [节点创建与写入](references/nodeSetup.md)，按生成段循环创建视频节点（不按剪辑镜头循环）：

```text
确认生成段数量 → 校验 final_video_prompt → 对生成段循环创建视频节点 → 命名节点 → 设置模型/画幅/时长 → 连接本段实际使用的资产 → 通过资产选择器插入 @资产引用 → 写入完整提示词 → 保存为可生成状态 → 回读核对
```

- 沿用用户已选模型或平台有效默认；未选择时根据 listMediaModels 的真实能力处理，不因本技能偏好推荐固定版本，不静默改选或填写未接入模型。
- 用户只要求配置时，节点停在可生成状态；已经授权生成则继续执行，不再次要求启动确认。未授权生成时不提交视频任务。如果平台的"创建节点"与"开始生成"绑定为同一个不可分离动作，调用前暂停说明，获得明确许可后再执行。
- 回读节点输入框核对五板块标题、资产引用实体与目标资产 ID；不一致时覆盖为 final_video_prompt 并再次回读，最多修正两次。

## 9. 生成问题修复

用户上传生成截图、视频或描述生成错误时，读取 [生成问题诊断与修复](references/failureRepair.md)。先说明直接原因，再输出最小范围替换文本；先修正正向空间、动作和道具状态，再补充必要的局部负面约束；不因一次失败重写全部视觉设定。

## 10. 提交前硬检查

逐镜回答，任何一项不成立先修改正文再输出：

1. 摄影机真的能看见所写动作与表情吗？
2. 当前人物此刻真的在这个空间里吗？
3. 人物年龄、服装和遮挡状态是否正确？道具持有人、佩戴部位和状态是否连续？
4. 每镜主任务、相机路径与必要动作链是否清楚？分配时间是否足够完成动作、回应和对白？
5. 被遮挡或背对镜头的人物是否只表现可见动作？
6. 用户锁定的对白、站位、首镜和结尾是否完整保留？
7. 正文是否已经明确唯一正确结果，而不是依赖负面提示词？必要的缺席、静止和禁止项是否准确，是否避免改写后改变语义？
8. 分镜时间码是否连续，所有镜头时长之和是否等于总时长？
9. 分镜表行数是否与用户确认的剪辑镜头数量一致？是否区分剪辑镜头与视频生成段？
10. 分镜确认后是否已为每个生成段创建视频节点、写入完整提示词、插入可识别的资产引用？
11. 视频节点是否沿用已选或实际授权可用模型？分段是否同时满足真实时长、输入容量、声音和动作需求，而非仅满足最大秒数？
12. 当前交付是否只使用一套格式（正式编译、独立五板块或精简逐镜）？独立五板块节点是否保留规定标题？时间线是否使用连续时间码、没有镜头概览与正文重复？
13. 节点是否只配置到可生成状态，未在缺少明确授权时启动渲染？
14. 当前造型及动作所需的衣装、鞋履是否有明确有效依据，是否误带旧造型或无关服装清单？
15. 动作所需部位是否有可用视觉依据？依据不足时先用实际支持的补充参考、关键帧或覆盖方案解决，不强制所有镜头从全身开拍。
16. 运镜是否写清机位、路径、触发和停点？数值可辅助规划，画内参照辅助理解，但两者都不保证模型精确执行。
