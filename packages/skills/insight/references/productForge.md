# 产品锻造：从洞察到产品概念与 MVP

产品层回答"把这个洞察做成什么东西"。按需启动：用户要求产品概念、功能或服务设计建议，不因品牌出现而自动启动。

纪律与营销选择层相同：产品是消费者已有动作的延伸，不是给消费者的一堂课；不为证明洞察而造产品。

## 张力 → 产品机会映射

从期望进展、消费阻力与实际取舍出发找产品机会，不从功能清单出发：

| 洞察张力 | 产品机会 |
|---|---|
| 摩擦/麻烦：某一步太麻烦 | 把那一步做掉：自动化、默认化、简化 |
| 尴尬/面子：不能说出口 | 隐私设计、代表达、去标签化包装 |
| 清单焦虑：选择太多做不了决定 | 策展与减法、默认选项、"先做这一件" |
| 关系距离：想说不会说 | 代发送、仪式化触点、提醒机制 |
| 代价回避：想要好处又怕代价 | 把代价做没：份量、保存、便携、可逆设计 |
| 说的做的不同 | 按真实行为而非口头声明设计功能 |

映射是起点不是终点；每个机会仍要回到被观察到的具体场景检验。

## 产品概念卡

- **一句话概念**：什么人、在什么场景、用它完成哪个动作。
- **承接洞察**：引用该条洞察的 `statement`（旧结构用 `title`），保留证据状态。
- **关键行为设计**：产品改变哪个选择或使用环节，为什么可能有效。
- **体验触点**：发现 → 购买 → 首次使用 → 复购，各触点上洞察如何可见。
- **不做什么**：明确砍掉的项，防功能堆叠。

## MVP 最小验证

- **最小可试版本**：能让目标用户完成那个动作的最小形态——功能原型、人工服务、甚至一个预约页都行。
- **验证问题**：目标用户是否实际完成关键行为、持续使用或选择它？动机是否成立另用研究检验。
- **判定标准**：依据业务基线、风险和样本设计事前写清继续/修改/停止条件；无基线时先探索，不凭空给比例门槛。定性访谈不能据此证明总体占比。
- **迭代分支**：通过 → 加深度；不通过 → 区分洞察、实现、价格、招募与渠道问题，再决定修改哪一层。

## 产品层闸门

- 概念源自洞察张力，能指出对应哪一行映射；
- "不做什么"写清楚了；
- 消费者能在 10 秒内说出这产品帮他做了什么；
- 验证判定标准在开发前定义，不是事后找数据；
- 不与洞察的人群与场景边界冲突。

## 反模式

- **产品倒装**：先定了要做什么产品，再找洞察背书。检验：拿掉洞察，产品概念是否照样成立？若照样成立，洞察没有在起作用。
- **功能堆叠**：把营销选择当成功能列表逐条实现。
- **洞察贴纸**：洞察只活在广告里，产品体验里找不到。检验：不看广告，用户能否从产品本身感受到那个洞察。
- **一步到位**：跳过 MVP 直接规划完整产品线与 SKU。
- **为洞察而反常识**：产品难用但"有态度"——态度不能替代可用性。
