# 消费者洞察

在 LITTO 中是广告通道的上游：[adfilm](../adfilm/SKILL.md) 的简报缺少消费者依据、卖点不清或用户要求洞察时调用；产出的洞察（含证据状态）再交回 adfilm 写策略与脚本。不用于剧情故事与 MV。

帮助使用者理解：**什么人在什么情境下，为了实现什么进展，受到什么阻力或取舍影响，因此怎样选择；这让业务应该改变什么。**

默认使用 brief 的语言。保留 Hiccai 对生活细节和表达的敏感，但以解释力、证据和决策价值判断洞察，不以金句、反常识或可拍性代替真实性。

## 先选择工作模式

- **消费者洞察（默认）**：从材料发现行为模式，解释动机和取舍，提出验证与业务行动。
- **洞察审核**：判断是事实、需求、洞察假设、已有证据支持的洞察，还是创意表达；指出缺失环节再修改。
- **研究设计**：没有足够资料时，先给有限的待验证假设与取证方案。阅读 [研究与验证指南](references/researchGuide.md)。
- **创意转译**：已有洞察需要传播表达或用户明确要求“现象洞察、可拍、半步提炼”时，阅读 [创意转译指南](references/creativeTranslation.md)。
- **案例拆解**：分开记录原始研究、作者声称的洞察、执行手段和结果；没有原始研究时，不从成功广告倒推消费者真相或因果关系。

- **营销行动**：用户需要行动建议时，阅读 [营销选择](references/marketingChoices.md)。品牌出现不等于用户要求整套方案。
- **内容与海报**：需要短文案、选题或脚本时，阅读 [共鸣转译](references/resonanceBridge.md)。
- **策略 / 产品**：用户要求定位、竞争策略或产品概念时，分别阅读 [策略桥](references/strategyBridge.md)、[产品验证](references/productForge.md)。
- **实际检索**：用户要求搜索、查证或需要核对当前事实时，阅读 [证据检索](references/evidenceSourcing.md)。无资料的创意探索可先给假设，不为填格式编造研究。

审核、提炼和输出前阅读 [判断标准与示例](references/fieldGuide.md)。按任务读取其他资料，不默认加载所有参考文件。

## 工作流程

### 1. 界定需要改变的决策

从现有材料提取：品类与业务问题、目标行为、消费情境、可用证据、品牌能力和约束。区分购买者、使用者、付款者与影响者，相关时再展开。

优先按情境和行为划分人群，例如“工作日晚间临时订餐、需要替家人做决定的人”，而非直接用“年轻人”推导共同心理。明确本次要理解的是首次购买、比较、放弃、使用、复购、转用还是流失。

缺少关键信息时只问会改变判断的问题；同时完成已有资料的整理。仅有 brief 时可以提出假设，但不能宣称完成了消费者研究。

### 2. 建立可追溯证据

为实际材料编号 E01、E02……，记录出处/定位、日期或未知、原话或行为、情境、样本范围及局限。保留原话，转述须标明。没有材料的假设使用空证据列表，不为其制造证据编号。

严格区分：
- **观察事实**：材料中真实出现了什么。
- **参与者解释**：当事人如何解释自己的行为；不自动等于实际原因。
- **分析推断**：分析者认为可能由什么机制导致。
- **待验证假设**：当前缺少直接支持，需要后续取证。

不虚构访谈、引语、比例、样本量或来源。评论的重复发布不算独立证据；评论者不等于全部消费者。定性材料解释可能的机制，不能直接证明人群占比。公开资料用于补充时标明来源、时效和适用范围；无法访问原文时明确限制。

### 3. 从行为追到任务、阻力和取舍

将相关证据归为行为模式，保留差异与反例。对每个有价值的模式回答：

1. 触发事件和具体情境是什么？此前、当时、之后发生了什么？
2. 消费者想完成的功能任务是什么？有哪些情感或社会目标，证据在哪里？
3. 理想进展受到什么阻力？正在牺牲金钱、时间、控制感、身份、关系或其他什么？
4. 使用了什么替代方案、凑合办法，或者选择不买、不行动？
5. 这些因素如何改变考虑清单、购买、使用、复购或流失？

“想要 A，但 B 使其选择 C”可以帮助定位张力，不必强造矛盾。优先检查预算、可得性、操作成本、习惯等解释，再考虑身份或深层情绪；不默认消费者在掩饰动机，不把面子、焦虑、亲情套到所有行为上。

### 4. 写出可反驳的洞察

用自然语言写清 **情境 + 期望进展 + 动机/阻力或取舍 + 行为后果**。可参考：

> 在［情境］下，［行为人群］希望［进展］，但［阻力/取舍］，因此会［选择或替代行为］；这提示［影响选择的机制］。

这是思考辅助，不是必须填满的文案公式。消费者洞察可以解释“因为”；不要为了标题好听而隐藏策略推理。事实支持到哪里，结论就写到哪里。

每条候选至少考虑一个合理的替代解释，说明适用边界，并提出会让判断失效的观察。没有反例材料时写“尚未收集”，不能写“没有反例”。无需凑出三个结论：保留有证据价值的条目，其余列为假设或淘汰。

### 5. 连接行动与验证

先写消费者需要怎样的改变，再判断品牌是否有能力提供。行动可以是产品、定价、包装、渠道、服务、信息呈现或传播，不必落到 campaign。

为推荐行动写出：作用机制、前提、低成本验证、目标行为指标，以及可能恶化的体验或业务指标。区分两类验证：研究检验动机解释；实验检验行动是否有效。一次转化提升不能单独证明心理动机成立。

没有品牌信息时给品类机会，并注明品牌适配待确认。不能从洞察直接承诺销量、传播或增长。

### 6. 审核与排序

用 field guide 的五个核心标准审核，结果使用“有支持 / 部分支持 / 待验证 / 不通过”，给出理由，不用全为 true 的自评清单。

排序优先考虑证据支持、行为解释力、决策相关性和可验证性，再看表达。信心标为低/中/高并解释依据：资料单一、替代解释未排除或存在冲突时降级；没有直接证据的结论必须标为待验证假设。高信心仅限当前样本与情境，不代表整个人群普遍成立。

## 默认交付

默认使用简洁中文报告，用户要求 JSON 时再输出结构化数据。

先给**决策问题、证据覆盖与局限、最值得推进的结论或假设**。随后按价值给出少量洞察卡，每张包括：

- **洞察陈述**：解释选择机制的一到两句话。
- **人群与情境**：行为边界与消费阶段。
- **证据**：证据编号、真实原话/行为及来源定位；无材料时明确为空。
- **推理**：观察 → 期望进展 → 阻力/取舍 → 选择后果，区分推断。
- **替代解释与边界**：反例、未知和不适用情况。
- **状态与信心**：已有支持的洞察或待验证假设；低/中/高及依据。
- **业务机会**：消费者收益、品牌能力和具体行动。
- **验证计划**：方法、受访/实验对象、支持或推翻判断的观察、行为指标。

证据台账可以全报告共享，避免逐卡重复。JSON 中 `evidence_status` 区分“观察有支持 / 机制部分支持 / 待验证假设”，不用一个“已验证”同时概括事实与因果。JSON 可使用 `decision_question`、`evidence_register`、`insights`，每条含 `statement`、`segment_context`、`evidence_ids`、`reasoning`、`alternative_explanations`、`boundaries`、`status`、`confidence`、`opportunity`、`validation`。保留用户指定结构；若沿用旧版字段，新增这些证据与判断字段，不把创意字段当成洞察合格标准。

审核现有条目时先给结论及关键缺口，证据不足时只提供标注清楚的假设改写。案例拆解可归纳“情境 → 任务与取舍 → 行为机制 → 干预机会”，但迁移到新市场或品牌后需要重新验证。

## 数量、深度与短文案

用户要求“只给洞察”时，仅给编号洞察句，不追加分析、营销动作和验证表；没有直接证据时用一次简短说明“以下为待验证洞察方向”，或在列表标题中标明。短输出仍应保留真实的人、情境及影响选择的取舍，而非卖点改写。

用户要求 N 个方向时，探索 N 个不同的选择机制；按情境、决策角色、消费阶段、期望进展、阻力与替代方案检查重复。只换主语、情绪或措辞，仍可能是同一洞察。材料支持不足时可将其余明确列为假设；实在无不同方向则如实减少，不凑已证实结论。

用户要求“每条约 20 字海报”时，保持编号一一对应，一句保留一个核心矛盾或生活动作；约 20 字默认按 18–24 个正文字符（不计标点）控制，用户另有要求从其要求。不把洞察全部改成“产品让你更美好”的利益口号，不额外输出钩子、转发语、研究表。

产品事实与消费者证据分开：用户提供的“现房、近商圈、全套房”等属于 brief 条件，不证明人们为何买；“唯一在售”等有时间及区域边界的宣称需核实后才能当作对外事实。现房不自动等于立即入住，近轨道不自动等于步行可达，全套房不自动等于等面积或同等舒适。承诺必须对应已知能力。

完成独立推导后，可读 [案例校准库](references/caseLibrary.md) 检查因果跳跃。案例只能校准方法，不能作为新任务证据。
