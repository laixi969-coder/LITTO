# 缺陷与修复

按「先便宜后昂贵」处理。所有会消耗算力的重生成，先向用户说明对象、数量、模型和费用性质并等待同意。下表中的节点函数以 `getNodeTools` 返回的实际清单为准。

| 看到的问题 | 最可能原因 | 最低成本修复 | 画布上怎么做 |
| --- | --- | --- | --- |
| 手、脸局部畸形，其余画面可用 | 生成随机误差 | **局部重做**：以原图作参考，只改问题部位 | 图片生成节点接原图为参考，`node:setPrompt` 只写「仅修改{{ref 1}}中的{部位}，其余保持不变」，再 `node:generateImage` |
| 人物长得不像设定（身份漂移） | 参考权重不足、提示词描述与参考矛盾、模型不支持身份参考 | **加强身份参考**：确认参考板已接入，提示词开头明写「身份以 {{ref N}} 为准，脸型五官体型不变；妆发服饰按本段选定造型」，不将计划换妆换发型当作换脸 | `node:setPrompt` 修改；参考仍无效再换支持多参考的模型（先 `node:getConfig` 看能力） |
| 构图不符合计划 | 提示词里构图描述含糊 | **加构图参考**：用上一镜关键帧、草图或手画布局作构图参考，写明「人物位置、景别、机位高度」 | 接入构图参考图，提示词写用途 |
| 动作不自然、违反物理（悬空、滑步、穿模） | 动作描述缺少起势、重心、接触 | **重写动作并重生成**：补「起势—主动作—收势」，写明脚与地面接触、重心转移、惯性 | 只改 `node:setPrompt` 的动作部分，其余不动；必要时接动作视频参考（模型支持时） |
| 场景结构变了（门窗位置、家具关系） | 场景参考未接入或被覆盖 | **锁定环境参考**：接入无人物的场景主视图，提示词写「环境按 {{ref N}}，布局不变」；换机位时描述该机位应看到的布局 | 补连线并核对引用顺序 |
| 道具/产品变形、logo 糊 | 产品几何没有锁定 | **加产品参考并锁定**：产品正面/侧面图作参考，提示词写「形状、比例、logo 保持 {{ref N}}」；特写镜头单独出图再用于视频 | 产品参考图接入对应节点 |
| 轻微色差、亮度不一致 | 各镜独立生成的随机差 | **后期统一**，不重新生成：交付时统一调色 | 记录需要调色的镜头；若有 ffmpeg 工具，只在用户要求时做简单调色 |
| 某镜头怎么改都不对，且提示词已清楚 | 所选模型缺少该能力（多参考、首尾帧、画幅等） | **换模型或改方案** | `node:getConfig` 看能力，向用户说明差异，同意后 `node:setConfig` |
| 越轴、视线、景别等剪辑类问题 | 计划阶段的错误，不是画面问题 | **改分镜**，不改画面：调整机位侧、补过渡镜头 | 改文本节点中的分镜和对应视频提示词 |
| 服装、持物在镜头间无故不一致 | 状态没有写进提示词或参考不统一 | **先核对适用范围**：唱跳 MV 的计划换装不修成同装；连续剧情或同一造型单元内按状态表重写受影响提示词，必要时补服装参考 | 先核对 `连续性.md` 与造型编排，再改各镜 `node:setPrompt` |

## 修复原则

1. 先判断是「计划错了」还是「画面错了」。计划错了不要靠重生成碰运气。
2. 一次只改一个原因，改完说明改了什么，方便用户判断是否有效。
3. 同类问题试过一次修复仍复现：停下，向用户解释原因和可选方案（换参考、换模型、接受并后期处理）。
4. 修复产出新版本而不是覆盖旧版本（见 SKILL.md 第 7 节），让用户能退回。
5. 没有实际看过画面，不说「已修复」，只说「已调整设置，等你确认画面」。
