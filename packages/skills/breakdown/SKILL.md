# 剧本拆解

拆解是创作与制作之间的枢纽：把已确认的剧本变成一份**待确认清单**，用户确认后才进入资产库。资产与世界设定从剧本推出来，用户只确认、合并或删除，不从空白表单开始。

## 输入与边界

- 输入：已确认的剧本与场次表。先用 `readSceneList` 读取当前场次表，记下其中的实体 id 和 `version`。只有剧本没有场次表时，先按 [story](../story/SKILL.md) 的规则用 `saveSceneList` 整理并保存，再拆解；用户提供的定稿剧本不改写。
- 未确认的故事、大纲不拆解；先回到 story 阶段。
- 不规划镜头，不生成图片或视频。镜头规格由 [cinema](../cinema/SKILL.md) 的导演流程在资产确认后产生。

## 步骤

### 1. 逐场提取

以场次表的实体为单位逐项整理（人物、场景、道具、服装各有 id），只记录**会进入画面且影响一致性**的内容：

| 类型 | 记录 |
|---|---|
| Character | 名字、年龄段、体型、发型、气质；出现的场次；跨场不得改变的特征；剧情导致的变化（受伤、换装、变老） |
| Wardrobe | 属于谁、哪些场次穿、款式面料颜色；剧情触发的变化 |
| Environment | 空间类型、固定陈设与出入口、光源（窗、台灯）、时段与天气；出现场次 |
| Prop / Product | 形状尺寸材质、持有人、起止状态（完好 / 破损、开 / 关）；出现场次 |
| Vehicle / Creature | 同上，按实际出现 |

资产一律按实体 id 对应，不按名称匹配。场次表里同一个人或物被登记成了两个 id，先用 `saveSceneList` 修正场次表，再重新读取拆解，不在拆解里私下合并。同一场景的不同时段、同一物件的状态变化写进该资产的 `stateChanges`，不拆成两项资产。仅一闪而过、不影响叙事的实体放进 `skipped` 并写明理由。

### 2. 世界与影调草案

有妆发、换装或持续外观变化时，按[妆造设计](../workflow/references/methods/characterStyling.md)补人物处境、当前造型与事件触发的变化。拆解阶段仍用现有 invariants / allowedVariations / stateChanges / gaps 保存依据，不给 saveBreakdown 添加未支持字段；确认后再将当前造型写入资产 attributes。身份、临时妆造和当场表情分开，不把“红唇不变”写成需要卸妆的角色永久锁。

从剧本与场次表归纳，写成可确认的提案：

- World：时代、地点逻辑、气候与时间、材质与物理、现实程度。
- Look：影调关键词、色彩关系、质感倾向，附一句从哪场戏、哪种情绪推出来的依据。剧本含日景与夜景混合时段时，按时段分档写明各自的基底、色温与光源，不用单一夜调或暗调覆盖全片；后续出图沿用对应时段的档位。

没有依据的项标「待确认」，不编造；剧本没有说的年代、国别不替用户决定，给 2–3 个有差异的选项供其选择。

### 3. 出清单并确认

先用 `saveBreakdown` 把清单保存为待确认底稿：每项资产填 `entityId`、`type`、`invariants`，可选 `allowedVariations`、`stateChanges`；不单列的实体写进 `skipped`；世界与影调草案写进 `world`、`look`，缺口写进 `gaps`；`sceneListVersion` 用刚读取的版本。出场场次由工具从场次表自动推导，不要自己填。场次表里每个实体都必须被拆成资产或写进 `skipped`，校验不通过会逐条返回问题，修正后重新调用。

保存成功后，以表格交付给用户确认，每项一行，出场次取工具推导的结果：

| 资产 | 类型 | 出场次 | 必须保持不变 | 允许变化 | 备注 |
|---|---|---|---|---|---|

同时列出：缺口（剧本没写但制作必须决定的，如主角的年龄与外形）、风险项（场次表里标过「高风险」的）、建议合并与建议删除的项。

用可用的 `askUser` 让用户逐类确认或修改（`fields` 字段名如 `characters`、`environments`、`props`、`world`、`look`），没有该工具时文字提问等待。跳过、取消或未回答时保留清单并暂停，不自动写入。

### 4. 写入项目

只在用户确认后，按 [cinema](../cinema/SKILL.md) 的规则先调用 `productionSpec(read)`，再用 `world`、`look`、`asset` 操作保存已确认项，并在资产描述里写明对应的实体 id 与出场场次（如「实体 c1，出场 s01、s03」），作为回链。用户在确认时改动了清单，先用 `saveBreakdown` 更新底稿，再写入项目。工具成功返回对象 ID 才算保存；没有该工具时说明只能交付文字清单。

已 Approved 的资产不覆盖：同一资产有变化时另建变体或版本，写明下游影响。

## 剧本改动后的再拆解

剧本改动后先用 `saveSceneList` 保存新版场次表（旧版本自动进入 `场次表历史/`），再读取新版本重新拆解。对比 `场次表历史/` 里的上一版，只报告**差异**：新增、变更、不再出现的项，以及受影响的场次；已 Approved 的资产保持原样，由用户决定是否新建版本。不得整份重拆后覆盖。

## 交付后的下一步

资产经用户确认并建立参考后，进入 [cinema](../cinema/SKILL.md) 第 4 节镜头规划。
