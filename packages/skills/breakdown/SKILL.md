# 剧本拆解

拆解是创作与制作之间的枢纽：把已确认的剧本变成一份**待确认清单**，用户确认后才进入资产库。资产与世界设定从剧本推出来，用户只确认、合并或删除，不从空白表单开始。

## 输入与边界

- 输入：已确认的剧本与场次表（SceneList，见 [story](../story/SKILL.md)）。只有剧本没有场次表时，先按场次整理出 SceneList 再拆解；用户提供的定稿剧本不改写。
- 未确认的故事、大纲不拆解；先回到 story 阶段。
- 不规划镜头，不生成图片或视频。镜头规格由 [cinema](../cinema/SKILL.md) 的导演流程在资产确认后产生。

## 步骤

### 1. 逐场提取

遍历每一场，只记录**会进入画面且影响一致性**的内容：

| 类型 | 记录 |
|---|---|
| Character | 名字、年龄段、体型、发型、气质；出现的场次；跨场不得改变的特征；剧情导致的变化（受伤、换装、变老） |
| Wardrobe | 属于谁、哪些场次穿、款式面料颜色；剧情触发的变化 |
| Environment | 空间类型、固定陈设与出入口、光源（窗、台灯）、时段与天气；出现场次 |
| Prop / Product | 形状尺寸材质、持有人、起止状态（完好 / 破损、开 / 关）；出现场次 |
| Vehicle / Creature | 同上，按实际出现 |

同一个人在不同场次的称呼不同时合并为一项；同一场景的不同时段保留为同一资产的变体，不拆成两个资产。仅一闪而过、不影响叙事的物件不单列。

### 2. 世界与影调草案

从剧本与场次表归纳，写成可确认的提案：

- World：时代、地点逻辑、气候与时间、材质与物理、现实程度。
- Look：影调关键词、色彩关系、质感倾向，附一句从哪场戏、哪种情绪推出来的依据。

没有依据的项标「待确认」，不编造；剧本没有说的年代、国别不替用户决定，给 2–3 个有差异的选项供其选择。

### 3. 出清单并确认

以表格交付，每项一行，附场次回链：

| 资产 | 类型 | 出场次 | 必须保持不变 | 允许变化 | 备注 |
|---|---|---|---|---|---|

同时列出：缺口（剧本没写但制作必须决定的，如主角的年龄与外形）、风险项（场次表里标过「高风险」的）、建议合并与建议删除的项。

用可用的 `askUser` 让用户逐类确认或修改（`fields` 字段名如 `characters`、`environments`、`props`、`world`、`look`），没有该工具时文字提问等待。跳过、取消或未回答时保留清单并暂停，不自动写入。

### 4. 写入项目

只在用户确认后，按 [cinema](../cinema/SKILL.md) 的规则先调用 `productionSpec(read)`，再用 `world`、`look`、`asset` 操作保存已确认项，并在资产的 references 或备注里保留场次回链。工具成功返回对象 ID 才算保存；没有该工具时说明只能交付文字清单。

已 Approved 的资产不覆盖：同一资产有变化时另建变体或版本，写明下游影响。

## 剧本改动后的再拆解

剧本或场次表改动后，只报告**差异**：新增、变更、不再出现的项，以及受影响的场次；已 Approved 的资产保持原样，由用户决定是否新建版本。不得整份重拆后覆盖。

## 交付后的下一步

资产经用户确认并建立参考后，进入 [cinema](../cinema/SKILL.md) 第 4 节镜头规划。
