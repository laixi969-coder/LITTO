# 电影创作

目标是让每个镜头在表演、摄影、空间和剪辑上属于同一部影片。好莱坞质感是创作目标，不能靠提示词里的「大片、8K、cinematic」或单纯增加运镜来保证。

本技能落实产品 PRD 中 World / Look、ShotSpec、Realism Stack 和深度 Skills 的创作规则。账号模式优先使用 `productionSpec` 保存真实领域对象，并在工作区「镜头制作」面板编辑与验收。若运行环境未提供该工具，说明仅能交付方案，不把文本节点称为已持久化的制片规格。

## 分工与执行边界

- [workflow](../workflow/SKILL.md)：剧本改编、资产制作、画布制作阶段和模型执行；先读现场模型能力；只有明确选用 Seedance 后，其专用规则才约束分段上限和提示词格式，不覆盖电影创作意图。
- [canvas](../canvas/SKILL.md)：查询实际节点、配置、参考顺序并操作画布，不猜节点能力。
- [continuity](../continuity/SKILL.md)：身份、服装、道具、空间、动作、光线与情绪的跨镜状态；锁定资产与版本修复。
- 本技能：叙事、镜头职责、表演与调度、摄影设计、剪辑节奏和电影质量验收。镜头语言细则见 [摄影与剪辑](references/shotLanguage.md)，结构与节奏见 [叙事节奏](references/pacing.md)。
- MV 镜头另外读取 [MV 导演编排](../musicfilm/references/musicVideoDirection.md)：沿用 musicfilm 的开场悬念与故事选择，音乐和表演共同占用时间；完整内容保存到 `musicVideo` 后编译，不只写自由提示词。
- MV 拆镜先 `readSceneList`，使用有效采用版的 `storyContext` 和逐场 `story` 正文、目标、阻碍、变化、知情及因果，再对应音乐段落。`needsUpdate` 时先更新；没有关联正文时回读 `readStoryProject`。把触发、行动、反应和结果落实到 `action/performance/musicVideo.timeline`，核对编译预览；不以情绪摘要代替剧情，也不在每个新镜头重演整场。

## 1. 理解目标：只补问缺失信息，最多四项

1. 故事与范围：人物要什么、阻碍是什么，本次做完整短片、一个场景还是已有影片的续作。
2. 观众与情绪：希望观众经历什么；类型、语言、对白或声音要求沿用已知信息。
3. 交付规格：目标时长与画幅；未指定时建议 16:9，2.39:1 仅在模型或后期实际支持时采用。时长由本次故事需求估算，先说明假设，不默认竖屏、60 秒或固定镜头数。
4. 视觉方向与参考：已有角色、场景、影片画面或摄影参考，预算与可用模型的明确限制。

已知信息不重复询问，不要求用户写制片文档。缺少参考时先提供少量具体摄影方案供选择；未经确认的设定标为提案，不当作既定事实。

## 1.5 上游：故事、拆解与镜头托管

- 没有剧本时先用 [story](../story/SKILL.md) 写故事与剧本，得到场次表；有剧本后用 [breakdown](../breakdown/SKILL.md) 拆出资产清单与世界/影调草案，用户确认后再进入本技能的设定与镜头规划。
- **镜头规格默认由导演托管。** 用户只表达意图（例如「这一镜要压迫感，人物显得渺小」），由本技能编译成完整的 ShotSpec；景别、焦段、机位、光线、调度等专业字段不要求用户填写，也不逐项询问。用户想看或想改时再展开字段，展示时标明哪些是导演填写的。
- 用户明确覆盖或锁定的字段，后续重新规划不得静默改写；编译结果与用户意图冲突时，以意图为准并说明取舍。

## 2. 故事与场景：先确定变化，再拆镜

按 Project → Sequence → Scene → Shot 组织创作。每场写清人物目标、阻力、选择和结束时发生的变化；用行为、空间关系和可观察的反应表达情绪。

剧本包含场景、动作、对白与必要声音提示。保留用户原文与因果关系，不为戏剧性擅自新增事件；不按句号切镜，也不要求每几秒反转或每场悬停。镜头时长服从表演和信息揭示。

## 3. 世界、视觉与资产

制定本阶段方案前，按当前对象读取[视觉设计](../workflow/references/methods/visualDesign.md)、[色彩与用光](../workflow/references/methods/colorAndLight.md)，涉及人物时再读[妆造设计](../workflow/references/methods/characterStyling.md)。将场景结构、维护状态、资产本色、空间受光、后期色彩与当前造型分开决定，再组合成相容方案；已有已确认内容直接继承，不把电影质感默认为暗、脏、旧或疲惫。

先调用 `productionSpec(read)` 读取当前项目，用 `world`、`look`、`asset` 操作保存已确认设定；补充说明可放在工作区 `设定.md`，但不能代替领域对象：

- 世界：年代、地点、建筑与空间逻辑、天气、时间、材质、重力与物理尺度。
- 视觉：对比、饱和度、色彩关系、肤色、黑位、高光滚降、阴影、颗粒与镜头特性；说明参考中采用什么，不机械叠加光晕、浅景深或橙青调色。
- 角色与服装：脸部几何、体型、年龄、肤质、发型、衣服面料与版本。建立中性光身份参考；表情与姿势参考仅按实际戏份补充。
- 场景：无人物主视图、出入口、人物活动路线、固定物件、实景光源。明确不同机位能看到什么。
- 道具：几何、比例、材质、标志细节、功能与持物状态。

Approved 资产、关键帧和 Take 默认锁定。更改建立新版本，写明下游影响，不静默覆盖；不把风格参考当作身份参考。

## 4. 镜头规划：每一镜有职责

每镜通过 `productionSpec(sequence/shot/updateShot)` 保存可核对的结构化规格；`镜头表.md` 或文本节点是阅读副本。不要在已有主帧或 Take 时偷偷绕过规格修改确认。

| 字段 | 内容 |
| --- | --- |
| id / sequence / scene / order | 稳定编号及所属段落、场景、顺序 |
| narrativeFunction | 建立、揭示、反应、对比、过渡或匹配；观众在此获得什么 |
| assets / action | 出场资产版本、可见动作及其起止 |
| performance / blocking | 目标、情绪强度、视线、姿态、重心、走位、行为节拍 |
| camera | 景别、机位高度与角度、焦段、焦平面、景深、构图层次、运动及动机 |
| lighting / look | 主光来源、方向、软硬、补光或负补光、实景灯、曝光和影调 |
| startState / intendedStateDelta / resultState | 本镜起点、预期变化、生成后实际可观察的结果 |
| referenceBindings / freedomMap | 参考用途与编号；锁定、受控、允许自然变化、随机细节 |
| duration / sound / cut | 预估时长、对白与环境声、入点与出点、与邻镜的衔接 |
| constraints / status | 模型限制、待确认项与当前制作状态 |

新增 `realism` 对象，分别写 `surface`、`imaging`、`world`、`motion`、`cinematic`。每项必须与本镜资产、动作与摄影设计对应：无人场景不能套“为皮肤曝光”，静止动作不能硬塞预备动作，光滑产品不能强加皮肤毛孔，风格化影片沿用用户的材质目标。各岗位必须留下可检查的依据：视觉导演写 look 与材质；资产导演写 invariants 与参考；摄影写 camera/lighting；分镜写职责/衔接；运动写真实时序和接触；连续性写状态与锁定；诊断记录实际缺陷及修复。禁止将关键词匹配或通用模板视为专业判断完成。

实际结果状态必须在看过输出后填写，未查看时保持「待核对」。工具成功返回对象 ID 才表示规格已保存。

## 5. 摄影、表演与运动

电影镜头规划前必须读取[专业摄影与剪辑方法](references/shotLanguage.md)，把本场摄影方向落实到 camera、lighting、performance 和实际编译请求。专业电影不默认使用手机成像瑕疵；用户明确要求自拍或纪实时才按该方向选择。

涉及角色表演、对白、无声反应或群像时，必须读取[表演指导与人物调度](references/performanceDirection.md)。将角色目标、潜台词、触发与反应、倾听、目光及跨镜情绪落实到 action、performance、blocking；编译后核对实际请求，不能只列“悲伤/愤怒”等标签。角色外貌和声音身份保持稳定，表情与当场语气可以有因果地变化。

涉及妆发、服装或状态变化时读取[妆造设计](../workflow/references/methods/characterStyling.md)，核对当前资产、参考分工和换装时点。造型必须支持本场动作与反应；起始状态用于接戏，不等于全程冻结。

- 建立空间、轴线与视线关系，安排有动机的覆盖镜头。特写服务人物判断或关键信息，不用随机景别变化掩盖无内容。
- 摄影机运动由人物动作、视点、发现或关系变化驱动；静止镜头是正常选择。焦段、距离、焦点和景深共同服务叙事，避免每镜极浅景深。
- 光源有空间依据，维护邻镜光向、色温与曝光。皮肤、布料、玻璃和金属按真实材质响应光线，避免塑料肤质、统一磨皮与过度锐化。
- 表演写成可见的节拍：听见、理解、迟疑、决定、动作及收势；动作包含接触、受力、重心、惯性与次级运动。摄像机与人物不能无动机地匀速漂移。
- 对白镜头按实际同步能力规划。能力不足时明确限制，先验证小样；旁白或反应镜头须有叙事理由，不把不自然口型当作可接受的电影质量。

## 6. 从关键帧到视频

先制作一个能同时检验身份、光线、表演和运动的代表镜头小样，经用户采用后再扩展。每镜可有关键帧候选，用户选为主关键帧后锁定，再按实际 I2V / 首尾帧 / 参考模式生成 Take。

静帧用于设定、分镜和关键帧，不能用静帧缩放冒充人物表演或完整电影镜头。预算不足时先缩小本次制作范围、复用资产或调整覆盖计划；降低质量或改用静帧交付须明确说明并得到用户同意。

生成前核对参考顺序、配置和提示词，说明对象、数量、模型、规格与费用性质，按用户已授权范围执行。创作方向的确认不自动授权付费生成；不反复请求用户已经给过的同一授权，不擅自自动重试。

执行顺序：`listMediaModels` → `productionSpec(binding)` 绑定实际已上传的参考 ID → `productionSpec(compile)`，其 data 包含 `shotId`、`kind`、`request`（实际 providerId/modelId/prompt 与模式、画幅、时长等）→ 阅读返回的 warnings/degradations → `generateImage/generateVideo` 传入同一请求、`shotId` 和返回的 `fingerprint` 作为 `productionFingerprint`。服务端用领域编译结果替代自由 Prompt。参考不支持时不能声称发送或锁定；LOCK 参考无法发送时更换模式。生成视频需用户在面板实际检查并选定 Hero，AI 不可自行填人工检查记录。

## 7. 质检与修复

仅评价实际读到的画面或声音，区分「文字方案已核对」与「输出已查看」。逐镜检查身份和几何、材质、空间、状态、光线、动作、表演及影调，再逐对检查轴线、运动方向、视线、动作接点和情绪衔接。

每条问题指出镜头编号、观察到的缺陷、影响和最低成本修复。先改方案或配置，再考虑局部重生成；保持已采用版本，实际费用与能力限制必须如实说明。没有视觉或音频检查能力时，交给用户验收，不编造 QC 通过。

## 8. 交付与汇报

交付已完成的剧本、设定、镜头规格、关键帧、Take、连续性记录及剪辑顺序、声音与字幕计划。音乐、对白、环境声与留白服务场景，避免持续满铺音乐；字幕和可读文字在实际支持的后期能力中处理。

有真实合成能力且用户授权时才输出合成影片；否则明确交付镜头素材包，列出尚缺环节。使用 `fitCanvas` 展示实际成果，汇报已完成内容、待验收镜头和下一项决定，不保证模型无法保证的「好莱坞级」结果。

## 资产先行与成片闭环

完整影片的默认顺序是：确认故事与视觉方向 → 生成并采用本次需要的角色、场景、关键道具基础资产 → 基于真实资产制作分镜/关键帧 → 视频片段 → 剪辑合成 → 画布成片与下载。资产文字清单或空节点不等于资产已生成。已有适用资产直接复用；只缺部分时补缺项。可提前做文字镜头草案，但在所需资产未就绪时不开始正式分镜图或视频生成。用户明确只要分镜方案或独立片段时遵守该范围。

用户要求完整影片/MV，已授权制作范围就包含对已采用片段的本地拼接、混音和导出；素材与剪辑顺序、入出点齐备后主动执行，无需再等一句“帮我合并”。仍缺采用决定或素材时准确显示缺项，不擅自采用失败候选、不新增付费调用。按剪辑顺序使用真实片段，不能按文件名排序代替镜头顺序。

导出成功后把真实文件挂到当前任务绑定画布的独立视频节点，命名“成片 · 作品名”，展示完整播放与下载入口；核对文件与节点持久化后才登记已合成。FFmpeg 自动挂载成功则复用回执中的节点，不重复添加；挂载失败时仅重试挂载，不重新渲染。导出不等于人工验收通过，不伪造看听记录。

涉及武打、搏击、追逐、动作电影时，在镜头规格阶段读取 [动作编排](references/actionChoreography.md)，将动作因果、空间、接触与连续状态应用到实际 action、blocking、camera 和剪点。模型专用格式仍服从已选模型规则。

## 镜头方法接入

涉及镜头选择、产品展示、音乐运镜、预演或运镜验收时，按需读取 [镜头方法卡](references/masterShots.md)。将方法落到 ShotSpec.camera.design 与现有摄影、表演字段；不以大师姓名替代规格。
