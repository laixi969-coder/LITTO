# 镜头设计：从观众获得的信息出发

本文件为 LITTO 独立编写的方法卡，不是某位导演的固定风格或模型能力保证。来源、许可和十二项吸收决策见仓库 `docs/masterShotsIntegration.md`。只有相关镜头才读取对应方法；不把全部词汇装进每个提示词。

## 决策顺序与落盘

先写观众此刻知道什么、下一刻应知道什么，再选主体动作、空间关系、视点和剪点。固定机位能完成目的时允许固定。导演选方案，writer 填规格，reviewer 独立寻找反例。主 Agent 负责持久化与真实模型执行，团队不私自生成媒体。

把镜头卡写入 ShotSpec.camera.design：technique（技术而非大师姓名）、purpose（叙事目的）、start/end（可见起止状态）、subjectPath、cameraPath（必须分开）、timing（动作/对白/停顿预算）、cut（出入剪点）、invariants（不能改变的事实）、acceptance（观看时能判定的结果）、fallback（能力不足时的替代）。既有 camera 的景别、焦距、轴线、视线和 lighting 继续填写；表演放 performance/action，层次放 blocking。不能只给镜头取名而不填可执行规格。

## 方法卡

| 技术 | 适用目的与执行 | 不适用/风险 | 观看验收与退路 |
| --- | --- | --- | --- |
| 主镜头 master shot | 连续覆盖一段行动，先交代人物、出口、道具与轴线，再以补充镜头强调信息 | 不等于必须远景，也不等于大师风格；空间已清楚可省建立镜头 | 不靠字幕也能辨认行动方向；失败先补明确空间关系的静态镜头 |
| 推近 dolly in | 由环境关系过渡到可见决定；相机沿路径接近，主体可不动 | 不等于 zoom，透视会变；不为每次说话推进 | 背景视差与主体尺度连续，终点关键表演可读；退为两景别剪接 |
| 拉远 reveal | 从细节揭示更大关系，遮蔽物离开画面才释放信息 | 不提前露出悬念，不凭空增加人物道具 | 揭示时刻匹配因果；退为特写→关系全景 |
| 横移/跟随 truck/track | 保持主体可读，同时用视差描述空间或跟住位移 | 角色轨迹与相机轨迹不可混写；遮挡不应丢身份 | 主体速度、脚底接触、前后景视差一致；退为固定构图内出入画 |
| 环绕 orbit | 展示关系变化或产品体积；围绕明确中心，给足弧线中间帧 | 两端直线插值不是环绕；不得无动机跨轴，背面未知不能编品牌结构 | 半径、朝向、遮挡及轴线可解释；退为几个已知角度独立镜头 |
| 摇镜 pan/tilt | 相机位置不动，通过旋转把注意力从 A 转到 B | 不写成横移；甩镜遮盖的信息仍须后镜补齐 | 地平线、旋转方向、起止停留可读；退为切镜 |
| 变焦 zoom | 相机位置不动改变视角，压缩/放大观看范围 | 不能宣称产生位移视差；焦距须结合画幅 | 背景透视不随相机位移改变；退为后期裁切并检查分辨率 |
| 滑动变焦 dolly zoom | 明确心理失衡时，相机距离与视角联动，主体屏幕高度近似不变 | 非普通推近；需要逐帧补偿；不能用两个同 FOV 端点实现 | 对同一主体近似满足 distance × tan(verticalFov/2) 恒定；检查背景变化，失败退为主观镜头+反应 |
| 焦点转移 rack focus | 通过先后清晰关系引导注意；写清两个对象、距离、触发时刻 | 图生视频未必支持焦点控制；不自动加呼吸效应 | 对象身份和位置不变，焦点转移可读；退为两个清晰的独立镜头 |
| 过肩/正反打/主观 | 建立谁看谁与信息差；明确视线目标、肩位、轴线一侧 | 三人对话不能按说话轮次机械左右翻转；未知空间不填假轴线 | 逐对画出视线和人物位置；退为包含双方的同框 |
| 动作匹配/match cut | 前后镜靠真实动作相位或图形关系连接 | 同动作不可重复两次；两种匹配不可混称 | 比较接点前后姿态、运动方向、道具所在手；退为完整动作后再切 |
| 长镜头与遮挡转场 | 用调度完成注意转移，经过真实遮挡点连接空间 | 长不等于高级；人物/光源/物体不应借遮挡变形；模型时长不足不得硬装连续 | 按进入、移动、关键行为、结束分段检视；退为有动机的切镜 |

## 产品与音乐分支

产品卡按真实卖点选择：轮廓建立（可辨外形）→材质特写（真实表面与反射）→功能演示（输入动作与可见效果）→使用关系（手/物体接触）→品牌收束（真实文字与包装）。这是一组可选职责，不强制五镜。透明、镜面、液体、微距的异常重点由材质决定。保留包装字样、比例、开口与配件；不能用光效冒充功能证据。用既有 3D 导演台预演角度，用既有动态分镜/FFmpeg 检查节奏，不另装编辑器。

MV 使用已分析的音乐事件与时间码组织乐句/停顿/重拍，不逐拍切镜。镜头运动峰值、动作落点、剪点分别落在明确事件；音乐缺失时只能交付待对齐草案。歌词与动作不必机械逐字对应。

## 控制与降级

区分四层：文字意图、参考视频、局部 3D 预演、原生数值轨迹。前两者不承诺外参或像素锁定。轨迹只能发送给 listMediaModels 明确声明 cameraTrajectory 的所选模型。GEN3C 接收图像与相机轨迹，逐请求文本提示词不是其官方接口能力；需显式确认 imageAndCameraOnly，不能声称其完成台词、人物表演或声音控制。

先在 3D 导演台预演，核对相机起点与主关键帧构图，导出相对初始相机的 OpenCV 坐标轨迹（右/下/前，行主序 3×4 camera-to-world，24fps）。translationScale 必须按服务深度尺度校准。只导出单个连续镜头，硬切分成独立请求。先做短镜头，GPU 未运行只能称协议/几何验证。

## 对抗式审阅

每镜追问：删掉它会损失什么？给定时长能说完并完成动作吗？相机与角色是否被误写为同一路径？没有新信息却在运镜吗？特写会提前泄露什么？上一镜隐藏的道具能在此镜出现吗？轨迹单位、FOV、帧率、画幅与种子图是否一致？生成失败退路是否仍保存叙事目的？

reviewer 对每条给出镜号、事实依据、严重性和最小修复；拒绝空泛“更电影感”。观看素材之前只审规格，观看之后才评价效果。不把规则生成草稿称为导演推理或素材验收。
