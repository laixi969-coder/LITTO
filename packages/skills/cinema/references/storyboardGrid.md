# 多格分镜图到成片

用户可选择四格、九格或其他行列布局；不默认多格，也不因选择多格增加生成次数。沿用用户已确认的故事、资产、模型、精度与授权范围。布局和每格内容已明确时直接执行，不再确认一次。

## 精度与布局

1. 查询 `listMediaModels` 和 `productionSpec(readQuality)`。用户已说“图片 4K、视频 1080P”等规格时，用 `productionSpec(setQuality)` 保存实际支持的值；未选时用 `requestProductionDecision(selectQuality)`，不要静默选最低档。所选精度不支持对应时长时说明可选时长，不暗中降级。
2. 图片精度指整张图。实际 3840×2160 的九宫格，等分后每格仅为 1280×720；不能将每格称为原生 4K。若每格细节不足，按原镜头与已采用资产另生高精度干净单帧，新增生成须在用户授权内；插值放大不等于恢复真实细节。
3. 保存每格对应的真实 shotId、顺序、内容与时长，继承项目 Look 和已采用资产参考。用户自带图可复用，不要求重做。多格总览可调用 `generateImage`，显式 `purpose: "storyboard"`，带实际资产图片，描述行列与从左到右、从上到下的顺序。总览不是任何单镜的 Hero，不传某一镜 shotId 来让编译器替换掉总览提示词。

## 拆格并登记

4. 先查看真实输出并 `ffprobe` 读取尺寸；模型可能未严格按指定行列绘制，不能盲目平均切格。有分隔线、标签或外边框时按可见内容取矩形，避开文字与邻格。多余格、缺格或错位只修相关格，不暗中重生成整批。
5. 用现有 `ffmpeg` 裁图，每张输出新路径，原图保留。示例（仅当实际图片的对应格确为此坐标）：`steps: [{method:"input",args:["assets/board.png"]},{method:"videoFilters",args:["crop=1280:720:0:0"]},{method:"frames",args:[1]},{method:"output",args:["assets/shot01.png"]}]`，`publishToCanvas:false`。先创建输出目录，裁切坐标以实际图为准，不使用示例坐标猜测。
6. 对每张干净图调用 `productionSpec(importKeyframe)`：`{shotId:"真实镜头ID",path:"assets/shot01.png"}`。同镜头重复导入相同图片返回已有候选，不重复创建；已采用版本保留。用返回的关键帧 ID 一次调用 `requestKeyframeApproval({keyframeIds:[...]})`，在聊天中展示整批单格并保存主帧。不要先询问是否采用，再让用户去面板点 Hero。总览布局确认不能代替尚未看过的裁图检查。

## 视频和交付

7. 默认每镜使用干净主帧，以实际模型支持的 I2V 或参考模式编译并生成。`compile` 返回的 `request` 含已解析精度，连同 fingerprint 原样用于生成。单独描述本镜运动、表演、声音与衔接，不能让一个普通 I2V 请求负责整张宫格所有镜头。多参考模型可以传入多张干净参考，但数量能力不证明它能逐格、逐秒准确演绎；只有实际文档支持分镜输入且用户选择此路线时才做整图参考小样。
8. 实际检查输出，通过聊天采用 Take，复用已有有效采用。缺失或失败的镜头如实保留待完成，不以静帧移动冒充视频，不擅自增加重试费用。
9. 以领域镜头顺序和已采用 Take 读取 `readEdit`、保存剪辑方案，完成声音、转场与导出；可用 `productionSpec(render/inspectFinal)` 或现有 FFmpeg 实际合成。导出精度与源片精度分开说明，不能把放大的 1080P 片段称为原生 4K。用户已授权成片时继续完成本地合成与画布发布，不在生成片段后停下等待一句“再拼起来”。最终使用真实视频文件供播放下载，未做的声画验收明确标注。
