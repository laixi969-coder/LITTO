# 写实与玄幻动作：从可见事件到镜头执行

这是 MILIMILI 自行编写的动作设计资料。结合对 real-combat-director 与 xuanhuan-combat-director 的能力评估，补充发力、多人压力、能量尺度与终局空间的设计入口；两仓库未提供明确 LICENSE，未移植其正文、招式表、参数库或脚本。来源版本记录见[来源与许可](actionChoreographyLicense.md)。先遵循[动作编排](actionChoreography.md)和[武打专项](manjuActionDirection.md)，不将素材词库当武术史料或生成效果保证。

## 发力和承接

先判断动作要改变什么：距离、支撑、方向、持物状态、退路或胜负。关键动作写清支撑来源、身体重心与转动、攻击路径、接触或避开的部位、对方反应和结束位置；连接动作可以简写，仍须继承前一拍状态。无需把生物力学术语逐项塞进视频提示词。

可按可见机制选择动作，而非堆流派名：

| 机制 | 需要看见的依据 | 状态承接 |
| --- | --- | --- |
| 直线推进 | 支撑与身体向目标移动，手或器械沿可读路线进入 | 接触后的距离、对方退向与下一次选择 |
| 旋转挥击 | 重心转换与躯干转动带出弧线 | 挥击的惯性、回收路径和暴露方向 |
| 近身短动作 | 双方距离容得下动作，接触与反应可辨 | 不把格挡当全员暂停或位置重置 |
| 身体挤压或冲撞 | 路径、支撑与接触面明确 | 失衡、转向或障碍后的恢复依据 |
| 摔投或支撑扰动 | 双方接触关系与支点变化能看清 | 落地姿态、持物与空间朝向接得上 |

反应与动作匹配，不默认每击腾空、骨裂、火花或建筑损坏。既定伤情只在相关动作真正发生后登记；未观察输出不填写 resultState。写实强度由连续压力、攻守变化和位移后果决定，不等于克制对练。

## 多人压力

为每人给出当前目标、位置、路线和介入条件。副攻者可以封退路、逼转向、截住武器或改变主角选择；人物不必同时发生复杂接触，也不能等上一人收招后才启动。

注意力以主要交锋为锚点，背景行为仍改变空间。暂时离开的人需有被阻挡、失衡、绕行等可见原因和重新介入时机；不能用整段“伺机”解释围观。外形差异沿用已定资产，不为了防复制自动换服装。多人复杂接触先做可核验片段，身份稳定不能代替动作验收。

## 玄幻能量与体量

先沿用 world/look 的超自然规则：能力由谁发起、通过什么媒介出现、沿何路线传播、为何影响对方、何时结束。写实场不自加能量；仙侠也不自动附带飞行、巨化、爆炸或废墟。

让观众读懂体量需要空间证据：效果在画面哪里、与人物及已知物件的相对大小、前后层次与遮挡、发起点和目标点。必要时给粗略量级，避免互相矛盾的米数、画幅占比与人物尺寸；极小人物无法同时清楚呈现面部微表情。

多物体效果先定义可读群体路径、前中后层次和追踪主体。不要让每件物体同时执行独立复杂招式；镜头究竟展示总体规模还是局部接触需选清。法阵、召唤物与自身变形分别登记，不能前一镜在身后召唤、下一镜未经过程变成角色自身。

光色来自已经确定的元素、材质和实际发光源；特效出现时才影响角色及场景照明。不默认三色、固定环数或强制冷暖对抗。特效的遮挡与消退不能让人物、武器或地形在下一镜无故重置。

## 结束位置与下一镜

结束既可以胜负分明，也可以脱离、僵持或悬念，服从剧本。逐个记录人物的落点、朝向、持物、支撑和可见状态。被击离画要交代运动方向与后续可接位置；遮挡、烟尘或光效结束后不能凭空回到起点。消散、巨化恢复与死亡只有世界设定和故事明确时才发生。

ShotSpec 的 action 写可见因果，blocking 写位置与路径，performance/realism.motion 写身体响应，camera 写实际可看见的区域，startState/intendedStateDelta 写状态。musicVideo.timeline 存在时仅用这一份执行节拍；同一事件不在多个字段写出不同时间。

按事件估时，再选模型支持的段长；不把每击硬摊成 2–3 秒，不强制三轮反杀或单段30秒。只有模型能力实际支持时才安排内部切镜、首尾帧、参考组和声音语法。正式请求回读 compiled.prompt，排除动作重复、摄影矛盾和状态跳变。

对抗式验收：对手是否真的改变主角行动，副攻者是否改变退路，接触是否有后果，失衡是否连续恢复，规模是否靠空间而非形容词成立，终局是否接得上下一镜。小样动态未看过，不能宣布动作通过。
