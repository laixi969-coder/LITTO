# 按片型执行的画面与动作标准

用于剧情、商业广告和 MV 的导演、生成及验收。沿用用户已确定的故事、人物、风格与生成范围；以下五类参考代表能力目标，不能把不同片型强行调成同一种颜色或节奏。目标是否达到以实际作品为准。

## 剧情与动作叙事

以《弥存计划》所代表的空间可读、连续行动与场景光色为目标。一个行动单元先明确人物目标、当前位置、障碍和出口，再安排触发、避让、翻滚/交锋、追逐与可见结果；只执行本镜承担的阶段，不在每镜从头重复整套动作。摄影覆盖要交代空间、看清关键接触、呈现对方反应并保留位移后果。

使用现有字段落地：

- 场景资产记录门窗、障碍、出口及固定光源；blocking 写前中后景人物位置，camera.position 写相对机位，lighting.worldSource 写真实光源。不同场景可有明确光色，不能为了“统一”抹掉场景区别。
- camera.design.start/end/subjectPath/invariants 保存本镜起止姿态、路径和空间保持项；连续事件使用 continuityFromShotId，前镜实际结束状态优先。
- 唯一执行时间线为 camera.design.timeline；MV 使用 musicVideo.timeline。combat.beats 每项通过 timelineIndex 绑定其中一个零起始节拍，不再另写一套秒数。同一节拍可以有多人并行动作。
- creativeBrief.combat 明确 dramaticTurn、signature、coverage。每个 beat 写 attackerId、defenderId、action、reaction、endState、supportingAction。副攻者要有具体位置与行动作用，有意不动时说明原因，不能默认所有配角轮流等待。
- 发生接触、承托、撞击、落地或交接时，在 interactions 写真实参与资产与 start/contactAt/end、approach/contact/force/support/release/endState。躲开而没有碰到不能捏造接触。

优先实时执行；翻滚有进入、支撑/接地、身体通过与恢复，追逐有路径、距离变化和终点，交锋有作用方向与对方后果。镜头跟随行动，不能人物等摄影机。不得因难度把已要求的翻滚、追逐或多人行动删成站立、慢推或轻触。单段容量不足时调整机位覆盖或拆成因果完整且可接续的单元，保留原目标；新增生成仍遵守授权范围。

## 双人剧情与古装表演

以庭院双人参考中的站坐变化、靠近、搭肩、拥抱和情绪回应为目标。先用空间画面建立两人位置，再用正反打、双人近景和接触细节推进关系。每个角色都有注意对象与反应，切镜保留视线、手位、接触部位、持物、身体承重和衣料变化。

古装情绪镜可保持克制，行动镜须有清晰动作结果。妆面、发丝、织物、珠饰、毛皮保持各自材质，柔和人像不等于抹平五官与皮肤。副角色和前景人物也要保持身份及空间位置，不能只锁主角。

## 商业广告

生活方式参考：用出门、上车、接近环境或使用产品的行为链组织镜头，身体任务与产品展示相互服务。为全身、手部、产品和环境准备适用的实际参考，不强迫一张半身坐姿图承担全部机位。

感官参考：触水、树皮、眼睛、茶汤、闻茶与山林可以通过颜色、形状、材质、视线或感受衔接。明确哪些是同一时空行动，哪些是意象蒙太奇；后者不机械继承上一镜全部空间姿态。保留有意景深、虚焦、遮挡和明暗变化，不把它们一律当作失败或全片锐化。

沿用 adDirection 的视觉规则、产品权威参考、样镜和 advertising 节拍；锁定产品本色与几何，不把整套参考人物、品牌或场景照搬到新项目。

## MV

用实际原曲的乐句、段落与动作峰值组织视觉变化；叙事段沿用剧情因果，表演段可有计划地换场景和造型，意象段沿用感官联系。不同段落分别保持应有的一致性，不强求全片同一姿态、服装或机位，不机械逐拍切镜。保留已确定的歌曲入点与口型覆盖。

## 光色、质感与最终检查

项目 Look 管理颜色关系、肤色、高光滚降、暗部、材质与清晰度；场景 lighting 管理具体光源与曝光。保留用户指定的汗水、损伤、夜景、柔焦和运动模糊及其作用，不由“干净清爽”默认值覆盖；无依据不新增。后期调色用于匹配已有素材，不能修复错误空间、物理或接触。

inspectProduction/read 返回 qualityReviewPlan；视频的 motionPlan.checkpoints 来自当前执行时间线、接触和攻防设计。实际完整播放后，由助手按每个 id 提交 motionReview:[{id,verdict:pass|revise,note}]，note 写真实时间点、观察和偏差；没有观察的部分不填 pass。技术检查是助手的工作，不是给用户新增逐项确认。

动作没完成、人物穿透、多人无故等待、身份/空间漂移或没有受力结果时记录实际缺陷，只返修受影响单元。检查完整不代表模型必然执行正确，生成成功和身份稳定不能替代动作与创意达标。保留失败证据与已有好素材，不自动无限重试。

最终以完整序列检查镜间动作阶段、空间方向、光色和节奏；同一人物在不同场景的服饰、伤损和持物要可追溯。5–10 秒样镜只能验证局部，不能宣称数十秒或数分钟连续性已达标。一镜到底须单独检查全程空间与动作；分段续接如实称连续长镜头效果。

用户已确定的方案和有效检查沿用，必要选择集中展示一次。用户要求先不消耗算力时只规划、编译和本地核验，不调用付费生成或视觉模型。

## 请求中落实参考职责

生成前用实际节点 references 或 compiled.inputs 核对：当前采用媒体/版本、真实顺序、用途、裁切或投影结果、sent、容量和降级。全局资产编号、参考板内格号、当前请求图号互不等同；每段重排，以实际发送为准。前镜不会仅因排在前面就自动成为后镜输入。

同一图可提供多项相容事实，但说明各自作用范围，不为形式要求重复上传。人物图锁身份与当前造型，构图/白模/深度只取选定结构，场景图提供已有地标；任何参考板的灰底、文字、网格和人物数量都不自动进入剧情。

有 DEPTH、PANORAMA 或音视频参考的字段/能力声明，不等于目标适配器已发送专用条件。普通图像参考按软引导说明；只有真实支持才能用首尾帧、音频参考或动作视频。缺关键输入先调整能力方案，不能将文字“严格按照”当能力补丁。

## 原创例与反例的使用

适用与输入：提交参考或预演时；输入真实媒体、职责、顺序及模型声明。

写法示例：图A锁人物身份，图B只借门洞构图；实际请求先B后A，就按实际顺序重编号。

反例：提示写参考图3，但请求只发送两图；把白模颜色当成演员服装。

约束与例外：本例只说明组织方法，人物、时长、数量与媒介须换成当前项目；不自动加入案例剧情。已有有效方案直接复用。

验收与修复：回读sent、媒体及降级；缺通道先说明并调整方案，不能靠文字声称发送成功。 本例未实际生成，不作为效果证据。
