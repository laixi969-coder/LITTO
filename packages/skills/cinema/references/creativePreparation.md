# 先完成造型与动作设计，再生成

本资料供助手执行，不把以下字段变成用户表单。用户已经授权自主制作时直接完成设计、实际检查与修正；沿用模型、精度、人物关系、对白原文和口型要求。技术上的完整不代表艺术质量通过。

## 1. 创作目标先落到可见设计

creativeBrief.kind 按本镜内容选 combat（武打，必须有 combat 编排）、performance（表演/对白）、establishing（空间建立）、product（产品展示），不能为绕过检查把武打标成其他类型。产品独立镜头也要设计创作目标，无人物时不添加妆造要求。将用户目标写进 shot.creativeBrief.intent；visualPayoff 写画面里具体看得到的造型重点、构图和光影关系。不要只写“高级、电影级、真实”。写实描述材质与物理，不能自动推出素衣、无妆、低反差、慢动作；精致也不等于华服、浓妆或堆配饰。以角色身份、故事和用户目标选择。

人物资产的 attributes.styling 使用四个非空字符串：makeup（肤面、眉眼唇及角色气质）、hair（分区、轮廓、收束与饰件）、costume（剪裁、层次、面料和主次色）、accessories（有叙事或轮廓作用的配饰，或明确无配饰及理由）。说明与动作的相容性：肩肘活动、摆幅、握持和鞋履；有口型要求时嘴部不能被面纱、发丝或景别持续遮挡。当前设计只写当前一套，不混入候选。

先看真实造型图：整体轮廓有无辨识度，近景妆发与全身服饰是否相容，材质与光线有没有层次，是否达到用户要求的气质。未达到就修改相关资产和参考，不能因为脸对、无变形就锁定。已有资产只是可复用素材，不自动证明符合新的审美要求。改造型时沿用资产版本/草稿流程；旧图可只锁身份，不让旧素衣覆盖新造型。

## 2. 武打先设计戏，再拆执行单元

先在整场写出争夺目标、空间障碍、主动权转移和高潮，再拆镜。creativeBrief.combat 保存本镜的 dramaticTurn（局面如何变化）、signature（有辨识度且符合角色的动作设计）、coverage（观众怎样看清接触与反应，实际剪辑接点）。不以提高 intensity、加招式数量或追加“激烈”代替设计。

beats 每项保存 attackerId、defenderId、action、reaction、endState、supportingAction。ID 必须来自当前镜头资产；第三人的行为应真实改变路线或压力，没有第三人时明确写无。攻击、防守和结果必须连成因果，不能把“出手—格挡—回位—等待”写成激烈交锋。招式是银幕编排，不需要使用流派术语。

先把一段有价值的攻防拍好，再扩展组合。每个生成单元围绕一个清晰转折，复杂多人接触、快速换位和精确口型不要全挤进同一段。按模型容量拆生成素材，由剪辑构成整场节奏；不降低整场精彩程度，也不按九宫格或模型最大时长机械均分。实际秒数仍以 musicVideo.timeline 为唯一执行时间线，combat 是设计依据，两者必须一致。

小样必须代表目标片的动作力度和造型，不能用普通对练验证成功后声称大片质量达标。失败先分辨编排不精彩、参考不合适、模型未执行哪一项；同一参考和同一动作的提示词对照只改变一个变量，不凭单次失败宣判模型上限，也不重复堆词抽卡。

## 3. 对白与口型单独保留

creativeBrief.dialogue 必填；本镜确实无对白时 lines:[]，但整场台词必须分配到其他镜头，不能因动作隔离验证而从全片消失。

结构为 {mode:"native"|"post",lines:[{speakerId,text,start,end,delivery,lipSync:"visible"|"offscreen",framing}]}。text 保留原文，start/end 是本段秒数，delivery 写语气和气口，framing 写怎样看清说话人的嘴。用户要求可见口型时用 visible，不能静默改画外音。native 使用有声视频模型并开启 generateAudio；post 是明确的后期配音与口型处理任务，不能把生成无声素材当作完成。独立 lipSync 能力和原生音画能力分别判断。

对白可以在交锋的判断、压迫或短暂脱离中发生，其他人物仍有合理行为；将高难接触放在对白前后，不让所有人站定等待。不用统一语速估算当作同步证据。成片需实际检查说话人、台词、发声起止、嘴部开合与音效遮挡；只看抽帧必须标未核验。

## 4. 保存、编译和采用

shot / updateShot 保存 creativeBrief，与 action、camera、performance、realism、musicVideo 一起复核；资产妆造仍保存在 attributes.styling。服务端会拦截缺失设计、无效角色、越界对白时间和声音方案冲突，错误由助手修正，不再请用户填专业参数。旧项目可读取，继续生成正式人物镜头时由助手补足设计。

编译后逐项核对：可见视觉目标、角色造型、动作转折、原文对白及口型要求是否进入实际提示词。不能用自由 prompt 覆盖已保存规格；图片不写整段对白和连续动作，视频才发送本段动作与台词。

camera.design.timing、action 与 combat 中的秒数使用本镜局部时间，从 0 到该镜 duration，不把整段累计时间直接写入单镜生成请求。跨镜移动须在前镜末态中已经开始，后镜从该末态接续；坐标、退步方向和持物变化逐项对照，不能用已结束的动作或已消散的兵器继续攻防。intendedStateDelta 按 characters/wardrobe/props/environment/lighting/motion/emotional 分组；例如 {characters:{真实角色ID:{position:"镜尾位置",pose:"镜尾姿态"}}}，不把角色名或 ID 放在根层。编译告警须先修复，不能把成功返回提示词当作准备完成。

获得自主采用授权后，agentReview 额外传 creativeReview:{verdict:"pass"|"revise",styling:"实际造型与目标对照的具体依据",staging:"实际构图、动作起点或攻防结果与目标对照的具体依据"}。每项必须基于查看真实素材，不写“检查通过”凑字段；未查看不能填 pass。关键帧只评静态设计，视频另评连续运动与实际声音。revise 会保留问题并阻止采用，不因身份一致自动通过。

这些字段记录助手的判断，不是自动审美评分器。通过类型检查、请求成功、文件可播放、检查项齐全均不能替代实际质量验证。最终报告分别说明代码验证、设计检查、视频效果和对白口型检查。
