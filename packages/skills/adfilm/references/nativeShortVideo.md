# 原生短视频创作 — 从值得看的生活事件出发，交付能拍完的短视频

## 在 MILIMILI 中使用

- 本方法替换原 adfilm 的通用短视频创意结构，适用于 TikTok、Reels、Shorts、带货/UGC 原生创意、软件推广、纯内容涨粉与 Hook 设计；用户提到 hiccai-pop 时也从这里进入。电影式品牌片仍用 [adfilm](../SKILL.md)。
- 先分目标，再按下面的默认条件交付。仅要创意、Hook 或脚本时直接给该范围的完整成果，不先启动广告简报审批、产品出图或媒体生成。用户已明确的制作方式、露脸要求、语言与授权优先；不能因 MILIMILI 有生成工具就默认改成 AI 制作。
- 产品推广后续进入实际 AI 制作时，衔接 adfilm 的产品参考、导演方案、样镜与 advertising 字段；将首帧、伏笔、末镜证据、露出时点与声音接点落入现有镜头规格。产品默认末镜揭晓时，前镜不得因为统一参考或产品展示模板而提前露出商品。
- 纯内容不套产品资产、adDirection、advertising、CTA 或广告审片要求。需要在工作台保存或制作时复用 [story](../../story/SKILL.md) 的版本与采用流程和 [workflow](../../workflow/SKILL.md) 的执行能力，保持本方法已选定的观看回报与镜头，不重新改写成广告。
- AI 制作或更高规格仅在用户明确要求时使用，按 workflow 的实际模型能力、分段与算力授权执行；已有生成授权直接沿用。方案中的可拍性审核不等于已拍摄、已生成、已验证留存或产品效果。


## 1. 工作范围与默认值

用户给产品名或内容主题即可构思，不为可自行决定的机位、场地和台词反复提问。先服从用户当前及前序明确约束，再使用默认值。

先区分**目标**（实物带货 / 软件、App、数字资产推广 / 纯内容涨粉）与**内容类别**（穿搭、搞笑、故事会、治愈生活、文化观点、软件效率、解压过程、创意好物）。类别不等于目标：整理冰箱可以卖收纳盒，也可以只做生活记录。未给产品的故事、观点或生活主题按纯内容处理，不补商品或下载CTA。先确定观众期待故事答案、可学方法、可核对结果还是感官完成感，再选机制。需要各形态具体流程时读 [全场景创作方法](nativeShortVideo/allScenePlaybook.md)。

- **默认所有方案都必须能用一部普通手机完成拍摄、录音与基础剪辑**，不依赖额外摄影设备、电脑后期或付费生成。先按第 5 节筛掉拍不成的点子，再扩写；只有用户明确要求更高制作规格时才放宽。
- 默认中文说明；涉及台词和顶部文字时给自然英文及中文意思。未指定平台时以 TikTok 原生表达构思，可改编 Reels、Shorts；不承诺播放、完播或转化结果。
- 产品创意先从物件、可见状态、实际操作或录屏任务出发，不默认写熟人争吵、抢夺、指责和情绪表演。仅有人物关系确实不可替代且符合出镜配额时采用人物故事。产品最多承担一个主要利益点；纯内容优先一个主题与一种核心回报。
- 产品反转仍须有前三秒具体冲突、提前伏笔与末镜翻案，但冲突可以是物件关系、空间判断、数量归属或输入与结果矛盾，不必由人吵架。强反转的证据须推翻判断，不能将“原来是这个原因”升级为欧亨利。未要求全是反转时，可混合操作解围、对照验证、过程兑现、ASMR与录屏；诚实标注机制，不用演示冒充反转。纯内容不强加商品或70%揭晓时点。
- **默认至少70%的创意完全无人出镜**：10条至少7条、5条至少4条；其他多条数量向上取整，单条优先完全无人。比例按创意条数计算，不按视频时长，也不是70%才露出产品。剩余条目优先仅手部或不露脸的简单操作，默认不安排露脸表演。用户明确要求其他配比或露脸时按其要求执行；不能因无人反转难写自行改成全人物剧情。
- **低表演负担**：默认幕后1人操作手机与道具；露脸、双人对白、尴尬/愤怒/惊喜反应不能成为默认成立条件。旁白可选，不强制口播或表演配音。各条标明出镜人数与幕后总人数；固定手机后再操作，不把藏住演员等同于降低演技需求。
- 无人指不出现人、手、身体、倒影或 AI 人形角色。宠物可单独标注，但不靠诱发宠物惊吓、挣扎或危险动作制造包袱。无需人物反应时，用物件状态、位置或声音变化完成反转。
- 分别标注**出镜**（完全无人/仅手部/有人）与**载体**（实拍/录屏/AI/混合）。Faceless 只是不露脸；录屏内的人像、头像、数字人和 AI 人形也计入有人。无人优先真实状态或正常机械过程，不为凑数量默认写定格动画。
- 即使只要创意，每条也给覆盖全片的 3–6 个具体镜头及实现办法；不只写故事梗概或第一秒。用户只要单个 Hook 等更窄交付时，遵循其范围。

## 2. 原生创意的基本单位

有人产品故事先在内部写完这六格，再扩展镜头；不必把内部草稿全部交付：

> **谁在记录** → **什么小事值得拍** → **观众会怎么误判** → **画面已留下什么证据** → **产品凭什么改变局面** → **谁的态度或什么状态发生变化**。

无人产品反转改写为**观察视角 → 可见冲突 → 对物件/空间/结果的误判 → 前置线索 → 产品因果 → 可见翻案结果**，不硬填人物情绪。纯内容先写**谁会看 → 起始问题/状态 → 观看回报 → 中段怎样推进 → 结尾如何兑现**；不为了填格子虚构误判或产品。双轨故事会可以由旁白承担叙事、手部过程承担感官回报；明确标作双轨讲述，按 [全场景方法](nativeShortVideo/allScenePlaybook.md)检查两轨，不能冒称手部画面证明了口述事件。

### 原生视角

优先桌面静物、局部结构、柜内固定镜头、无身体倒影的主观视角或手机录屏；人物配额内再考虑自拍吐槽、车内自曝和镜前准备。视角要回答：**拍摄者为什么此时拿着手机，为什么暂时看不到答案？** 模拟偷瞄感可由演员配合完成，不默认偷拍陌生人或暴露私人信息。

优先押金要被扣、面试快迟到、室友误会、东西被弄坏、做饭穿帮等可立即理解的小损失。不要为了「强冲突」自动升级成公司瘫痪、生命危机、全场围观或反派咆哮。熟人关系不是固定人设标签，少用职业、族裔、性别刻板印象代替冲突。

### 前三秒的目标：让刷到的人迅速找到继续看的理由

创作前读取 [前三秒钩子方法](nativeShortVideo/firstThreeSeconds.md)。先确定目标观众与观看回报，再选**画面主导、文字主导、画面与文字配合、声音/对白触发、结果/过程主导**。不把“画面一定优于文字”作为规则；文字可以承担主钩子，声音可以触发注意。产品故事的画面提供实际冲突证据，纯过程提供可感知变化；双轨故事分别检验讲述与感官过程。

**产品故事与情境解围的画面与文字必须共同形成具体冲突**：画面显示动作受阻、说法与行为不符、预期与实际结果不同，或两个难以同时成立的状态；文字补关系、规则或利害，让观众知道矛盾在哪里。二者不必字面唱反调，不能靠故意说假话制造冲突。内部明确写出“本应X，但画面出现Y，所以观众等Z”。如果Y只有字幕宣称、镜头拍到的却是普通产品/纸卡，退回重写。静态画面只有本身包含可比较的冲突证据才可用；文字主导不等于文字包办剧情。

教程、观点、治愈和ASMR可从明确方法或过程回报开场，不强造冲突：首屏拍到值得观察的变化，并说清观众会学到什么或看到什么完成。双轨故事会首句建立具体事件与问题，字幕保证静音可读，画面提供真正持续的操作过程；分别验收，不能用切沙画面补救无关或空泛的故事开头。

开头独立通过三项：**快速理解发生什么 → 目标观众值得关心 → 有值得继续看的答案或过程**。只有奇怪、只有一句提问、只有三个时间节拍，都不足以通过。不能靠后半段反转、自评分或“强钩子”标签补偿。

每条明确真实首帧、准确首屏文字与声音，以及0–1/1–2/2–3秒的连续内容。时间轴用于检查，不要求每秒新动作或三次切镜；短文字被理解、同一过程持续推进也可形成节拍。需要展开候选时，用[机制库](nativeShortVideo/hookPatterns.md)的“观众/任务→主机制→首屏证据→文字或对白→待兑现回报→结尾答案”逐项构思；视觉、声音、文字、未完成过程是可选维度，不是强制四项同时出现。首屏优先一个焦点与一个核心问题，画面、文字、声音各补缺的信息，不同时讲三件事。

**封面与开头分开**：封面用于点开，视频首帧与前三秒用于刷到后的继续观看；不能假设观众看过封面或发布文案，不能用封面卡取代正在发生的事。用户要封面时单独交付，不默认加静态片头。

文字优先一句具体关系、利害或回报，按目标语言试读；双语解释用于方案说明，不默认全部叠到成片。静音检查保留计划字幕，检查画面+文字能否形成同一个观看动机，不机械要求纯画面讲完整故事。

内部截断在3秒，检查“看懂什么、为什么在意、等什么”；再猜结尾，淘汰容易猜穿且没有过程回报的套路。举尺子却藏住对象、普通封条配悬疑声、装睡听到饮料就醒、分饼干后贴俏皮标签，都不能因有疑问而自动通过。详细失败诊断见参考文件。

隐藏产品不能连矛盾一起隐藏；无人配比不能成为接受弱案的理由。若约束让某个故事开头失效，换故事，不擅自取消约束。结尾必须兑现首屏承诺，不能前面刺激、后面无关商品。案头合格不等于实际留存已验证。

## 3. 先区分机制，再决定怎么拍

本节评估产品故事的反转与融合。纯内容不必有产品角色；口述反转在讲述内检查公平线索，教程、观点和感官过程按 [全场景方法](nativeShortVideo/allScenePlaybook.md)评价，不套下表的产品因果字段。

| 机制 | 观众的变化 | 产品角色 | 是否可称欧·亨利式反转 |
|---|---|---|---|
| 误会重释 | 对归属、身份、输赢或责任的判断被证据推翻 | 纠正误判的证据或改变结果的媒介 | 须通过下方强反转门槛；解释异常成因不自动算 |
| 秘密工具暴露 | 以为是天赋、忙碌或神秘行为，原来有工具协助 | 隐藏的能力来源 | 仅揭晓工具属于原因揭秘；须另有判断被推翻才算 |
| 关系/动机翻转 | 受害者成为设局者、指控者成为犯错者等角色改判 | 使角色选择及后果可见的媒介 | 善意解释、准备惊喜不自动算；须有翻案证据 |
| 产品造成麻烦 | 功能作用在不合适对象上，引出小损失或笑点 | 肇因或意外后果的来源 | 只有前序含义改变才算；否则是功能笑话 |
| 困境解围 | 麻烦仍是真麻烦，只是被产品解决 | 解法 | 否，标注「情境解围」 |
| 对照/感官兑现 | 脏变干净、乱变整齐、按下出现结果 | 演示对象 | 否，标注「结果演示」或「ASMR」 |

默认反转创意先用前三类，必要时探索第四类；用户明确选择混合样本风格、解围或演示时，可用后两类并诚实标注。指定 N 条欧·亨利反转，就不能用功能演示凑数。

### 强反转门槛

产品反转默认按此验收；用户说“欧亨利”“更意外”“推翻理解”时逐条执行，不能用原因揭秘或感官演示补足数量。教程、治愈与直接演示不受此门槛约束。详细反例与检查见 [反转质量判定](nativeShortVideo/reversalQuality.md)。

先写一对可被画面检验的判断：**观众以为A；结尾证据E使A不再成立，并支持B。** “他做了X，因为Y”通常只补原因；须指出被否定的具体判断，而非把任何后补信息称为重释。优先改变归属、身份、责任、胜负或行动的实际后果；这些只是可选方向，不是保证有效的模板。

结尾必须有一个看得见的选择或结果，让前面的动作改义。至少一个公平伏笔在揭晓前可见，第一次合理支持误判，第二次能读出另一层意思；不靠最后新加的规则、关系、道具能力或未出现的第三人翻案。前3秒必须已有具体冲突，不能把铺垫全部藏起来。内部做反证检查：删掉解释语，A是否仍被推翻？如果A与结尾可以原样同时成立，或只是“原来在等人/送礼/关心”，退回重写。

反转内部结构：

> 观众因 **X** 以为 **A**；前面可见 **Y**；产品的已知能力 **Z** 揭示 **B**；第 **n** 镜的 **具体动作** 因此从 **原含义** 变为 **新含义**。

**结尾必须有可见的翻案证据**：先明确观众原判断A，再写同一对象/动作被怎样的镜头证据改判为B。可以是位置关系显露、原动作得到不同结果、角色做出与预期相反的实际选择，不能只出现一句解释字幕、旁白、台词或纸条。删掉最后的解释语，画面仍须支持核心转向；身份、称呼等细节可由文字补足。把字幕抄到道具纸上，不等于画面证明了反转。

检查：误判能自然形成吗？伏笔在揭晓前真实出现吗？结尾是否重释前面的动作？产品为什么不可随便换成另一件商品？二刷是否能找到线索？

仅在结尾摆商品、开盒看见产品、突然出现新人物解释一切，均不能通过。独特性可以来自产品的交互方式、形态和使用情境，不需要虚构独家技术；如果普通纸条、普通杯子就能原样替代，产品融合还不够。区分品牌/型号特有、品类相关、任意商品可替换：气泡饮料的分享或开罐声可算品类因果，不能冒称某品牌独占；任意商品都不影响故事时重写融合。

## 4. 产品露出、揭晓和循环分别处理

先分别记录**首次可辨认产品/界面、功能或身份揭晓、商业意图显现**。没有推荐话术不等于零产品；遮 Logo 不必然隐藏软件身份。

本节的产品露出规则只用于产品推广。纯内容记录故事答案或过程完成的位置即可；作为生活道具出现的物件不自动成为推广产品。教程可先示小结果再教方法，治愈过程可自然结束，不必等到70%处人为制造高潮。原生表达是内容形式，不授权伪造真实经历或隐藏必要的广告披露。

### 默认：最后一镜揭晓

保留原有的严格模式：**产品首次可辨认的画面位于最后一镜，与故事答案一起出现。** 翻牌前不露可辨认部件、包装、品牌名、倒影或产品名字幕。可见产品作用的结果，但最后交代其真实来源、对象和空间关系。

「最后一镜」不等于「最后一秒」。可让最后一镜从全片约 70% 处开始，在同一连续镜头中完成揭晓、最短必要演示和短反应，直到结束；揭晓后不再切回新的剧情镜头。镜头长度按动作决定，70% 是参考位置，不是逐帧配额。最后一镜不够看懂时，压缩前段铺垫，不能牺牲答案。

例如 16 秒：0–2 秒异常，2–7 秒误判，7–11 秒增加证据，11–16 秒最后一镜揭晓并容纳反应。更短更有力就缩短，不为拖到比例重复同一个冲突。

### 用户指定的其他模式

- **样本式「70% 揭晓，之后反应/循环」**：允许揭晓后独立反应镜头；仍不默认提前露出产品。若用户另有「最后一镜」要求，优先将揭晓与反应合并到同一镜头。
- **产品可见、用途保密**：适用于用户允许产品提前出现的隐形功能、伪装物或用途揭秘。分别标明首次露出和功能揭晓，不能声称「前 70% 零产品」。
- **直接演示/UGC**：按用户要求尽早展示产品、动作和真实结果，不伪装成反转。
- **硬广尾板**：用户要求时可在故事揭晓后加独立尾板，明确标作广告段；最多一个已知卖点，不用广告补救缺失的反转。

### 循环是剪辑关系，不是结尾口令

优先做「结尾动作回到开头动作」「末帧与首帧构图匹配」「末尾声音引出开头事件」；语句循环只有把尾句和首句连读自然才用。不能每条都以「因为——」收尾。

写清首帧/首句、末帧/尾句和实际接点。默认最后一镜模式靠末帧呼应首帧或声音衔接实现；不在揭晓后追加剧情。循环破坏因果时保留清楚的结尾，标注自然结束即可。重看价值首先来自伏笔，循环本身不保证留存。

## 5. 单手机拍摄是默认硬约束

“低成本”必须体现在实现方法里，不能只在末尾写“手机即可”。产品本体与已有生活物件可以入镜，但不得偷偷加入第二台手机、灯组、稳定器、外接麦、微距镜头、投影设备或电脑作为制作前提；被推广的产品本身除外，产品所需运行环境也必须如实列明。

- **设备与光线**：一部手机，默认普通录像、内置录音与手机基础剪辑。用窗边自然光或现有室内灯；手持或靠书本等稳固摆放。支架只可选，必须同时给无支架拍法；不以暗室弱光、极小细节或远距离收音作为成功条件。
- **场地与人手**：一个现成生活场景，优先一人自导自拍；确需互动时最多两名参与者，演员兼拍摄，不另算一个隐藏摄影师。手机固定后再入画；同一镜头不能要求同一个人既持机移动又在远处表演。一个手机不等于必须一人，但要写真实总人数。
- **道具与准备**：产品外最多三件常见、已有物件，不默认购买、定制、破坏昂贵物品或复杂搭景。优先随手能摆好和复位的动作；依赖长时间等待、反复碰运气或精密机关的方案先简化。
- **镜头与后期**：默认3–6镜、1–2个手机摆放位置，顺序分次拍即可，不需要多机位同时拍摄。以硬切、裁剪、短字幕、简单配音完成；不依赖绿幕、抠像、跟踪、擦线、定格动画、3D或AI生成。前三秒靠动作与信息差，不能靠制作奇观。
- **无人实现**：优先静态物件关系、真实正常作用、画外一次推动或一次停机替换。必须说明固定手机与画外操作位置；需要擦掉手/线、逐帧搬物或遥控机关才能成立时，默认重写。
- **手机也是道具时**：拍手机屏幕优先用该手机自带录屏，另拍的实景再简单硬切；不能让唯一手机同时充当被拍道具和摄影机。需要它出现在同一实拍画面里时改构图或改情节，不能暗中加第二部。
- **软件题材**：仅在确有可用移动端时给手机录屏，不虚构移动版或手机功能。桌面专属工具的运行电脑是额外依赖，不能包装成“一个手机全搞定”；说明冲突，给不冒充功能演示的可行手机方向，或等用户明确允许桌面录屏再用该模式。

### 创作流程

1. **路由目标与条件**：确定三种目标之一、内容类别、出镜要求及载体；先分配至少70%完全无人名额，再在各名额内构思，不能先写全人物剧再裁掉脸；再收窄产品能力或纯内容主题。区分用户提供的能力、待确认的性能和纯剧情设定。缺型号时不编造延迟、续航、功率、售价、治疗效果或测试数据；选无需这些承诺的情节，必要时列「待确认」且不在观众文案中当事实使用。查新样本时选1–2个KB/DD近邻，借结构而不照抄效果。
2. **选一个生活矛盾或过程回报**：明确人/物、记录视角和观众关切。产品故事先写因果链，再定结尾答案，倒推可见伏笔与开场动作；纯内容按故事问题、教程步骤、观点示例或感官完成组织全片。
3. **拉开创作机制**：多条产品故事按“初始判断→翻案证据→改判结果”比较机制，不能仅改变误判来源的措辞；纯内容改变核心问题、步骤组织或过程回报。只换演员、地点和台词不算新机制。五条都拍微距残渣再露牙模，也只算一种。“数口数等碰杯”与“倒计时等开罐”仍是同一个结尾机制。
4. **先验收前 2–3 秒**：内部比较 3 个不同钩子机制，按第 2 节理解、关切、继续观看三项逐项检查；没有具体观看动机或结尾不兑现的版本直接重写。选定开头必须交付主导通道、首帧、准确文字/声音、时间节拍与具体观看动机；用户要单条完整脚本时可展开三个备选；多条完整创意默认只交付各条选定开头，除非另要备选。不能把自评分当实际停留率。
5. **做减法并写完整画面**：按上述单手机限制，一个场地、最多2名参与者（含幕后）、3件已有道具（产品除外）、3–6镜、1–2个手机位置。含产品在内的摆放和操作均要可解释。超过预算先缩成单房间、画外声、局部镜头；用户指定高规格时才放宽。

中段每镜至少增加一项：有依据的误判、失败原因、提前伏笔、故事新线索、教程关键步骤或过程新状态；反复着急、重复尖叫、不断放大倒计时只留一次。不能靠拖延答案填到70%。

每镜写：**机位/景别 → 主体位置 → 单一动作 → 可见结果 → 衔接**。避免「发现秘密」「震撼反转」「产品特写收尾」独自充当画面描述。

录屏整条覆盖**初始状态 → 光标目标 → 实际操作 → 输出变化 → 核对依据**。严格最后一镜模式可先用通用任务文件建矛盾，最后连续录屏揭晓工具；不能把可辨认界面当零产品。模拟界面、虚构任务数据标为演绎，不冒充真实产品能力。

实拍写清手机固定位置、遮挡/同轴切镜方法、操作者位置；无人方案明确画外一次推动、支撑或一次停机替换的具体办法；不默认遥控装置。不能说「道具自己动」。声音型误判配一个可见同步线索，音效不替代证据。

只有用户明确要 AI 制作或更高规格时，才采用 AI 路径，并说明已超出默认单手机实拍；写明人物/场景/产品参考图需求，关键镜头给可复制描述：主体外观、布局、景别、一个动作、镜头运动、结束状态。沿用同一参考，复杂操作拆成前后镜；商品外观优先真实图片/实拍，品牌文字后期叠加。控制生成镜头数和合成负担，不把「AI 能做」当低成本依据，也不把生成的效果当实测。

每条用一行制作清单列：一部手机、总参与人数（注明兼任）、场地、已有道具、手机摆位、手机内剪辑步骤及最难一步怎么简化；不编市场报价。剪辑压缩长过程要在涉及效果证明时标明延时/剪辑，不能把现实耗时冒充成视频几秒。

## 6. 样本迁移的边界

产品故事迁移「情境—误判—动作—后果」，纯内容迁移「入口—进展—回报」，不迁移无依据的性能和伤害性操作。新样本中的几类常见错误要主动修正：

- 功能偷换：不把降噪写成过滤说话者的抱怨、把压缩收纳写成除湿治疗、把冲出残渣写成消除蛀牙、把折叠杯写成绕过安检规则。
- 虚构证明：不把巨量毛球、即时变白、照亮整座山、零泄漏等夸张情节当真实结果。镜头实际显示什么，就只支持什么；模型演绎标明模型，不外推真实效果。
- 危险桥段：下药整蛊、给睡着的人封嘴、真人试刀、跳踩鸡蛋、飞踹房门、高速车上测试、宠物挣扎等不进入可执行拍摄方案。保留戏剧机制，改成软道具、受控静态展示或无伤害误会；不能只贴「请勿模仿」继续写危险拍法。
- 借口造假：不编造真实顾客评价、盗窃记录、医疗结论、销量或原视频播放量。剧情角色可有虚构日常经历，不能冒充真实见证。
- 互动不造假：不继承样本“故意专业错误引战”的建议。用户需要评论设计时，用真实使用取舍或待验证问题，不编评论、禁令、收益和鉴定结论。
- 软件不跨步许愿：生成内容不等于正确输出，输出不等于商业收益；保留检查步骤，不把引用链接、精美图表或模拟进度当验证。
- 名字不是证据：创作无需研究时按已知事实写；确需性能、法律、医疗或真实爆款数据时先查适用的可靠来源。找不到证据就不写对应断言，而不是照抄样本。

## 7. 交付格式

### 多个创意

先一句说明内容目标、产品信息或主题假设、出镜配比和揭晓/完成模式。出镜标签细分完全无人、仅手部、不露脸身体、露脸；不露脸身体仍计有人。每条加一句是否需表演，默认无需演技。使用新样本时可用一行给出KB/DD编号与借用机制。每条合并成以下四块，减少重复：

1. **标题｜机制｜出镜方式**；有屏幕文字时给英文与中文意思，说明成片选用语言。单列 **前3秒：主导方式 / 首帧 / 首屏文字与声音 / 0–1、1–2、2–3秒 / 为何在意与等待什么**；可与第1镜合并，不能只写“强冲突开头”。
2. **观看回报与答案**：反转写观众误判、公平伏笔、具体哪一镜被重释、产品角色；明确结尾哪一个可见动作/证据推翻原判断，不能只写结尾金句。解围/演示写原问题、产品动作与结果。纯内容写故事答案、可复用方法、观点适用范围或过程完成状态；双轨写清旁白进展与画面进展，不硬造误判。
3. **3–6 个编号镜头**：全程画面和大致时间；产品模式标出首次可辨认、功能揭晓及反应发生在哪一镜，纯内容标出答案/方法/过程完成。给结尾与开头的实际接点，或注明自然结束。
4. **怎么低成本完成**：默认手机实拍或手机录屏，给手机摆位、谁按录制、谁操作、总人数/场地/已有道具/镜头数、手机内剪辑方法；确有未证实能力时说明如何避开依赖。

最后推荐一条先拍，理由具体到道具、动作和观看回报；产品故事补误判与产品因果。除非用户需要投放套件，不额外塞多个标题、评论区引战话术和长篇平台介绍。

### 完整脚本/分镜

输出：内容定位与核心回报（产品反转补误判与产品因果） → 单条脚本的 Hook 备选（多条完整创意省略备选，避免淹没正文） → 选定开场的 0–1 / 1–2 / 2–3 秒与观看问题 → 逐秒分镜 → 开头承诺如何兑现与结尾接点 → 制作清单。

用户要完整创意时，在回答正文逐条给完，不能用文件链接替代未展开的镜头。

分镜表列：时间、机位与具体动作、英文台词/中译、字幕/声音、信息推进或伏笔/揭晓作用、实现方法。产品模式单独标明首次可辨认时间与镜号；纯内容不填虚构产品字段。AI 脚本补关键镜头生成描述与参考素材需求；不宣称已拍摄或生成。

## 8. 交付前检查

- 内容目标与观看回报是否匹配？纯内容是否被硬塞商品、CTA、70%反转或无关冲突？故事会是否兑现首句问题，教程/观点是否给具体方法与适用边界，感官过程是否真实推进并完成？
- 遮住结尾，前 2–3 秒能否独立形成具体观看动机？0–1 / 1–2 / 2–3 秒是否写清实际视听内容及理解或期待的推进，而不是机械填三个动作？
- 产品故事前三秒“本应X、画面却Y、因此等Z”是否具体？文字是否补足实际冲突，而不是对着普通物件凭空讲戏？纯过程是否有可感知回报，双轨故事首句与手部过程是否各自成立？
- 对实拍产品反转，去掉结尾的解释字幕、旁白、台词和解释性纸条，是否仍能从镜头证据看出核心认知改变？若不能，不按该反转交付。双轨口述故事单独检查讲述内的伏笔与答案，不把无关手部动作当事件证据。
- 开场提出的问题是否被结尾兑现？有没有用不相关的刺激吸引注意，再强接商品？
- 主导通道是否适合这个故事？首帧和一句短文字能否迅速建立关切，是否误把静态道具、猜得中的套路或俏皮文案当强钩子？是否错误依赖观众先读封面？
- 强反转的结尾证据是否使原判断不再成立，而不只是补充原因？伏笔是否提前可见，且不靠结尾新增规则救场？
- 反转类是否真的重释一个旧动作/线索？产品故事的证据是否预先可见，拿走产品因果是否断裂？口述故事是否有讲述内伏笔？有没有把普通解围改名为欧·亨利？
- 产品故事默认最后一镜才首次可辨认产品，且无部件、字幕、反射泄露？若使用其他模式，是否来自用户要求？纯内容不套产品露出检查。
- 最后一镜是否留够答案和反应时间？循环连起来是否自然、有因果，还是只加了「因为」？
- 每条是否真的能用一部手机拍完并在手机里剪完？是否藏有第二手机、额外摄影师、电脑、灯组、特殊镜头、定格或AI制作依赖？道具和手机能否同时处于所写位置？不满足就先重写，不能标“低成本”放行。
- 默认完全无人是否达到至少70%（5条至少4条、10条至少7条）？其余是否优先仅手部/不露脸操作？是否未经用户要求安排露脸或依赖表情演技？无人方案是否确实无手、身体、人像、倒影，并解释运动来源？多条机制是否不同？
- 中段是否逐镜增加信息？录屏是否读得清、跟踪同一输入输出、说明模拟和加速？是否将品类能力误说成品牌独占？
- 是否把样本的数字、危险行为、虚构场景或夸张效果当作了真实产品证明？
- 新文档的风格/算子是否只作创作选择？是否为固定跳切、荧光跳字、三轨音效或强行语句循环牺牲了可读性、过程和答案？

失败时重写对应部分，不靠标签、自评分或附加广告补救。
