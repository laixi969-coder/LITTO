# Faceless 与纯录屏：从可读任务到可验证结果

> v3.2.1 制作约束：默认单手机实拍或手机自带录屏，手机内完成基础剪辑。下文桌面示例仅适用于用户明确允许电脑录屏的情况，不属于默认单手机方案；不能假设桌面工具存在移动版。

v3.5.0扩展：本文件的产品揭晓与反转证据要求适用于推广故事；纯录屏聊天喜剧、观点图解、治愈过程及双轨故事会按 [全场景方法](allScenePlaybook.md)选择回报，不强加商品或画面翻案。新样本的出镜误标与制作依赖可查 [KB/DD索引](sampleBankV4.md)：人物照片、线描人像、像素人形和短剧演员均不能计入完全无人。

## 1. 先标两轴

- 出镜：完全无人 / 仅手部 / 有人。画中画、照片人像、数字人、AI 人形与倒影都检查；不露脸不能自动算无人。
- 载体：实拍 / 录屏 / AI / 混合。录屏不必无人，无人不必动画。宠物另外标注。

默认至少70%完全无人：5条至少4条，10条至少7条；其余优先仅手部或不露脸操作，默认不需要露脸演技。比例按创意数量计算。用户明确只要 Faceless 且未严格要求完全无人时，可以包含手部，但每条写清；不能将这些计入“完全无人”数量。

## 2. 软件和实体商品用不同镜头语法

实体镜头：机位 → 主体位置 → 单一动作 → 可见状态变化。
录屏镜头：**初始界面状态 → 光标目标 → 实际操作 → 输出变化 → 核对依据**。不必每镜重复全部五项，但整条必须覆盖。

一镜只突出一处证据：错误提示、差异行、选中区域或输出结果。竖屏裁切后保留上下文，不能只剩数字而不知数字代表什么。字幕给关系，界面给证据，不把长聊天、长旁白和三行小字同时塞进前三秒。

准备自有或获准使用的数据，关闭不相关通知。虚构聊天、演示界面、预置状态必须标为演绎/模拟；模拟界面只能表达拍法，不能用来证明真实产品能力。录屏所需权限、输入格式、处理耗时与输出质量按实际条件确认。

## 3. 三个露出时间分别记录

1. 首次可辨认产品/界面；
2. 功能或答案揭晓；
3. 明确介绍/推荐产品。

没有推荐话术，不等于没有产品。遮住 Logo 也不必然不可辨认。严格最后一镜模式：前段用通用任务文件或结果证据；最后连续录屏中切到实际工具并完成操作与检查，后期不再剪出独立新镜头。如果必须提前操作产品才能懂，就换故事，或按用户已允许的演示模式执行。

## 4. 一个完整拍法示例：多出来的一位数

**用途：演示已确认支持“清除数字字符串中的分组逗号”的文本处理工具。** 无指定真实品牌、无性能断言。以下是通用脚本模板；实际拍产品前需先用所选工具验证示例。它是任务解围，不是欧·亨利反转。完全无人、纯录屏；20 秒，4 镜，默认最后一镜首次可辨认工具。

顶部文字：`The amount is right. Why won't it import?`（金额没错，为什么导不进去？）模拟任务窗口角落持续标注“演示数据 / 模拟导入”；不是声称真实报错记录。

**前三秒：** 0–1 秒，导入按钮旁已出现红字“仅接受整数数字”；1–2 秒，错误行高亮 `1,250`；2–3 秒，光标划过四个数字，停在中间逗号。观众的问题：究竟哪里多了一位，怎样改格式又不改金额？这是可读错误，不需要假老板威胁开除。

| 镜头 / 时间 | 画面、操作与声音 | 信息作用 / 实现 |
|---|---|---|
| 1 / 0–3秒 | 竖屏裁切一个模拟导入面板；红色提示与单行数字同框。光标从数字划到逗号，轻提示音一次。 | 错误与数据关系可见；使用自制静态页面模拟状态，标明演示，不假装产品原生界面。 |
| 2 / 3–7秒 | 切到通用纯文本窗口，同屏仅三行：`1,250`、`2,000`、`350`。光标选中第一行逗号，再扫过第二行同位置；字幕“不是金额错了”。 | 一处错误变成同类格式问题；不能把三行改成假称十万行。 |
| 3 / 7–12秒 | 复制三行；旁边小对照区显示目标格式示意 `1250`，原始文本仍留在左侧。光标悬停，不显示隐藏工具。 | 明确要改的字符与要保留的金额；无需重复错误弹窗。 |
| 4 / 12–20秒 | 一段连续录屏切到已验证的真实工具，首次可辨认产品；粘贴输入、运行清除分组逗号、展示三行输出。继续在同镜内并排对照：`1,250 → 1250`、`2,000 → 2000`、`350 → 350`。字幕“格式变了，金额没变”。 | 产品解决同一格式问题；保留输入输出与核对。操作超过8秒就延长镜头，或明确加速，不能拼成即时能力。自然结束。 |

拍摄配置：出镜0人，幕后1人，一台电脑，零实拍道具；录屏后裁切与添加字幕即可。先录完整实际操作再估时。不能把所有地区的逗号都当千位分隔符，也不能无条件删除小数逗号；本例预先限定为这三条整数演示数据。

这条的成立点是“同一任务、同一数据、真实处理、可核对结果”，不是反转。若用户要欧·亨利，应另写能重释旧动作的故事，不能改一个标签交差。

## 5. 无人实拍优先级

先在无人名额内选表达，不把人物吵架藏在画外、让字幕代演，或仅裁掉脸后算作无人。优先：物件的空间/归属/数量误判、可见操作受阻、同条件对照、真实过程完成、无人物素材的手机录屏。它们是选题入口，不保证每一种都产生反转；强反转仍按 [反转质量判定](reversalQuality.md)验收。默认一名幕后操作者，旁白可选，不安排多角色争吵配音。裁切、扩大视野或普通硬切可以揭晓空间关系，但不得偷偷更换决定性道具伪造连续证据。

用户要求全是强反转时，保留该质量要求与无人配额，不用演示、冷凝原因或露脸剧情补数；重写故事机制与物件关系。用户未限定全是反转时可混合演示和过程型，必须明示类别。


**先过画面证据关，再选拍法。** 内部明确“本应X，实际Y，等Z”和“结尾证据E如何使判断A变B”。不能用色卡、杯子、纸条的静态陈列配字幕包办情节；结尾新增一张解释身份/动机的纸，不算拍出了反转。具体退回案例见 [前三秒方法第9节](firstThreeSeconds.md)。录屏也一样：实际操作及结果能支持结论，不能只换一行成功文案。


默认先选真实状态差或产品正常作用，再考虑画外一次推动或一次停机替换；需要遥控机关、擦线、定格或生成才能成立时，重写成单手机可完成的动作。只有用户明确要求这些制作方式才采用。写清操作者藏在哪里、哪些画面来自剪辑。画外手推导致物件动，可以构成剧情；不能声称是产品自动驱动。用冷凝水、光影、声音等时，核对等待时间与现场可见性，避免小滴水被写成瞬间瀑布。

产品不必每条都“活过来”。一个真实卡住的结构、一行反复失败的数据、一个差一点合拢的物件，就可能提供观看动机。若只有奇怪，没有观众关心的结果，仍退回修改。

## 6. 发出前检查

前三秒在手机尺寸能读懂吗？观众等待的结果具体吗？中段每镜是否增加证据？输出有原始输入可核对吗？人物有没有藏在界面里？首次产品露出是否诚实标注？模拟/加速是否被冒充实测？结尾回答的是开头那个问题吗？
