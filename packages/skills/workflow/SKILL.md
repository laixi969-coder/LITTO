# MILI MILI 画布制作工作流

从用户已有内容接续，把成果放到当前 MILI MILI 项目。以本次剧本与真实素材组织制作，不要求用户先补齐一套制片文档。这个包包含所需方法，不依赖原来的多岗位 Skill 组。

## 从哪里开始

从想法创作故事或剧本时先读取 [story](../story/SKILL.md)，短剧分集按其中的专项选择规则处理。TikTok、Reels、Shorts、带货/UGC、软件推广、纯内容涨粉、Hook 或 hiccai-pop 改用 [adfilm 的原生短视频方法](../adfilm/references/nativeShortVideo.md)；仅要拍摄方案或文字创意时直接交付，不默认调用生成模型。主 Agent 按作品目标选主方法并主动推进已授权阶段，不将电影、剧集、短剧的所有模板同时强制执行；已有定稿继续按制作提取流程，不重新立项。

沿用用户确认的影片定位、世界、视觉、资产、时长和版本。电影使用 [cinema](../cinema/SKILL.md)，产品广告使用 [adfilm](../adfilm/SKILL.md)，跨镜状态使用 [continuity](../continuity/SKILL.md)。Music Film 以音乐、歌词、章节和确认的视听方向组织，不能套用剧情片的固定分段或拒绝有意的节奏剪辑。

先读现场模型和节点能力，再决定执行方案。用户未指定模型时提出基于真实能力的选择，不强制 Seedance、竖屏或固定时长。只问影响结果且未知的缺项；已有模型和参数不重复询问。

## 通用制片与模型规则

### 剧情推进与实际演绎

剧情制作先按[输入与剧本](references/sourceAndScript.md)落实可拍场景，再按[表演指导](../cinema/references/performanceDirection.md)设计目标、身体任务、触发反应与相对位置/走位。镜头用视点、遮挡揭示、动作反应和剪点传递信息，不只靠摄影机移动和旁白串联图片。对白逐句从采用剧本分配到 creativeBrief.dialogue，核对原句、说话人、声音通道与时间；无对白镜头留空不代表可删掉整场台词。

紧凑以事件、信息和关系变化判断，不强迫快切，不因固定机位判为 PPT。慢戏、空镜和静止须有作用，不用呼吸、眨眼、衣发微动填满时长。按源节拍拆合镜头，保留事件顺序和对白；规则草稿未补设计不得当正式分镜。成片完整看听时核对 narrative、performance、dialogueCoverage、editing，记录时间点证据；无人、无对白和非剧情作品说明实际适用范围。草图配音预演始终标预演。

### 启动时落实验收标准

质量要求从第一版方案进入现有 World/Look、资产与 ShotSpec，不等出片后再提出。只补本次缺项，复用已确认内容，不新增检查表文件、审批阶段或独立审稿调用。生成前按下表把后验问题转成可执行设计；没有角色、对白、产品或跨镜依赖的任务跳过对应项。

| 需要避免的返工 | 生成前落实的位置与内容 |
| --- | --- |
| 身份、服装、商品结构漂移 | 已采用资产与真实参考绑定；区分身份、造型、产品和风格用途，写清保持项、允许变化与变化时点；核对实际发送的参考，不能只在文字里声称锁定 |
| 肤质、场景材质或光线不符 | World/Look 与 realism：材质各自的纹理和反光、景别可见细节、当前时段真实光源；已有合格母图直接复用，不重复做风格探索 |
| 动作失控、表演空泛或时长不足 | action、performance、camera.design 或 musicVideo.timeline：动作触发、接触、反应、起止状态和可执行节拍；一份时间线，先解决互相矛盾的描述，再生成 |
| 换装、持物、空间或邻镜光向穿帮 | assetIds、intendedStateDelta、lighting 和摄影设计：承接实际已采用末态，明确有意变化；compile 的连续性提醒在生成前处理，规划末态不能当成实际观察 |
| 对白丢失、声音方案冲突或接缝难剪 | creativeBrief.dialogue、声音方案与剪辑入出点：核对说话人、原文、时段和模型能力，保留动作与发音所需余量；有意静默不当缺陷 |
| 规格错误、参考被丢弃 | compile 返回的实际提示词、inputs、warnings 与模型参数：一次处理全部适用缺项，锁定参考不能降级后照常生成；更换模型或付费范围沿用已有授权规则 |

这些标准用于设计与请求检查，不要求生成模型自行质检。提示词只保留本镜具体执行内容，不重复贴完整规则或后期验收清单。确定性的缺项由程序校验；构图、越轴、节奏等提醒由助手结合创作意图判断，已记录的有效决定不重复询问。

### 用最少的生成获得可用成片

- 复杂动作、新造型或产品交互存在共同风险时，先用代表性样镜验证再扩展；已有合格样镜直接复用，简单镜头不额外增加试拍。广告沿用下文已有样镜定标要求。
- 无状态依赖的资产与镜头按已授权批次及时提交，在实际工具与供应商并发限制内执行；只有需要前镜尾帧、实际末态或共同样镜采用结果的后镜等待，不因镜头编号逐个等待。先完成各镜规格、参考与必要采用，再取得各镜 compile 的 request，在同一轮集中调用 generateImage 或 generateVideo；不要与串行的 productionSpec、确认工具混在同一批调用。画布节点返回 generating 后继续启动其他独立节点，再检查各自结果；同镜同请求不重复提交。
- 生成后核对实际偏差：多肢、身份/商品错误、关键剧情或对白缺失须处理；审美建议不自动重生成。先看已有候选、剪辑入出点或声音调整能否解决，只重做受影响素材，不整批返工。
- 媒体、相关规格和检查范围未变时复用已有检查依据；修改声音只复核声音及同步影响，换一个镜头复核该镜与相关接点。实际改动涉及身份、剧情或跨镜状态时扩大到真正受影响的部分，不能沿用失效验收。
- 不另增默认重试次数，遵守已授权上限。同一原因连续失败先改动作、参考或镜头方案，不原样反复抽卡；超出预算保留成果并说明缺项。工作版与正式验收分别标记，前置校验不代替真实输出检查，也不代填完整看听记录。

广告与品牌片在生成前读取 [adfilm](../adfilm/SKILL.md) 的真实导演方案流程：保存序列类型和 `adDirection`，参考片用 `analyzeReference` 实际分析，每镜关联 `advertising`，先检查并采用指定视觉样镜再量产。`readAdDirection` 返回是否已定标；产品独立镜头也须有 `creativeBrief`。成片先做 `inspectFinal`，再用 `inspectAdFilm` 比较整片表达、产品和邻镜光色。用户已授权的范围直接继续，不为这些内部步骤要求重复确认。

电影、短片、广告、MV 与独立视频共用同一套视觉设计入口：初次制定或修改视觉方案时，有场景就读取[视觉设计](references/methods/visualDesign.md)，确定配色或布光就读取[色彩与用光](references/methods/colorAndLight.md)，有人物妆发服饰就读取[妆造设计](references/methods/characterStyling.md)；已有适用方案直接继承。广告另外使用 [adfilm](../adfilm/SKILL.md) 的产品展示方法。按本次对象读取，不因不是 MV 就跳过，也不为无人产品图增加人物造型。

生成前核对最终请求，而不只核对聊天里的方案：场景的空间/陈设/材质/维护状态、资产本色、实际光源、后期色彩、当前妆发服装及参考用途是否相容；不适用项跳过。有 productionSpec 时检查 compile 返回的提示词、参考与降级；普通节点则检查实际节点配置、提示词与输入图片。未经说明的做旧、疲态、湿地、雾尘及与当前时段冲突的影调先移除；用户明确需要的状态保留。只能检查计划与请求是否一致，不能代替生成后的视觉验收。

故事、MV 方向和视觉设计从用户材料与明确要求出发，不从情绪、曲风或电影感自动推导老旧、破损、污渍及人物的衰老疲态。未指定状态时，场景、服装与道具按符合年代用途、正常维护、整洁完好设计；AI 自己补出的细节只是提案，重复引用不能变成事实，用户纠正后须同步清除当前草案和待生成提示词中的冲突描述。

设计或生成角色资产前读取[资产制作](references/assets.md)。默认一次生成一张包含正脸妆造特写及全身正、侧、背面的角色设定图；复用已采用角色，不自动拆图、逐角度补图或因轻微差异重生成。资产直接使用 purpose=asset，不进入剧情镜头编译与逐镜质检链路。

电影或电影感镜头的摄影设计，先读取[专业摄影与剪辑方法](../cinema/references/shotLanguage.md)，再填写镜头规格和编译提示词；沿用当前 Look，不继承其他项目的手机、纪实或广告风格。Look 按时段与场景分档：当前镜头是日景、室内白昼或清晨黄昏时，按当时段的实际光源组织光色，不把夜档的低照度、色温与低饱和基底套到非夜景画面；项目 Look 只有一档影调且含日景段落时，先补分档再继续。

先形成镜头职责、摄影、表演、光线、起止状态、参考用途及锁定要求，再按实际模型能力编译提示词。只有用户明确选用或现场节点实际选定 Seedance 2.0/2.5 时，才读取[Seedance 模型规则](references/seedanceDirector.md)。这份规则约束对应模型的格式与执行，不能改写已经确认的电影或音乐创作意图。切换模型后退出专用规则，保留创作规格。

### 禁令：「写实」不是「做旧」

这是硬禁令，不是风格偏好。

**写实指材质可辨、光向明确、皮肤有肌理；不是低饱和、不是颗粒、不是压暗、不是磨损污渍。**

禁止在提示词里主动写「脏、旧、破、锈、污渍、油污、汗渍、剥落、斑驳、做旧、褪色、磨损、灰尘」这类状态词。剧本没写就不许加。模型会把你没说清的地方全部往旧里补，一句「磨得发白的工装」会被扩写成汗渍油污锈斑。

默认输出必须是：

| 项 | 默认 |
| --- | --- |
| 曝光 | 正常、明亮通透，中间调不压暗 |
| 色彩 | 自然准确，不刻意降饱和，不整体偏灰 |
| 皮肤 | 默认沿用清爽人物方法：自然均匀肤色、符合景别的细微纹理、轻薄妆面与克制高光；保留既定肤色、年龄和明确的特殊妆效，不以粗毛孔、黑眼圈或厚粉分界证明写实 |
| 服装 | 平整挺括、洗得干净 |
| 环境 | 有生活物件，但墙面地面干净，没有污渍霉斑 |

**唯一的例外**是剧情明确要求的状态（战损、废墟、贫民窟、角色受伤），此时在提示词里写 `DISTRESSED: 具体理由`，只影响该对象与当前时段。没有这行标记，`POST /api/ai/media/generate` 会直接拒绝。

判定「做脏做旧」的量化信号（`qc` 会自动报）：平均亮度低于 55、平均饱和度低于 8。遇到 `underexposed` / `desaturated` 先查提示词，不要靠调色补救。

### 资产先行：角色卡、场景、道具先于分镜

分镜之前必须先有资产，没有资产的镜头等于每镜重新选角、重新搭景。顺序固定为：

1. **拆资产**：调 `POST /api/ai/media/assets`，从已采用的剧本拆出角色、场景与道具清单（落盘 `assets/assetPlan.json`）。清单只收剧本明确写到的，不发明。
2. **出角色卡**：每个 `must` 角色先把定妆图做出来并采用，写进 `assets/cast/<角色名>.json`（含 `references`）。同一个人物贯穿全片，脸不能变。
3. **出场景定场**：每个主场景出一张定场帧，作为该场景所有镜头的共同参考，用于光向、材质与空间的一致。
4. **出道具**：只在剧情里起作用的道具才做，纯装饰不做。
5. **再进分镜**：以上采用后才开始写 shotSpec 与生成镜头。

开拍前调 `POST /api/ai/media/preflight` 核对：清单里几个角色、实际几份档案、缺哪些。缺口在分镜阶段会变成每镜漂移，那时候再补已经拍废一批。

先查询当前租户的实际图像能力；仅支持编辑时提供有效参考，支持文生图时可据已确认设计生成。教程或旧项目的模型名称不代表当前账号配置，不能虚构基准脸或静默切换模型。

### 镜头时长、身份锁定与生成后核对

生成前逐项确认，缺任一项不进入量产：

- **时长按内容和实际能力决定。** 查询当前支持时长，结合动作串并行、空间距离、反应停留和实测台词安排。字数只作未录音时的粗估，不按动作个数乘固定秒数，不因两次转折强制用模型上限。合段同时满足参考、声音、内部切镜和动作容量；不足时沿完整因果拆分，保留已定剧情与生成范围。
- **人物镜头必须传已采用的角色参考图**（`images` + `mode:["imageReference:N"]`），身份参考与场景参考分开，`notes` 写清各自管什么。没有角色资产时先生成资产，不用文字描述代替像素级身份。纯文本模式只允许用于无人空镜、环境、流体、光效等不涉及人脸的镜头；人脸镜头用纯文本等于每镜重新选角。
- **同场景的连续镜头共用一张定场帧作参考**，或用上一镜末帧作 `firstFrame`，保证空间、光向、道具位置承接。不靠文字写「同一个房间」。
- **生成后核对实际输出**：身份、当前造型、世界空间与光源；关键动作检查完整过程，声音实际试听。严重偏差先诊断并在授权内修受影响部分，不因轻微差异自动重跑；抽帧不替代完整动态，字幕不是发声。
- **台词时长按真实语速估算**；模型不支持原生发声时先落实配音通道，不删台词、不把字幕当已出声。

### 按当前镜头内容选择专业资料

以下匹配同时适用于电影、MV、广告和独立镜头；按当前镜头需要读取，不把所有资料机械叠加。已知需求直接应用，不要求用户手动选技能。

| 当前任务 | 使用资料与时机 |
| --- | --- |
| 准备提交生成、不确定该传哪些参数 | 读取[生成参数手册](references/generationParams.md)；六个参数（shotSpec／cast／styleReference／continueFrom／composeFilm／qc）决定底线质量，人物镜没有身份参考会被直接拒绝 |
| 定影调、选导演风格、需要可执行的色值比例 | 读取[导演色卡库](../directorPalettes/SKILL.md)；198 位导演的实测主色板（HEX＋画面占比）、情绪色板与光影特征，转成 `shotSpec.lighting` 与 `styleReference`。一镜只用一个导演的色板，主色由环境承载，肤色不被环境色污染 |
| 需要导演视觉语言、选画风、把口语需求补成规范提示词 | 读取[导演与视觉风格](../gavenDirectImagePrompts/SKILL.md)；按 Dxx 导演／Pxx 摄影／Cxx 胶片／Rxx 印片代码选风格并展开成自然语言。项目已有 Look 时以项目为准，不叠加冲突风格；画风代码只定影调与成像，不改剧情与人物 |
| 只要一份精简可读的逐镜提示词，不需要资产绑定与节点配置 | 读取[剧本转视频提示词](../gavenScriptToVideo/SKILL.md)；按动作因果与对白容量拆片段，逐镜写景别、运镜、时长、动作与表演。**片段上限以 listMediaModels 的真实 duration 为准**（如 MiniMax-H3 为 15 秒），该技能默认的 30 秒只适用于 Seedance 2.5 |
| 要成片级的完整提示词：资产绑定、摄影与光影、逐镜时间线、声音、负面约束一起交付 | 读取[视频提示词导演](../videoPromptDirector/SKILL.md)；按五板块结构写完 `final_video_prompt`，用 preflight 校验结构与总时长；按生成段创建视频节点，连接资产后读取 getConfig.references，用实际 `{{ref N}}` 标记绑定，再回读 generationPrompt。总时长在模型能力内且剧情可控时优先单节点；正式镜头仍走 productionSpec 编译，不以独立片段绕过。清爽人物同时读取其中 cleanPortrait 方法 |
| 旅拍婚礼、双人旅行或个人旅拍，需要选镜、删镜、换装 | 读取[旅拍影像提示词导演](../travelWeddingDirector/SKILL.md)；默认每镜 2 秒、4:3 写实、无 BGM，内置按镜号检索的镜头库与带版本管理的服装表。挑完镜头仍按 videoPromptDirector 的五板块成稿，不整库复制进提示词 |
| 小清新、自然光、清透色彩、湖边庭院海边树林 | 读取[光感小清新导演](../lightFreshDirector/SKILL.md)；按光源方向与时段组织光线，多镜头按动作与光线节奏分配而不是平均切分；镜头库按镜号检索，成稿规范沿用 videoPromptDirector |

| 多镜头、续作、局部重做、反打或跨镜动作 | 读取[连续性守则](../continuity/SKILL.md)，按实际状态承接身份、光线、情绪、道具与动作 |

| 真人 MV、生活类短片或宣传视觉中的情境人像、摄影样片 | 按下文[情境人像](#情境人像)组织已定稿角色的事件、姿态与摄影；只做身份资产时不启用 |
| 剧情 MV、短 MV、多图音乐编排、演唱或音乐卡点 | 读取 [MV 导演编排](../musicfilm/references/musicVideoDirection.md)，用开场问题、人物行动与回收组织故事，保存 musicVideo 时间轴与声音方案；精确同步须按实际音频与视频验证 |

资料用于补足当前 action、performance、blocking、camera 和剪辑计划，不改变已确认的媒介风格、模型、故事与生成授权。纯文字方案完成不等于已出图、已生成视频或已验收。

参考角色、服装、空间、影调和运动的用途分开记录。原生首尾帧、音频或多参考不受支持时说明实际降级和影响；不能仅在文字里标记已发送。已采用版本默认保留，更改另建候选并写清下游影响。

用户探索视觉方向时可用 readVisualReferences 查询精选导演画像与电影画面来源；readStoryProject 的 visualReferences 返回本项目收藏、用途和具体借鉴说明。按 composition/lighting/palette 转为当前 Look 与摄影方案，不把参考片剧情或身份搬进作品。文字评分不代表已经分析图片，电影画面不自动成为可投喂生成的资产；只有用户具备适用授权且模型支持时才实际绑定。收藏更新不静默覆盖已经采用的资产或镜头。

## 在画布上推进

制作默认在当前画布呈现。通过[画布执行](references/canvasExecution.md)读取目标节点、真实模型、模式、参考端口与输出。只做文字规划时不触发媒体生成。工作区沿用当前项目，不猜节点 ID、函数或供应商能力。

| 阶段 | 成果 | 参考 |
| --- | --- | --- |
| 内容与范围 | 原文、故事或可审阅剧本，已确认目标 | [输入与剧本](references/sourceAndScript.md) |
| 世界与资产 | World/Look、角色、服装、场景与道具版本和参考用途 | [资产制作](references/assets.md)、[电影创作](../cinema/SKILL.md) |
| 镜头规划 | ShotSpec、职责、起止状态、摄影/表演及预期衔接 | [摄影与剪辑](../cinema/references/shotLanguage.md) |
| 关键帧与视频 | 关键帧候选、人工采用的 Hero Frame、视频 Take 与实际反馈 | [画布执行](references/canvasExecution.md)、[状态与交付](references/stateAndDelivery.md) |
| 模型专用编译 | 对应模型支持的格式、时长、参考与降级 | [Seedance 模型规则](references/seedanceDirector.md)（仅实际选用时） |

按镜头保存规格和关键帧候选，采用 Hero Frame 后生成视频 Take。模型支持多镜片段且用户采用该方案时才合并执行，仍保留各镜版本和起止状态。连线传递素材，不代表审批或自动调度。

账号工作区的电影制作通过 `productionSpec` 读写世界、影调、资产与镜头，并先 `compile`，再带 `shotId` 和 `productionFingerprint` 调用图片或视频生成。提供 `requestKeyframeApproval` 时，在聊天中展示并确认主关键帧，可合并多个镜头一次采用，返回 `approved: true` 后继续已授权的视频生成；已采用且有效的帧不重复确认，不要求用户到「镜头制作」再点一次。资产批准、定妆选择、Take、规格变更、剪辑、配音和成片验收使用 requestProductionDecision，在聊天中预览、填写观察并保存。Take 仍须完整播放并记录实际结束状态。工具缺失时在聊天说明缺项，不强制跳转面板。Agent 不代填人工验收。文本与普通画布节点仅可作为辅助记录，不能替代领域审批。未提供规格工具时明确说明执行能力缺失。音乐分析、歌词对齐、Music Timeline 未接通时说明缺项，不能以通用音频节点冒充完整 Music Film。

## 按问题读取方法

- 创意、人物目标、因果与续作：[故事开发](references/methods/storyDevelopment.md)。
- 小说视听化、场景、心理与对白：[剧本改编](references/methods/screenAdaptation.md)。
- 外观、空间和道具结构：[视觉设计](references/methods/visualDesign.md)。
- 色彩关系与光线来源：[色彩与光线](references/methods/colorAndLight.md)。

方法中的示例与风格候选不是本项目事实。Seedance 专用提示词格式阶段不叠加第二套模板；其他模型继续基于电影规格和真实能力执行。不要机械增加运镜、浅景深、光晕或“cinematic/8K”等词替代具体摄影判断。 用户要求手机自拍、生活记录或 UGC 真人质感时，按需读取[真实感方法](../continuity/references/realism.md)中的手机成像规则；先明确参考用途、持机与动作因果，再选择少量有触发条件的成像瑕疵，不默认添加噪点、磨皮或跳切。

## 情境人像

仅在当前任务需要角色定稿后的情境人像、宣传照或摄影样片时使用，也可用于真人 MV、生活类短片中已选定的相应镜头；不把它设为所有真人项目的默认风格或必做阶段。角色主参考继续按[资产制作](references/assets.md)保持完整展示与中性透视，情境样片单独记录用途，不覆盖身份主参考。

1. **沿用身份与任务范围**：绑定已采用的角色参考，保留脸型、五官比例、年龄、体型及当前服装状态。缺少定稿时先按现有资产流程处理；已有适用照片可直接作为依据，不为补流程重做。只提升原照片摄影效果时，保留原事件、表情、动作与场景关系，只调整用户允许的部分。
2. **选一个具体瞬间**：从剧本、音乐影像方向或已确认主题中选出本图要表现的事件，写清触发、人物注意对象与主要身体反应，等待和倾听也可以成立。独立宣传照可提出情境方案，不能反写成剧情事实；不为“鲜活”强塞笑容、奔跑、风吹或新道具。
3. **让摄影看见反应**：按本图重点选择距离、机位、焦点及必要前景，说明要看清脸、手还是人与环境的关系。裁切、遮挡和近距离广角只在服务画面且身份仍可辨时使用，不固定特写比例，不把透视变形写回角色身形；动作与身体接触沿用[表演指导](../cinema/references/performanceDirection.md)。
4. **按现场决定光色**：沿用项目媒介、肤色、时段与光源，按[色彩与光线](references/methods/colorAndLight.md)组织观看重点。项目 Look 为夜调或暗调时，日景与白昼室内按当时段的实际光源重建光色，只继承材质与肤色规则，不套夜档的低照度与低饱和基底。光学效果可不加；需要时写明来源、作用区域及可读性边界，不机械叠加眩光、色散、旋焦或失焦。皮肤保留年龄、纹理与符合状态的反光，不统一磨皮、哑光或提亮；不预设人物地域、高饱和、阳光或唯美方向。
5. **守住适用范围内的一致性**：同一角色保持身份，连续剧情或同一套摄影方案内保持所选造型；唱跳 MV 已定的多造型方案允许随段落和剪点改变妆发服饰，不要求全片同装。风格参考只提供指定摄影关系，身份参考继续锁定角色；同一连续场景的光向、道具与动作状态交给[连续性守则](../continuity/SKILL.md)承接。

结论合入现有镜头或图片方案：采用哪个角色版本、哪个瞬间、怎样观看、光色依据和本次允许变化。视频仍先形成镜头规格，再按所选模型规则编译；不另建一套提示词格式，也不替代 MV 的音乐结构与卡点计划。

查看实际图片时对照主参考检查身份、服装状态、手与物的接触、目光对象以及必要信息是否被效果遮住。样片只能验证可见的静态结果；动作时序、跨镜接点与音乐同步须看实际视频，不能凭单张图宣布通过。

## 真人质感与镜头接点

真人项目先审看母图的皮肤、发际线、衣物材质和接触关系，不把磨皮母图交给视频后再靠颗粒或锐化补救。身份不变量与自然表演变化分开：用现有 `performance.timing`、`gesture`、`eyeline` 和 `action` 表达触发、反应、行动、余波，不机械套固定秒数或同时堆叠强表情。光源继承场景位置，不随人物情绪自动换灯、柔焦或加辉光。

精致人像的局部肤面修饰不等于磨平身份纹理；按[妆造方法](references/methods/characterStyling.md#精致写真人像皮肤妆发与搭配)检查高光过渡、纹理尺度、妆发与搭配，不统一增加毛孔、油光、皱纹或粗粝颗粒。用户已选的纪实、粗粝或其他画风仍优先。

角色板按当前景别提取必要参考。绑定 `crop` 使用 `{ x, y, width, height, unit }`：`normalized` 为原图像素坐标归一化的 0–1 区域，`pixels` 为原图整数像素；不支持视频分段裁切。核对编译结果的实际媒体，原生首尾帧与普通多参图片区分说明。

每个接点先写清切镜目的，再选择动作、视线、反应或声音衔接。沿用现有时间线的入出点、独立音轨与淡化控制；不要默认从每段第零秒用到结束，也不要给全部接缝加溶解。对白保留完整发音，环境声可跨镜延续，混合音轨不能冒充已分离的干净对白。生成素材时长与最终使用区间分别记录，模型时长约束以真实能力为准。

验收同时播放上一镜出点前与下一镜入点后的画面和声音，检查动作相位、持物、人物反应及光向。片尾抽帧只辅助发现问题，不替代播放。前镜换采用版本后，复核依赖其状态的后镜，不自动重跑或删除旧候选。

需要连续动作接切时，调用 productionSpec(continuationFrame,{shotId,takeId,seconds?}) 从明确接续的前镜真实视频提取交接帧，时间取实际剪辑出点附近，不能使用超出剪入区间的未来动作。返回的 path 可读图，也可作为换机位编辑输入；关键帧仍需真实检查，后镜仍须生成动态视频。默认时间只是建议，先核对动作相位和实际剪点。前镜素材、规格或接戏关系改变后旧帧失效。每镜 inspectQuality 会给出 freezeSegments 和 blackSegments，只作实际查看的定位线索；冻结信号不能自动当作有意静止，未报冻结也不能证明人物在表演。对白继续检查完整发声窗口与嘴部可见性，ASR 文本和静音检测不能代替逐字口型与听审。

## 确认、生成与恢复

剧情、广告和MV的动作与长时间连续性统一执行[动作、节奏与连续镜头](../cinema/references/movementDirection.md)。先用productionSpec(planGeneration)只读检查整批模型、模式、精度和单段时长，再集中确认具体方案；已确定内容直接复用。动作保持项不锁死参考姿态；单段一镜到底与多段剪接分开规划，超过单段能力不得冒充原生长镜头。用户要求不扣费时只规划和compile。

生成范围沿用明确授权。先完成可审阅的规格、参考和实际参数；需要采用或新增付费范围时给出具体影响，不重复确认已经授权的相同动作。人物声音、对白与音乐采用实际能力支持的方案，不猜原生音频、口型或对齐能力。

图片/视频生成返回任务 ID 或 generating 只表示开始。通过真实任务或节点状态查询结果，保留 Prompt、参数、参考与旧输出。账号模式下关闭页面只结束观察，节点重新打开后恢复查询；明确停止才取消 Job。服务重启且无上游任务句柄时状态待核查，不自动重发，避免重复付费。没有返回费用时标为未知。

依赖前镜的后续生成，要等采用前镜并核对交界状态。独立资产或镜头按已经授权的批次执行。未经真实媒体读取与检查，文件路径、播放器或静帧不能证明看过全片、听过音轨。区分人工验收、规则检查和视觉检查，也区分已生成、已采用与已组装成片。

## 资产先行与成片闭环

完整影片的默认顺序是：确认故事与视觉方向 → 生成并采用本次需要的角色、场景、关键道具基础资产 → 基于真实资产制作分镜/关键帧 → 视频片段 → 剪辑合成 → 画布成片与下载。资产文字清单或空节点不等于资产已生成。已有适用资产直接复用；只缺部分时补缺项。可提前做文字镜头草案，但在所需资产未就绪时不开始正式分镜图或视频生成。用户明确只要分镜方案或独立片段时遵守该范围。

用户要求完整影片/MV，已授权制作范围就包含对已采用片段的本地拼接、混音和导出；素材与剪辑顺序、入出点齐备后主动执行，无需再等一句“帮我合并”。仍缺采用决定或素材时准确显示缺项，不擅自采用失败候选、不新增付费调用。按剪辑顺序使用真实片段，不能按文件名排序代替镜头顺序。

自动合成只产出粗剪（options.draft:true），不能当作定稿或验收通过。完整制作先 readEdit 获取轨道、片段和 version，按主视频轨时间顺序逐个 previewCut{sequenceId,leftId,rightId,expectedVersion} 查看接点前后声画。需要改善的连续硬切先 suggestCuts 获取候选，结合完整对白、关键动作、视线与已定时长选择，再用 editTimeline 的 set_cut 保存入出点；候选分数不代表语义匹配，不自动采用第一名。声音突变时按实际内容用 soundBridge{sequenceId,leftId,rightId,expectedVersion,mode,duration}，mode 可为 jCut、lCut、crossfade、none，先核对素材头尾余量。修改后使用新版本重新预览受影响接点，已有合理硬切保留，不统一添加淡入淡出。不为接缝擅自重生成素材，也不把预览文件存在当作已看听。用户只要粗剪时先交付粗剪；准备交付、接缝已处理并实际看听后，显式 render 导出定稿（draft:false 或省略 draft），再进行最终检测与验收。

导出成功后把真实文件挂到当前任务绑定画布的独立视频节点：草稿命名“粗剪 · 作品名”，定稿命名“成片 · 作品名”，展示完整播放与下载入口；核对文件与节点持久化后才登记已合成。FFmpeg 自动挂载成功则复用回执中的节点，不重复添加；挂载失败时仅重试挂载，不重新渲染。导出不等于人工验收通过，不伪造看听记录。

涉及武打、搏击、追逐、动作电影时，在镜头规格阶段读取 [动作编排](../cinema/references/actionChoreography.md)，将动作因果、空间、接触与连续状态应用到实际 action、blocking、camera 和剪点。模型专用格式仍服从已选模型规则。
